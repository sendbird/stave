## 1. 앱 설치

```bash
brew install gh
gh auth login
gh api -H 'Accept: application/vnd.github.v3.raw+json' repos/sendbird/stave/contents/scripts/install-latest-release.sh | bash
```

설치 스크립트는 최신 릴리스의 `Stave-macOS.zip`을 받아 `~/Applications`(또는 `/Applications`)에 설치하고 앱을 엽니다.
SSO나 권한 범위 오류가 나면 `gh auth refresh -h github.com -s repo,read:org`를 실행한 뒤 다시 설치합니다.
자세한 설치 안내: https://github.com/sendbird/stave/blob/main/docs/install-guide.md

새 버전이 나오면 상단 바에 **앱 업데이트**가 보이고, **설치 후 다시 시작**으로 바로 바꿉니다.

## 2. AI CLI 설치와 로그인

Stave는 내 컴퓨터에 설치된 CLI를 내 로그인으로 실행합니다. 하나 이상 설치하고 로그인하세요.

| 프로바이더   | 로그인 명령           | 참고                                             |
| ------------ | --------------------- | ------------------------------------------------ |
| Claude Code  | `claude auth login`   | 설치: `npm install -g @anthropic-ai/claude-code` |
| Codex        | `codex login`         | 설치: `npm install -g @openai/codex`             |
| Cursor Agent | `agent login`         | 설치하고 로그인하면 설정에 탭이 나타납니다       |
| Kiro CLI     | `kiro-cli login`      | 설치하고 로그인하면 설정에 탭이 나타납니다       |
| OpenCode     | `opencode auth login` | 설치하면 설정에 탭이 나타납니다                  |

Claude와 Codex는 **설정 > 계정**에서 계정을 더 추가하거나 API 게이트웨이를 연결할 수 있습니다.

## 3. 앱에서 첫 설정

1. 첫 화면에서 **저장소 열기**를 누르고 로컬 git 저장소 폴더를 고릅니다.
2. 쓸 수 있는 프로바이더가 아직 없으면 첫 화면에 **시작하기**와 **계정 열기**가 보입니다. **설정 > 계정 > 시작하기**의 단계(프로바이더 CLI 설치, 로그인, 계정 추가, 게이트웨이 연결, 모델 고르기)를 따라갑니다. 계정 추가와 게이트웨이 연결은 선택입니다.
3. **설정 > 일반 > 언어**에서 한국어를 고를 수 있습니다.
4. **설정 > 프로바이더**에서 권한 프리셋을 확인합니다. [권한과 안전](#safety)을 먼저 읽으세요.

macOS가 데스크톱·문서·다운로드 폴더 접근을 물으면 한 번 허용합니다.

## 네 가지 기본 단위

| 단위         | 무엇인가                             | 알아 둘 점                                                                                                                  |
| ------------ | ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| 저장소       | 사이드바에 등록한 로컬 git 폴더      | 설정에서는 **프로젝트** 페이지가 저장소 설정을 다룹니다                                                                     |
| 워크스페이스 | 브랜치 하나에 묶인 전용 git worktree | 저장소마다 저장소 루트인 **기본** 워크스페이스가 하나 있고, 나머지는 `<저장소>/.stave/workspaces/` 아래에 만들어집니다 |
| 작업         | 워크스페이스 안의 대화 하나          | 탭을 닫아도 보관되지 않습니다. 보관은 탭 메뉴의 **보관**입니다. 작업 중간에 프로바이더를 바꿀 수 있습니다                 |
| 턴           | 요청 하나에 대한 응답 한 번          | 도구 실행, 승인 요청, 질문이 턴 안에서 일어납니다. 턴이 도는 동안 보낸 메시지는 대기열에 쌓입니다                         |

사이드바에서 기본 워크스페이스 이름과 브랜치는 `기본 · main`처럼 한 줄로 표시됩니다. 긴 브랜치는 말줄임 처리하고 브랜치가 없으면 점도 숨깁니다.

## 워크스페이스를 나누는 이유

기본 워크스페이스에서 바로 일해도 됩니다.
하지만 일마다 워크스페이스를 만들면 브랜치와 파일이 분리되어, 여러 AI 작업을 동시에 돌려도 서로의 변경을 덮어쓰지 않습니다.
일이 끝나 PR이 머지되면 워크스페이스를 보관하고, 필요하면 브랜치도 함께 지웁니다.

## 1. 워크스페이스 만들기

사이드바의 저장소 행에 마우스를 올리면 **새 워크스페이스**, **워크스페이스 킥오프**(반짝이 아이콘), **저장소 설정** 버튼이 보입니다.
**새 워크스페이스** 대화상자에서 **워크스페이스 브랜치 이름**과 선택 항목인 **워크스페이스 레이블**을 적고, 만드는 방법을 고릅니다.
화면 보기: [새 워크스페이스](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/new-workspace.png)

| 만드는 방법                    | 하는 일                                                                         |
| ------------------------------ | ------------------------------------------------------------------------------- |
| 브랜치에서 만들기(기본)        | 기준 브랜치를 검색해 고르고, 거기서 worktree를 만듭니다                         |
| 깨끗한 워크스페이스 만들기     | 새 브랜치로 격리된 worktree를 새로 만듭니다                                     |
| 기존 worktree 연결             | 다른 위치의 worktree를 `.stave/workspaces/`에 심볼릭 링크로 연결하고 브랜치를 유지합니다 |

**생성 후 명령**(예: `bun install`)을 넣으면 만들자마자 실행합니다.

### 킥오프로 시작하기

Jira 이슈, PR, 보고서처럼 이미 있는 자료에서 시작하려면 **워크스페이스 킥오프**를 씁니다.
링크나 설명을 붙여 넣고 **원본 맥락 확인**을 누르면 Stave가 자료를 읽어 브랜치, 레이블, 정보 패널 링크, 첫 작업의 모델과 요청을 제안합니다. 모두 고친 뒤 만들 수 있습니다.
**AI 건너뛰기**는 AI 없이 링크와 텍스트만 읽어 제안합니다.
**담당자**에서 **나** 또는 저장된 에이전트를, **위치**에서 새 워크스페이스 또는 **현재 워크스페이스**를 고릅니다. **즉시 시작**을 끄면 첫 요청을 보내지 않고 컴포저에 남겨 둡니다.
화면 보기: [워크스페이스 킥오프](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/kickoff.png)

## 2. 작업 열고 요청 보내기

1. Cmd/Ctrl+N을 누르거나 빈 워크스페이스의 **새 작업**을 누릅니다.
2. 컴포저 아래쪽 모델 버튼(**모델 선택**, Alt+P)에서 프로바이더, 모델, 추론 강도를 고릅니다. **Stave Auto**를 고르면 요청의 난이도에 맞춰 Stave가 모델을 고릅니다.
3. 할 일과 완료 조건을 함께 적습니다. 예: "로그인 후 원래 페이지로 돌아가게 고치고, 리다이렉트 테스트를 추가해 통과시켜 주세요."
4. **보내기**를 누릅니다.

화면 보기: [모델 선택](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/model-picker.png)

컴포저에서 쓰는 기호는 네 가지입니다.

| 기호 | 하는 일                                  |
| ---- | ---------------------------------------- |
| `/`  | 명령(예: `/aside` 곁질문)                |
| `$`  | 스킬을 골라 이번 메시지에 붙입니다       |
| `!`  | 저장한 매크로를 실행합니다               |
| `@`  | 작업, 정보 패널 항목, 파일을 참조합니다  |

## 3. 턴이 도는 동안

```sequence "턴 하나에서 일어나는 일"
participant U 나 | 컴포저
participant S Stave | 데스크톱 앱
participant P 프로바이더 | Claude Code · Codex 등
U -> S: 요청 보내기 | 지침과 맥락을 붙여 전달
S -> P: 턴 시작
P => S: 생각 · 도구 실행 · 응답
P -> S: 승인 요청 | 권한이 필요한 도구
S -> U: 승인 행 표시
U --> S: 한 번 허용 · 항상 허용 · 거부
S --> P: 결정 전달
P => S: 이어서 실행
P --> S: 턴 끝
S --> U: 응답 · 변경 파일 · 요약
@caption 턴 흐름을 단순화한 그림입니다. 승인 단계는 권한 프리셋에 따라 나타나지 않을 수 있습니다.
```

**읽기와 입력**: 언어를 지정하지 않은 코드 블록에는 구문 색을 입히지 않습니다. 입력창은 대화의 글자 크기 설정과 작업 패널의 크기 제한을 따릅니다. 최소형 입력창의 고정폭 글자와 캐럿도 함께 커집니다.

**승인**: AI가 권한이 필요한 도구를 쓰려 하면 컴포저 위에 **한 번 허용**, **항상 허용**, **거부** 버튼이 있는 행이 뜹니다. **항상 허용**은 허용을 계속 유지할 수 있으면 모든 승인 화면에 똑같이 나옵니다. 프로바이더가 직접 유지하거나, 신뢰된 승인 목록에 항목으로 남깁니다. 행에는 요청이 알려 준 위험(예: **네트워크 접근**)도 나옵니다. 펼침 메뉴는 요청한 하위 에이전트를 알려 주고, **안내로 대체**와 **거부 후 안내**를 담고 있습니다. 승인을 기다리는 동안 입력하면 보내기 버튼이 **거절하고 방향 조정**으로 바뀝니다. 승인 카드 안에서는 Cmd/Ctrl+Enter로 한 번 허용하고, Esc로는 거부하지 않습니다. 아무도 답하지 않은 요청은 제한 시간이 지나면 자동으로 거부되며, 카드와 행의 펼침 메뉴에 그 시각이 나옵니다(**응답이 없으면 오후 4:24에 자동으로 거부합니다**). **항상 허용**으로 답한 카드에는 **신뢰됨: <항목> · 제거**가 붙고, **제거**를 누르면 그 항목을 다시 뺍니다.
화면 보기: [승인 요청](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/approval.png)

**진행 줄**: 턴이 도는 동안 단계 목록 위 줄에 장난스러운 상태 문구, 지금 진행 중인 단계(예: **search.ts 읽는 중**), 경과 시간이 함께 나옵니다. 턴이 끝나면 그 턴의 제목으로 바뀝니다. 웹을 검색하거나 가져온 턴은 답변 아래에 **출처**와 개수가 붙고, 펼치면 페이지마다 한 번씩 보여 줍니다.

도구 결과, 생각 과정, 접힌 도구 그룹의 본문은 처음 펼칠 때 불러오며 다시 접어도 유지됩니다. 브라우저에서 본문을 검색하거나 인쇄하려면 먼저 펼쳐 주세요.

**질문**: AI가 선택지가 있는 질문을 하면 숫자 키로 고를 수 있습니다. Claude의 선택지에는 코드 조각 같은 미리보기가 붙을 수 있고, 그 선택지에 포커스나 포인터가 있는 동안 선택지 아래에 보입니다.

**대기열**: 턴이 도는 동안 보낸 메시지는 컴포저 위 선반에 쌓입니다. 항목마다 **방향 조정**(지금 턴에 끼워 넣기), **보내기**, **편집**, **삭제**가 있고, **모두 지우기**로 비웁니다. 앱을 다시 시작해 복원된 대기열은 **재개**를 누를 때까지 기다립니다. 턴을 멈추려면 **중지**를 누릅니다.

**대화 기록**: 연달아 보낸 메시지(방향 조정 등)는 한 묶음으로 붙고, 마지막 메시지 아래에 안내가 한 번만 표시됩니다(**활성 턴에 방향 조정 전달됨 · 3**). 각 메시지에 마우스를 올리면 그 메시지의 복사와 시간 동작이 나타납니다. 응답의 프로바이더, 모델 또는 추론 강도가 바로 앞 응답과 다르면 그 응답 위에 바뀐 내용을 알리는 줄이 표시됩니다(**Claude Sonnet 4.6 · 보통 → Claude Opus 4.8 · 높음**).

**사용 한도**: 프로바이더 사용 한도에 걸리면 선반에 사용 한도 행이 뜹니다. **초기화 시 재개**를 누르면 한도가 풀리는 시각에 자동으로 이어 가고, **지금 재개**는 바로 다시 시도합니다.
화면 보기: [대기열과 사용 한도](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/queue-usage-limit.png)

**활동 탭**: 작업 패널의 **활동** 탭은 턴의 단계를 목록으로 보여 줍니다. **목록 | 타임라인** 전환을 쓰면 같은 턴을 0초, 30초, 1분처럼 눈금이 붙은 시간축에 그립니다. 턴 행에 토큰과 비용이 붙고, 도구 호출과 하위 에이전트가 막대로 놓이며, 턴이 도는 동안 **현재** 선이 보이고, 가장 오래 걸린 단계에 **가장 느림** 표시가 붙습니다. 시간이 기록되지 않은 단계는 축에 놓지 않고 아래에 나열합니다. **에이전트 트리**는 가지마다 접을 수 있고 방향키로 이동합니다. 대화에서는 도구 호출의 인수와 출력에 각각 **복사**가 있고, 긴 출력은 정해진 높이 안에서 스크롤되며 아래에 줄 수가 표시됩니다.

## 4. 변경 확인과 PR

1. 오른쪽 패널의 **소스 제어**에서 바뀐 파일과 기록을 봅니다.
2. 작업 탭 위의 **대화 / 검토** 전환(Cmd/Ctrl+Alt+R)으로 검토 모드를 엽니다. diff에 줄 코멘트를 남기고 **에이전트에 리뷰 보내기**로 고칠 점을 전달합니다. 자세한 내용은 [검토와 위임](#review)을 보세요.
3. 상단 바의 **PR 생성**을 누르면 PR 대화상자가 열립니다. 병합 방식과 자동 병합을 고를 수 있습니다. GitHub CLI(`gh`) 로그인이 필요합니다.
4. PR이 생기면 상단 바에 상태 칩이 보이고, 준비 완료 표시, 브랜치 업데이트, 병합, GitHub에서 열기를 바로 할 수 있습니다.
5. 일이 끝나면 워크스페이스 행의 ⋮ 메뉴에서 **워크스페이스 보관**을 고릅니다. **git 브랜치도 삭제**를 켜면 브랜치도 지웁니다.

## 맥락을 주는 방법

| 방법          | 어떻게                                                    | 알아 둘 점                                                                  |
| ------------- | --------------------------------------------------------- | --------------------------------------------------------------------------- |
| 파일·이미지   | 컴포저의 클립 버튼(**파일 첨부**). 붙여 넣거나 컴포저에 끌어다 놓기 | 끌어다 놓으면 **놓아서 첨부**가 보이고 붙여 넣기와 같은 방식으로 첨부됩니다 |
| 다른 작업     | `@`와 작업 제목 일부, 또는 사이드바에서 작업을 끌어 놓기  | **최신 응답** 또는 **최근 대화**를 고릅니다. 메시지당 최대 5개              |
| 스킬          | `$`를 입력하고 고르기                                     | 고른 스킬의 SKILL.md 전체가 함께 전달됩니다                                 |
| `@web`        | 메시지에 `@web`                                           | 프로바이더의 Chrome 연동을 씁니다. 범위는 설정 > 브라우저 > 멘션            |
| 정보 패널     | 메모, 할 일, 링크를 적어 둠                               | 프롬프트에 붙인 Jira·PR 링크는 자동으로 패널에 추가됩니다                   |
| 저장소 지침   | 설정 > 프로젝트 > 저장소 > **저장소 지침**                | 이 저장소의 모든 Claude·Codex 턴에 들어갑니다                              |
| 저장소 메모리 | 정보 > **메모리**                                         | 수집은 기본 꺼짐. 항목당 280자, 한 턴에 최대 6개. 삭제는 확인 없이 바로 되고, 뒤이어 뜨는 알림의 **실행 취소**로 되살림. 항목이 8개 이상이면 검색과 종류 칩이 나타남 |

```callout note "정보 패널이 전달되려면"
정보 패널, 작업 맥락, 최근 턴 요약은 **설정 > MCP > 로컬 MCP 서버**가 켜져 있을 때만 턴에 붙습니다. AI가 메모나 링크를 모르는 것 같으면 먼저 이 설정을 확인하세요.
```

## 흐름을 끊지 않는 기능

- **곁질문**: 컴포저 도구 막대의 **곁질문**, `/aside`, 또는 Cmd/Ctrl+K 다음 Q. 답은 읽기 전용이고 작업 대화에 추가되지 않습니다. Claude와 Codex에서만 됩니다.
- **다시 오셨네요**: 15분 넘게 자리를 비웠다 돌아오면 그동안 일어난 일과 마지막 결정을 요약한 카드가 뜹니다.
- **인계**: 작업 패널 > **인계**에서 **이 작업에서 채우기**나 **에이전트에게 업데이트 요청**으로 인계 기록을 채웁니다. 프로바이더가 작업을 시작하거나 돌아올 때 이 기록을 먼저 받습니다. 섹션의 2,000자에 들어가지 못한 줄은 그 섹션 아래에 **다시 넣기**와 함께 남습니다.
- **프롬프트 개선**: 컴포저의 지팡이 아이콘이 요청 문장을 다듬습니다. **프롬프트 개선됨** 알림에서 **실행 취소**와 **변경 보기**를 고를 수 있고, **변경 보기**는 지운 단어를 취소선으로, 추가한 단어를 밑줄로 보여 주며 **유지**와 **원래대로 되돌리기**를 둡니다.
- **컨텍스트 표시**: 컴포저에서 대화가 얼마나 찼는지와 남은 토큰을 보여 줍니다. Claude는 **구성**에 무엇이 채우는지(시스템 프롬프트, 도구, MCP 도구, 메모리 파일, 스킬, 추정한 대화)를 나열하고, 다른 프로바이더는 합계만 알려 줍니다. **컨텍스트 압축**은 대화가 길어졌을 때 줄입니다.
- **매크로**: 컴포저 도구 막대에서 저장한 매크로 목록을 열고 이름, `!slug`, 설명으로 검색합니다.

@page safety | 일하기 | 권한과 안전 | guide
@lead 프로바이더마다 AI가 묻지 않고 할 수 있는 범위를 모드 프리셋으로 정합니다. 새로 설치하면 모든 프로바이더가 가장 넓은 **자동** 프리셋으로 시작하니, 처음에 한 번 확인하세요.

```callout warning "기본값은 자동입니다"
새 설치에서는 Claude, Codex, Cursor, Kiro, OpenCode가 모두 **자동** 프리셋입니다. Codex는 전체 디스크 접근, 승인 없음, 네트워크 켜짐으로 시작합니다. 확인이 필요한 저장소라면 **설정 > 프로바이더 > 모드 프리셋**에서 **안내형**이나 **수동**으로 바꾸세요.
```

| Cursor     | 도구 호출마다 묻기                           | Cursor 자체 자동 검토                      | 모든 도구 호출 실행, MCP 서버 신뢰                        |
| Kiro       | 도구 호출마다 묻기                           | 없음                                       | 모두 자동 승인                                           |
| OpenCode   | 읽기까지 포함해 매번 묻기, 하위 에이전트 없음 | 없음                                       | 모든 요청 승인. OpenCode의 `deny` 규칙은 그대로 적용     |

컴포저의 프리셋 메뉴와 **설정 > 프로바이더**는 선택한 프리셋 아래에 그 프리셋에서 바로 실행하는 일과 먼저 물어보는 일을 행동별로 보여 줍니다(파일 읽기, 파일 편집, 명령 실행, 웹 도구, MCP 도구 등). Claude는 켜 둔 가드레일(G1–G3)도 함께 보여 주며, 이 항목은 에이전트 모드에서 프리셋과 상관없이 항상 먼저 물어봅니다. 다른 프로바이더에는 이런 고정 항목이 없습니다.

세부 항목을 바꾸면 프리셋 표시가 **사용자 지정**으로 바뀝니다. 컴포저의 런타임 칩은 현재 상태를 **안전**, **사용자 지정**, **확장됨**으로 보여 줍니다.

## 저장소마다 다르게 쓰기

설정 맨 위의 적용 대상 선택기(처음에는 **모든 프로젝트**)에서 저장소를 고르면 모델, 추론 강도, 권한을 그 저장소에만 따로 정할 수 있습니다. 원래 값으로 돌리려면 항목의 전역 값 사용을 누릅니다.

## 에이전트 실행의 안전장치

작업이 에이전트로 실행될 때는 저장소 밖에 쓰기, 자격 증명 경로 접근, 되돌릴 수 없는 원격 작업을 막는 안전장치(G1~G3)가 기본으로 켜집니다. Claude는 훅으로 셋 모두를 막고, Codex는 샌드박스로 저장소 밖 쓰기(G1)만 막습니다.

## 시크릿

API 키 같은 값은 채팅에 붙여 넣지 마세요. 에이전트가 값을 요청하면 컴포저 위에 가려진 입력 카드가 뜹니다. **저장 및 연결**로 저장하거나 **저장된 시크릿 사용**으로 고릅니다. 값은 운영체제의 자격 증명 저장소에 저장되고, AI에게는 변수 이름만 전달됩니다. 직접 관리하려면 **설정 > 시크릿 > 시크릿 추가**를 씁니다.

## 실행의 단계

```pipeline "완료 전 리뷰가 켜진 실행"
작업 | 지시와 완료 조건대로 일합니다.
리뷰 | 다른 에이전트가 읽기 전용으로 변경을 검토합니다.
수정 | 리뷰에서 나온 문제를 고칩니다.
! 완료 확인 | Stave가 워크스페이스 검사 명령을 직접 실행해 통과를 확인합니다.
@caption 파일을 바꾸지 않은 작업은 리뷰 단계 없이 끝납니다.
```

워크플로가 없는 에이전트는 작업 단계 하나로 실행됩니다.
단계는 AI 단계(지시와 완료 조건)이거나 Stave 동작입니다. Stave 동작은 초안 PR 열기(Open draft PR), 검사 감시(Watch checks), 리뷰 준비 전환(Ready for review), 스크립트 실행(Run script)입니다.

## 실행 상태

```diagram architecture "실행 배지 사이의 이동"
box running 1,2 primary | 실행 중 | 일하거나 기다리는 중 | 기다리는 동안 턴을 쓰지 않음
box answer 2,1 | 답변 필요 | 질문 · 승인 · 단계 시작 확인 | 답하면 다시 실행 중
box paused 2,2 | 일시정지 | 내가 멈춤 · 직접 조작 | 재개하면 다시 실행 중
box halted 2,3 | 멈춤 | 막힘 · 한도 · 대기 만료 | 실행 줄 버튼으로 이어 감
box done 3,1 | 완료 | 완료 조건 충족 | 산출물에 보고서
box stopped 3,3 | 중지됨 | 취소 · 이유 카드 | 다시 시도 · 직접 제어
edge running -> answer : 사람이 필요함
edge running -> paused dashed : 일시 중지
edge running -> halted : 진행할 수 없음
edge running -> done main : 완료 확인 통과
edge halted -> stopped dashed : 중지
@caption 앱 코드의 실행 상태와 배지를 단순화한 그림입니다. 답변 필요, 일시정지, 멈춤에서는 답하거나 재개하면 실행 중으로 돌아갑니다.
```

| 배지      | 뜻                                                                                 | 할 일                                     |
| --------- | ---------------------------------------------------------------------------------- | ----------------------------------------- |
| 실행 중   | 일하는 중. PR 검사, 사용량 한도처럼 기다리는 이유가 붙기도 합니다. 기다리는 동안 턴을 쓰지 않습니다 | 기다립니다                                |
| 답변 필요 | 질문이나 승인 카드가 열렸거나, 다음 단계 시작 확인을 기다립니다                    | 카드에 답합니다                           |
| 일시정지  | 내가 멈췄거나 직접 조작 중입니다                                                   | 작업 패널 > 진행의 **재개**               |
| 멈춤      | 막힘, 복구 필요, 대기 만료, 사용량 한도, 한도 도달                                 | 아래 실행 줄 버튼으로 이어 갑니다         |
| 완료      | 완료 조건을 채웠습니다                                                             | 산출물에서 실행 보고서를 봅니다           |
| 중지됨    | 취소되었거나 이유 카드와 함께 끝났습니다                                           | **다시 시도** 또는 **직접 제어**          |

실행 시간은 **활성 시간**입니다. 일시 중지, 답변이나 단계 시작 확인을 기다린 시간, Stave가 꺼져 있던 시간은 세지 않습니다. 작업 패널 > **진행**의 각 단계에는 그 단계의 턴이 쓴 사용량이 나옵니다. Claude는 비용, Codex는 토큰입니다.

컴포저 위 실행 줄에는 상황에 맞는 버튼이 뜹니다: **다시 시도**, **연장 (+10턴)**, **지금 재개**, **이어서 진행**, **중지**, **직접 제어**(실행을 끝내고 같은 모델의 일반 대화로 이어 감).
작업 패널 > **진행**에는 **이 실행이 하는 일**, **완료 조건**, **팀 한도**, 단계 카드(**단계 다시 시도**, **단계 건너뛰기**)가 있습니다.
완료 조건은 **충족됨 · Stave 확인**, **충족됨 · 에이전트 보고**, **미충족**, **검증 안 됨** 중 하나로 표시됩니다.
화면 보기: [진행 탭](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/agent-run-panel.png) · [단계 시작 확인 카드](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/run-sign-off.png)

## 목표를 맡기고 자리 비우기

1. 에이전트의 **실행 방식**에서 권한을 **자동**으로 둡니다.
2. **설정 > 프로젝트 > 워크스페이스 도구**에 검사 명령(예: `bun run typecheck && bun test`)을 추가합니다. 파일을 바꾼 실행은 Stave가 이 명령을 직접 돌려 통과해야 끝납니다.
3. 필요하면 **완료 전 리뷰**를 켜거나, 작업 · 리뷰 · 수정 단계를 직접 만듭니다.
4. **설정 > MCP > 로컬 MCP 서버**를 켜고, PR 단계를 쓰려면 `gh auth login`을 해 둡니다.
5. 에이전트 상세에서 **지정…**을 누르고, 원하는 결과와 그것을 증명할 방법을 적고, **위치**를 고른 뒤 지정합니다. 컴포저에서 에이전트를 골라 보내도 됩니다.
6. 자리를 비웁니다. 실행은 안전한 승인, PR 검사와 리뷰 대기, 사용량 초기화 대기를 스스로 처리합니다.
7. Fleet 보기의 **조치 필요**나 알림이 실행을 가리키면 돌아와 카드에 답하거나 실행 줄 버튼으로 이어 갑니다.
8. 끝나면 산출물의 실행 보고서에서 PR 설명에 추가하거나 Slack에 공유합니다.

@page review | 맡기기 | 검토와 위임 | guide
@lead 변경은 내가 직접 보는 검토 모드, 다른 모델에게 맡기는 AI 리뷰, 에이전트가 만드는 위임 작업으로 확인합니다. 결과는 작업 패널의 산출물에 모입니다.

## 검토 모드에서 코멘트 보내기

1. 검토 모드에서 diff의 줄에 코멘트를 남깁니다.
2. **에이전트에 리뷰 보내기**(Cmd/Ctrl+Alt+Enter)로 코멘트를 한 번에 보냅니다.
3. 에이전트가 고치면 다시 검토하고, 충분하면 **승인**합니다.

검토 화면의 **diff 코멘트** 목록에서 코멘트를 고르면 그 줄로 이동합니다. 보내기 전 코멘트는 삭제할 수 있고, 보낸 코멘트는 그 뒤 줄이 바뀌었는지 보여 주며 **해결**할 수 있습니다. 보낸 코멘트는 해결할 때까지 다시 시작해도 남습니다.

**검토 완료로 표시**를 누르면 잠시 **실행 취소**가 있는 알림이 뜹니다. 결정을 마치면 주 버튼이 Fleet 보기에서 기다리는 다음 결과나 승인인 **다음 리뷰**로 바뀝니다. 검토 화면에서 J, K로 기다리는 다음·이전 리뷰로 옮겨 갑니다.

## AI 리뷰

AI 리뷰는 같은 워크스페이스에서 읽기 전용 하위 작업으로 한 턴 동안 돌고, 승인 · 수정 후 승인 · 변경 요청 중 하나로 판정합니다.
선반에 리뷰 진행 상황이 보이고, 끝나면 결과를 첨부하거나 보고, 다시 실행하거나, 고친 뒤 **수정 확인**을 누릅니다.

## 위임 작업

에이전트는 다른 에이전트에게 일부를 맡길 수 있습니다. 위임 작업은 부모 작업 아래에 실제 작업으로 생깁니다.
**하위 에이전트** 탭에서 진행, 기다림, 확인 필요, 완료, 실패 상태를 보고, 활동 보기, 기록 열기, 중지를 할 수 있습니다.
**확인 필요**는 질문이나 승인을 요청하고 사람의 답을 기다린다는 뜻이고, **대기 중**은 다음 턴까지 스스로 기다린다는 뜻입니다.
목록 위의 개수는 필터(**전체**, **확인 필요**, **실패**, **실행 중**, **완료**)이고, **실패한 작업 재시도(N)**로 실패한 위임 작업을 한 번의 지침으로 모두 다시 실행할 수 있습니다.
하위 에이전트 둘 이상이 각자 worktree에서 일하면 **함께 바꾼 파일**에 둘 이상이 바꾼 파일과 바꾼 에이전트가 나오고, worktree별 diff를 열 수 있습니다. 파일 단위로만 비교하고 줄은 비교하지 않습니다.
위임된 에이전트가 사람의 답을 기다리면 선반에 알려 주고, 그 작업에서 답하거나 위임 Agent에 답변을 씁니다.

호출한 메시지의 답변 위에도 **하위 작업 결과**가 나옵니다. 행을 선택하면 원문 결과와 실행 내역을 읽을 수 있습니다. **결과 도착**은 하위 작업이 답변을 돌려줬다는 뜻이며, 부모가 검증하거나 반영했다는 뜻은 아닙니다. **작업 열기**로 하위 작업에 이동하고, 답변이나 승인을 기다리고 있으면 버튼이 해당 행동을 안내합니다. 완료된 도구 활동은 **작업 이력**으로 접히며 답변과 도구 횟수를 반복하지 않습니다. 질문은 접힌 이력 밖에 남습니다.

@page automation | 자동화 | 일정, 다시 확인, Fleet | guide
@lead 반복할 일은 일정으로, 나중에 다시 볼 일은 다시 확인으로 맡깁니다. 여러 워크스페이스에서 내 손이 필요한 일은 Fleet 보기에 모입니다.

## Fleet 보기

Fleet 보기는 모든 워크스페이스의 작업을 내가 할 일 순서로 모읍니다. 사이드바의 **작업 대기열** 보기도 같은 순서를 씁니다.

```pipeline "먼저 볼 순서"
! 조치 필요 | 질문, 승인, 실패, 단계 시작 확인처럼 내가 답해야 하는 일
진행 중 | AI가 일하고 있거나 실행이 기다리는 일
리뷰 대기 | 결과가 준비됐거나 PR이 있는 일
유휴 | 지금 할 일이 없는 작업
@caption 흐름이 아니라 우선순위입니다. Fleet 보기와 작업 대기열은 위에서부터 이 순서로 보여 줍니다.
```

| 레인      | 들어오는 일                                                          |
| --------- | -------------------------------------------------------------------- |
| 조치 필요 | 질문, 승인, 실패한 실행, 실행의 단계 시작 확인, 막히거나 정체된 실행 |
| 진행 중   | 턴이 돌거나 실행이 기다리는 중인 작업                                |
| 리뷰 대기 | 결과가 준비됐거나 PR이 있거나 한동안 소식이 없는 작업                |
| 유휴      | 할 일이 없는 작업                                                    |

행에서 바로 **허용**과 **거부**로 승인하고(A, D 키), 짧은 질문은 선택지를 골라 답합니다. **항상 허용**은 행을 펼친 패널에 있습니다. 그 밖에 열기, 읽음 표시, 닫기, PR 열기, 알림 미루기가 있습니다. 이 동작으로 행이 사라지면 포커스가 다음 행으로 옮겨 가고, **조치 필요** 개수는 "2개가 기다리는 중"처럼 문장으로 읽힙니다. J, K는 화살표 키처럼 행 사이를 옮겨 갑니다. 기다린 시간은 1시간이 지나면 경고 색, 하루가 지나면 실패 색으로 바뀝니다.
밴드 아래의 활동 필터와 **트리** / **카드** / **표** 전환은 각각 Tab 한 번으로 들어가 방향키로 바꿉니다. 필터나 검색으로 보드를 좁히면 툴바 아래에 칩이 나타나며, 하나씩 지우거나 **모두 지우기**로 한 번에 지웁니다.

그 아래 보드는 **트리**로 열립니다. 열린 작업마다 에이전트 카드가 상태, 모델, 사용한 도구, 지금 하는 일을 보여 주고, 위쪽 줄에는 에이전트 수, 실행 중, 확인 필요, 보고된 비용이 나옵니다. 작업 패널에서 하위 에이전트 탭을 연 작업은 카드에 함께 바꾼 파일 수도 나옵니다. 카드를 고르거나 Enter를 누르면 옆에(창이 좁으면 아래에) 하위 에이전트가 펼쳐집니다. 기다리는 하위 에이전트에는 **답변**, 실패한 하위 에이전트에는 **열기**가 있고, 둘 다 그 하위 에이전트의 작업을 엽니다. **카드**는 워크스페이스마다 카드 하나, **표**는 작업마다 한 줄로 보여 줍니다. 표의 열 머리글을 고르면 그 열로 정렬하고, 다시 고르면 반대로, 한 번 더 고르면 작업 대기열 순서로 돌아갑니다. 전에 카드를 쓰고 있었다면 업데이트 후 한 번 트리로 바뀌고, 그 뒤로 고른 보기는 유지됩니다.
화면 보기: [Fleet 보기](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/fleet.png)

## 알림과 이슈

- 상단 바의 **알림**에 질문, 승인, 완료 소식이 모입니다. 에이전트 실행은 단계 확인 요청, 막힘, 정체, 완료 때 한 번씩 알립니다. 승인은 Fleet 보기와 같은 **허용**, **거부**(A, D 키)로 답합니다. 새 알림은 오른쪽 아래 한 곳에 토스트로도 쌓이며, 입력창과 상태 표시줄을 가리지 않도록 그 위에 뜹니다.
- 상단 바의 **이슈**에는 나에게 할당된 Crane과 Jira 이슈가 보이고, **에이전트에 배정**으로 바로 로컬에서 시작합니다. 연결은 **설정 > 통합 > 이슈**에서 합니다. **필터**는 소스, 상태, 우선순위, 프로젝트, 레이블 값을 한 목록에서 검색해 고르고, 옆의 **업데이트**는 오늘, 최근 7·30·90일, 이번 달 중에 업데이트된 티켓만 남기며, 적용된 필터는 칩으로 보여 하나씩 지우거나 **모두 지우기**로 지우고, 옆에 일치하는 이슈 수가 표시됩니다.
