## 1. 앱 설치

```bash
brew install gh
gh auth login
gh api -H 'Accept: application/vnd.github.v3.raw+json' repos/sendbird/stave/contents/scripts/install-latest-release.sh | bash
```

설치 스크립트는 최신 릴리스의 `Stave-macOS.zip`을 받아 `~/Applications`(또는 `/Applications`)에 설치하고 앱을 엽니다.
SSO나 권한 범위 오류가 나면 `gh auth refresh -h github.com -s repo,read:org`를 실행한 뒤 다시 설치합니다.
자세한 설치 안내: https://github.com/sendbird/stave/blob/main/docs/install-guide.md

새 버전이 나오면 상단 바에 **앱 업데이트**가 보이고, **설치 후 다시 시작**으로 바로 바꿉니다.

## 2. AI CLI 설치와 로그인

Stave는 내 컴퓨터에 설치된 CLI를 내 로그인으로 실행합니다. 하나 이상 설치하고 로그인하세요.

| 프로바이더   | 로그인 명령           | 참고                                             |
| ------------ | --------------------- | ------------------------------------------------ |
| Claude Code  | `claude auth login`   | 설치: `npm install -g @anthropic-ai/claude-code` |
| Codex        | `codex login`         | 설치: `npm install -g @openai/codex`             |
| Cursor Agent | `agent login`         | 설치하고 로그인하면 설정에 탭이 나타납니다       |
| Kiro CLI     | `kiro-cli login`      | 설치하고 로그인하면 설정에 탭이 나타납니다       |
| OpenCode     | `opencode auth login` | 설치하면 설정에 탭이 나타납니다                  |

Claude와 Codex는 **설정 > 계정**에서 계정을 더 추가하거나 API 게이트웨이를 연결할 수 있습니다.

## 3. 앱에서 첫 설정

1. 첫 화면에서 **저장소 열기**를 누르고 로컬 git 저장소 폴더를 고릅니다.
2. 쓸 수 있는 프로바이더가 아직 없으면 첫 화면에 **시작하기**와 **계정 열기**가 보입니다. **설정 > 계정 > 시작하기**의 단계(프로바이더 CLI 설치, 로그인, 계정 추가, 게이트웨이 연결, 모델 고르기)를 따라갑니다. 계정 추가와 게이트웨이 연결은 선택입니다.
3. **설정 > 일반 > 언어**에서 한국어를 고를 수 있습니다.
4. **설정 > 프로바이더**에서 권한 프리셋을 확인합니다. [권한과 안전](#safety)을 먼저 읽으세요.

macOS가 데스크톱·문서·다운로드 폴더 접근을 물으면 한 번 허용합니다.

## 네 가지 기본 단위

| 단위         | 무엇인가                             | 알아 둘 점                                                                                                                  |
| ------------ | ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| 저장소       | 사이드바에 등록한 로컬 git 폴더      | 설정에서는 **프로젝트** 페이지가 저장소 설정을 다룹니다                                                                     |
| 워크스페이스 | 브랜치 하나에 묶인 전용 git worktree | 저장소마다 저장소 루트인 **기본** 워크스페이스가 하나 있고, 나머지는 `<저장소>/.stave/workspaces/` 아래에 만들어집니다 |
| 작업         | 워크스페이스 안의 대화 하나          | 탭을 닫아도 보관되지 않습니다. 보관은 탭 메뉴의 **보관**입니다. 작업 중간에 프로바이더를 바꿀 수 있습니다                 |
| 턴           | 요청 하나에 대한 응답 한 번          | 도구 실행, 승인 요청, 질문이 턴 안에서 일어납니다. 턴이 도는 동안 보낸 메시지는 대기열에 쌓입니다                         |

사이드바에서 기본 워크스페이스 이름과 브랜치는 `기본 · main`처럼 한 줄로 표시됩니다. 긴 브랜치는 말줄임 처리하고 브랜치가 없으면 점도 숨깁니다.

## 워크스페이스를 나누는 이유

기본 워크스페이스에서 바로 일해도 됩니다.
하지만 일마다 워크스페이스를 만들면 브랜치와 파일이 분리되어, 여러 AI 작업을 동시에 돌려도 서로의 변경을 덮어쓰지 않습니다.
일이 끝나 PR이 머지되면 워크스페이스를 보관하고, 필요하면 브랜치도 함께 지웁니다.

## 1. 워크스페이스 만들기

사이드바의 저장소 행에 마우스를 올리면 **새 워크스페이스**, **워크스페이스 킥오프**(반짝이 아이콘), **저장소 설정** 버튼이 보입니다.
**새 워크스페이스** 대화상자에서 **워크스페이스 브랜치 이름**과 선택 항목인 **워크스페이스 레이블**을 적고, 만드는 방법을 고릅니다.
화면 보기: [새 워크스페이스](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/new-workspace.png)

| 만드는 방법                    | 하는 일                                                                         |
| ------------------------------ | ------------------------------------------------------------------------------- |
| 브랜치에서 만들기(기본)        | 기준 브랜치를 검색해 고르고, 거기서 worktree를 만듭니다                         |
| 깨끗한 워크스페이스 만들기     | 새 브랜치로 격리된 worktree를 새로 만듭니다                                     |
| 기존 worktree 연결             | 다른 위치의 worktree를 `.stave/workspaces/`에 심볼릭 링크로 연결하고 브랜치를 유지합니다 |

**생성 후 명령**(예: `bun install`)을 넣으면 만들자마자 실행합니다.

### 킥오프로 시작하기

Jira 이슈, PR, 보고서처럼 이미 있는 자료에서 시작하려면 **워크스페이스 킥오프**를 씁니다.
링크나 설명을 붙여 넣고 **원본 맥락 확인**을 누르면 Stave가 자료를 읽어 브랜치, 레이블, 정보 패널 링크, 첫 작업의 모델과 요청을 제안합니다. 모두 고친 뒤 만들 수 있습니다.
**AI 건너뛰기**는 AI 없이 링크와 텍스트만 읽어 제안합니다.
**담당자**에서 **나** 또는 저장된 에이전트를, **위치**에서 새 워크스페이스 또는 **현재 워크스페이스**를 고릅니다. **즉시 시작**을 끄면 첫 요청을 보내지 않고 컴포저에 남겨 둡니다.
화면 보기: [워크스페이스 킥오프](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/kickoff.png)

## 2. 작업 열고 요청 보내기

1. Cmd/Ctrl+N을 누르거나 빈 워크스페이스의 **새 작업**을 누릅니다.
2. 컴포저 아래쪽 모델 버튼(**모델 선택**, Alt+P)에서 프로바이더, 모델, 추론 강도를 고릅니다. **Stave Auto**를 고르면 요청의 난이도에 맞춰 Stave가 모델을 고릅니다.
3. 할 일과 완료 조건을 함께 적습니다. 예: "로그인 후 원래 페이지로 돌아가게 고치고, 리다이렉트 테스트를 추가해 통과시켜 주세요."
4. **보내기**를 누릅니다.

화면 보기: [모델 선택](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/model-picker.png)

컴포저에서 쓰는 기호는 네 가지입니다.

| 기호 | 하는 일                                  |
| ---- | ---------------------------------------- |
| `/`  | 명령(예: `/aside` 곁질문)                |
| `$`  | 스킬을 골라 이번 메시지에 붙입니다       |
| `!`  | 저장한 매크로를 실행합니다               |
| `@`  | 작업, 정보 패널 항목, 파일을 참조합니다  |

## 3. 턴이 도는 동안

```sequence "턴 하나에서 일어나는 일"
participant U 나 | 컴포저
participant S Stave | 데스크톱 앱
participant P 프로바이더 | Claude Code · Codex 등
U -> S: 요청 보내기 | 지침과 맥락을 붙여 전달
S -> P: 턴 시작
P => S: 생각 · 도구 실행 · 응답
P -> S: 승인 요청 | 권한이 필요한 도구
S -> U: 승인 행 표시
U --> S: 한 번 허용 · 항상 허용 · 거부
S --> P: 결정 전달
P => S: 이어서 실행
P --> S: 턴 끝
S --> U: 응답 · 변경 파일 · 요약
@caption 턴 흐름을 단순화한 그림입니다. 승인 단계는 권한 프리셋에 따라 나타나지 않을 수 있습니다.
```

**읽기와 입력**: 언어를 지정하지 않은 코드 블록에는 구문 색을 입히지 않습니다. 입력창은 대화의 글자 크기 설정과 작업 패널의 크기 제한을 따릅니다. 최소형 입력창의 고정폭 글자와 캐럿도 함께 커집니다.

**승인**: AI가 권한이 필요한 도구를 쓰려 하면 컴포저 위에 **한 번 허용**, **항상 허용**, **거부** 버튼이 있는 행이 뜹니다. **항상 허용**은 허용을 계속 유지할 수 있으면 모든 승인 화면에 똑같이 나옵니다. 프로바이더가 직접 유지하거나, 신뢰된 승인 목록에 항목으로 남깁니다. 행에는 요청이 알려 준 위험(예: **네트워크 접근**)도 나옵니다. 펼침 메뉴는 요청한 하위 에이전트를 알려 주고, **안내로 대체**와 **거부 후 안내**를 담고 있습니다. 승인을 기다리는 동안 입력하면 보내기 버튼이 **거절하고 방향 조정**으로 바뀝니다. 승인 카드 안에서는 Cmd/Ctrl+Enter로 한 번 허용하고, Esc로는 거부하지 않습니다. 아무도 답하지 않은 요청은 제한 시간이 지나면 자동으로 거부되며, 카드와 행의 펼침 메뉴에 그 시각이 나옵니다(**응답이 없으면 오후 4:24에 자동으로 거부합니다**). **항상 허용**으로 답한 카드에는 **신뢰됨: <항목> · 제거**가 붙고, **제거**를 누르면 그 항목을 다시 뺍니다.
화면 보기: [승인 요청](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/approval.png)

**진행 줄**: 턴이 도는 동안 단계 목록 위 줄에 지금 진행 중인 단계(예: **search.ts 읽는 중**)만 나옵니다. 단계가 아직 없으면 **생각 중**으로 표시되며, 경과 시간은 메시지 하단에서 확인합니다. 턴이 끝나면 그 턴의 제목으로 바뀝니다. 웹을 검색하거나 가져온 턴은 답변 아래에 **출처**와 개수가 붙고, 펼치면 페이지마다 한 번씩 보여 줍니다.

Thinking 본문은 진행 중과 완료 후 모두 굵은 글씨, 목록, 코드 등의 마크다운을 표시합니다. 도구 인수·출력과 명령어 옆의 복사 아이콘을 누르면 원문이 복사됩니다. 성공하면 체크 표시로 바뀌고, 실패하면 오류를 알려 줍니다.

도구 결과, 생각 과정, 접힌 도구 그룹의 본문은 처음 펼칠 때 불러오며 다시 접어도 유지됩니다. 브라우저에서 본문을 검색하거나 인쇄하려면 먼저 펼쳐 주세요.

**질문**: AI가 선택지가 있는 질문을 하면 숫자 키로 고를 수 있습니다. Claude의 선택지에는 코드 조각 같은 미리보기가 붙을 수 있고, 그 선택지에 포커스나 포인터가 있는 동안 선택지 아래에 보입니다.

**대기열**: 턴이 도는 동안 보낸 메시지는 컴포저 위 선반에 쌓입니다. 항목마다 **방향 조정**(지금 턴에 끼워 넣기), **보내기**, **편집**, **삭제**가 있고, **모두 지우기**로 비웁니다. 앱을 다시 시작해 복원된 대기열은 **재개**를 누를 때까지 기다립니다. 턴을 멈추려면 **중지**를 누릅니다.

**대화 기록**: 연달아 보낸 메시지(방향 조정 등)는 한 묶음으로 붙고, 마지막 메시지 아래에 안내가 한 번만 표시됩니다(**활성 턴에 방향 조정 전달됨 · 3**). 각 메시지에 마우스를 올리면 그 메시지의 복사와 시간 동작이 나타납니다. 응답의 프로바이더, 모델 또는 추론 강도가 바로 앞 응답과 다르면 그 응답 위에 바뀐 내용을 알리는 줄이 표시됩니다(**Claude Sonnet 4.6 · 보통 → Claude Opus 4.8 · 높음**).

**사용 한도**: 프로바이더 사용 한도에 걸리면 선반에 사용 한도 행이 뜹니다. **초기화 시 재개**를 누르면 한도가 풀리는 시각에 자동으로 이어 가고, **지금 재개**는 바로 다시 시도합니다.
화면 보기: [대기열과 사용 한도](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/queue-usage-limit.png)

**활동 탭**: 작업 패널의 **활동** 탭은 턴의 단계를 목록으로 보여 줍니다. **목록 | 타임라인** 전환을 쓰면 같은 턴을 0초, 30초, 1분처럼 눈금이 붙은 시간축에 그립니다. 턴 행에 토큰과 비용이 붙고, 도구 호출과 하위 에이전트가 막대로 놓이며, 턴이 도는 동안 **현재** 선이 보이고, 가장 오래 걸린 단계에 **가장 느림** 표시가 붙습니다. 시간이 기록되지 않은 단계는 축에 놓지 않고 아래에 나열합니다. **에이전트 트리**는 가지마다 접을 수 있고 방향키로 이동합니다. 대화에서는 도구 호출의 인수와 출력에 각각 **복사**가 있고, 긴 출력은 정해진 높이 안에서 스크롤되며 아래에 줄 수가 표시됩니다.

## 4. 변경 확인과 PR

1. 오른쪽 패널의 **소스 제어**에서 바뀐 파일과 기록을 봅니다.
2. 작업 탭 위의 **대화 / 검토** 전환(Cmd/Ctrl+Alt+R)으로 검토 모드를 엽니다. diff에 줄 코멘트를 남기고 **에이전트에 리뷰 보내기**로 고칠 점을 전달합니다. 자세한 내용은 [검토와 위임](#review)을 보세요.
3. 상단 바의 **PR 생성**을 누르면 PR 대화상자가 열립니다. 병합 방식과 자동 병합을 고를 수 있습니다. GitHub CLI(`gh`) 로그인이 필요합니다.
4. PR이 생기면 상단 바에 상태 칩이 보이고, 준비 완료 표시, 브랜치 업데이트, 병합, GitHub에서 열기를 바로 할 수 있습니다.
5. 일이 끝나면 워크스페이스 행의 ⋮ 메뉴에서 **워크스페이스 보관**을 고릅니다. **git 브랜치도 삭제**를 켜면 브랜치도 지웁니다.

@page context | 일하기 | AI에게 맥락 주기 | concept
@lead AI는 내가 보낸 문장만 보지 않습니다. Stave는 저장소 지침, 워크스페이스 정보, 첨부, 스킬을 턴마다 묶어 보냅니다. 무엇이 들어가는지 알면 같은 말을 반복하지 않아도 됩니다.


## 맥락을 주는 방법

| 방법          | 어떻게                                                    | 알아 둘 점                                                                  |
| ------------- | --------------------------------------------------------- | --------------------------------------------------------------------------- |
| 파일·이미지   | 컴포저의 클립 버튼(**파일 첨부**). 붙여 넣거나 컴포저에 끌어다 놓기 | 끌어다 놓으면 **놓아서 첨부**가 보이고 붙여 넣기와 같은 방식으로 첨부됩니다 |
| 다른 작업     | `@`와 작업 제목 일부, 또는 사이드바에서 작업을 끌어 놓기  | **최신 응답** 또는 **최근 대화**를 고릅니다. 메시지당 최대 5개              |
| 스킬          | `$`를 입력하고 고르기                                     | 고른 스킬의 SKILL.md 전체가 함께 전달됩니다                                 |
| `@web`        | 메시지에 `@web`                                           | 선택한 브라우저 연결을 씁니다. 범위는 설정 > 브라우저 > 멘션            |
| 정보 패널     | 메모, 할 일, 링크를 적어 둠                               | 프롬프트에 붙인 Jira·PR 링크는 자동으로 패널에 추가됩니다                   |
| 저장소 지침   | 설정 > 프로젝트 > 저장소 > **저장소 지침**                | 이 저장소의 모든 Claude·Codex 턴에 들어갑니다                              |
| 저장소 메모리 | 정보 > **메모리**                                         | 수집은 기본 꺼짐. 항목당 280자, 한 턴에 최대 6개. 삭제는 확인 없이 바로 되고, 뒤이어 뜨는 알림의 **실행 취소**로 되살림. 항목이 8개 이상이면 검색과 종류 칩이 나타남 |

설정 > 브라우저 > 멘션 > 브라우저 접근에서 Claude Code와 Codex에 사용할
프로바이더 Chrome 연결(Claude Code, Codex, 기본값) 또는 browse 확장 프로그램을 선택하세요. browse CLI
(`@opencode/browse`)를 설치하고 Chrome 웹 스토어에서 확장 프로그램을 추가한 뒤
`browse install`을 실행해 연결하세요. 연결 확인 버튼은 설치 여부, 릴레이와 연결된
브라우저 상태를 요청할 때만 조회하며 결과를 저장하지 않습니다. 두 연결에는 같은
브라우저 모드가 적용됩니다. 무인 자동화와 보조 읽기 전용 실행에는 Stave가 브라우저
연결을 추가하지 않습니다. OpenCode, Cursor, Kiro는 이 `@web` 연결 대상에서
제외됩니다. 프로바이더 설정에 직접 등록한 서버는 해당 프로바이더가 관리합니다.

browse에서 로그인, 2단계 인증 또는 결제가 필요하면 에이전트가 제어를 넘깁니다.
브라우저에서 직접 완료한 뒤 Continue를 누르세요. 도구 실행에는 현재 권한 모드가
적용됩니다. browse 도구가 없으면 설정 > 브라우저에서 확인하도록 안내하며 Lens로
대체하지 않습니다. 쿠키, 비밀번호, 토큰을 에이전트에게 전달하지 마세요.


```callout note "정보 패널이 전달되려면"
정보 패널, 작업 맥락, 최근 턴 요약은 **설정 > MCP > 로컬 MCP 서버**가 켜져 있을 때만 턴에 붙습니다. AI가 메모나 링크를 모르는 것 같으면 먼저 이 설정을 확인하세요.
```

## 흐름을 끊지 않는 기능

- **곁질문**: 컴포저 도구 막대의 **곁질문**, `/aside`, 또는 Cmd/Ctrl+K 다음 Q. 답은 읽기 전용이고 작업 대화에 추가되지 않습니다. Claude와 Codex에서만 됩니다.
- **다시 오셨네요**: 15분 넘게 자리를 비웠다 돌아오면 그동안 일어난 일과 마지막 결정을 요약한 카드가 뜹니다.
- **인계**: 작업 패널 > **인계**에서 **이 작업에서 채우기**나 **에이전트에게 업데이트 요청**으로 인계 기록을 채웁니다. 프로바이더가 작업을 시작하거나 돌아올 때 이 기록을 먼저 받습니다. 섹션의 2,000자에 들어가지 못한 줄은 그 섹션 아래에 **다시 넣기**와 함께 남습니다.
- **프롬프트 개선**: 컴포저의 지팡이 아이콘이 요청 문장을 다듬습니다. **프롬프트 개선됨** 알림에서 **실행 취소**와 **변경 보기**를 고를 수 있고, **변경 보기**는 지운 단어를 취소선으로, 추가한 단어를 밑줄로 보여 주며 **유지**와 **원래대로 되돌리기**를 둡니다.
- **컨텍스트 표시**: 컴포저에서 대화가 얼마나 찼는지와 남은 토큰을 보여 줍니다. Claude는 **구성**에 무엇이 채우는지(시스템 프롬프트, 도구, MCP 도구, 메모리 파일, 스킬, 추정한 대화)를 나열하고, 다른 프로바이더는 합계만 알려 줍니다. **컨텍스트 압축**은 대화가 길어졌을 때 줄입니다. 넓은 입력창은 사용량 / 한도 토큰 수를, 좁은 입력창은 퍼센트를 보여 줍니다. 압축 중에는 시작 시각을 알면 경과 시간을 표시하며, 복원된 비활성 메시지는 시간을 계속 세지 않습니다.
- **매크로**: 컴포저 도구 막대에서 저장한 매크로 목록을 열고 이름, `!slug`, 설명으로 검색합니다.

@page safety | 일하기 | 권한과 안전 | guide
@lead 프로바이더마다 AI가 묻지 않고 할 수 있는 범위를 모드 프리셋으로 정합니다. 새로 설치하면 모든 프로바이더가 가장 넓은 **자동** 프리셋으로 시작하니, 처음에 한 번 확인하세요.

```callout warning "기본값은 자동입니다"
새 설치에서는 Claude, Codex, Cursor, Kiro, OpenCode가 모두 **자동** 프리셋입니다. Codex는 전체 디스크 접근, 승인 없음, 네트워크 켜짐으로 시작합니다. 확인이 필요한 저장소라면 **설정 > 프로바이더 > 모드 프리셋**에서 **안내형**이나 **수동**으로 바꾸세요.
```

## 프리셋별 동작

화면 보기: [설정 > 프로바이더](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/settings-providers.png)

| 프로바이더 | 수동                                         | 안내형                                     | 자동                                                     |
| ---------- | -------------------------------------------- | ------------------------------------------ | -------------------------------------------------------- |
| Claude     | 기본 권한 모드, 샌드박스 켜짐                | 파일 편집은 자동 허용, 샌드박스 꺼짐        | Claude 분류기가 판단, 샌드박스 꺼짐                      |
| Codex      | 읽기 전용, 필요할 때 승인 요청, 네트워크 꺼짐 | 워크스페이스 쓰기, 신뢰하지 않는 명령은 승인, 네트워크 꺼짐 | 전체 디스크 접근, 승인 없음, 네트워크 켜짐, 실시간 검색 |
| Cursor     | 도구 호출마다 묻기                           | Cursor 자체 자동 검토                      | 모든 도구 호출 실행, MCP 서버 신뢰                        |
| Kiro       | 도구 호출마다 묻기                           | 없음                                       | 모두 자동 승인                                           |
| OpenCode   | 읽기까지 포함해 매번 묻기, 하위 에이전트 없음 | 없음                                       | 모든 요청 승인. OpenCode의 `deny` 규칙은 그대로 적용     |

컴포저의 프리셋 메뉴와 **설정 > 프로바이더**는 선택한 프리셋 아래에 그 프리셋에서 바로 실행하는 일과 먼저 물어보는 일을 행동별로 보여 줍니다(파일 읽기, 파일 편집, 명령 실행, 웹 도구, MCP 도구 등). Claude는 켜 둔 가드레일(G1–G3)도 함께 보여 주며, 이 항목은 에이전트 모드에서 프리셋과 상관없이 항상 먼저 물어봅니다. 다른 프로바이더에는 이런 고정 항목이 없습니다.

세부 항목을 바꾸면 프리셋 표시가 **사용자 지정**으로 바뀝니다. 컴포저의 런타임 칩은 현재 상태를 **안전**, **사용자 지정**, **확장됨**으로 보여 줍니다.

## 저장소마다 다르게 쓰기

설정 맨 위의 적용 대상 선택기(처음에는 **모든 프로젝트**)에서 저장소를 고르면 모델, 추론 강도, 권한을 그 저장소에만 따로 정할 수 있습니다. 원래 값으로 돌리려면 항목의 전역 값 사용을 누릅니다.

## 에이전트 실행의 안전장치

작업이 에이전트로 실행될 때는 저장소 밖에 쓰기, 자격 증명 경로 접근, 되돌릴 수 없는 원격 작업을 막는 안전장치(G1~G3)가 기본으로 켜집니다. Claude는 훅으로 셋 모두를 막고, Codex는 샌드박스로 저장소 밖 쓰기(G1)만 막습니다.

## 시크릿

API 키 같은 값은 채팅에 붙여 넣지 마세요. 에이전트가 값을 요청하면 컴포저 위에 가려진 입력 카드가 뜹니다. **저장 및 연결**로 저장하거나 **저장된 시크릿 사용**으로 고릅니다. 값은 운영체제의 자격 증명 저장소에 저장되고, AI에게는 변수 이름만 전달됩니다. 직접 관리하려면 **설정 > 시크릿 > 시크릿 추가**를 씁니다.

@page agents | 맡기기 | 에이전트와 실행 | concept
@lead 에이전트는 지침, 모델, 권한, 단계를 저장해 둔 작업자입니다. 작업에 에이전트를 지정하면 실행(Run)이 시작되고, Stave가 단계와 완료 조건을 확인하며 끝까지 이어 갑니다.

```diagram architecture "에이전트, 작업, 실행의 관계"
box agent 1,1 primary | 에이전트 | 저장된 정의 | 지침 · 모델 · 권한 · 단계
box task 2,1 | 작업 | 에이전트가 지정된 대화 | 한 번에 실행 하나
box run 3,1 primary | 실행 | 단계를 차례로 진행 | 완료 조건 · 팀 한도
box stage 4,1 | 단계 | AI 단계 또는 Stave 동작 | 초안 PR · 검사 감시 · 스크립트
box sub 3,2 | 위임 작업 | 하위 에이전트 | 리뷰어 등
box fleet 4,2 | Fleet 보기 | 내 조치가 필요할 때 | 답변 · 승인 · 확인
edge agent -> task main : 지정
edge task -> run main : 시작
edge run -> stage main : 차례로
edge run -> sub dashed : 위임
edge run -> fleet dashed : 사람이 필요함
@caption 앱 코드의 에이전트 모델을 바탕으로 한 개념도입니다. 에이전트 자체는 아무것도 시작하지 않고, 지정될 때 실행이 생깁니다.
```

## 에이전트 만들기

사이드바의 **에이전트**(Cmd/Ctrl+K 다음 G)를 엽니다. 탭은 **에이전트**, **내 기준**, **성과**입니다.
**새 에이전트**를 누르고 **에이전트 초안 작성**으로 설명에서 초안을 만든 뒤 고칩니다.
에이전트는 출처에 따라 내장, 사용자 지정, 저장소(`.claude/agents/` 같은 파일)로 나뉩니다.
상세 화면에서 **지정…**, **복제**, **보관**, **내보내기**, **저장소에 쓰기**를 할 수 있습니다.
화면 보기: [에이전트](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/agents.png)

**실행 방식** 섹션의 주요 설정:

| 설정          | 선택지                                         | 뜻                                                        |
| ------------- | ---------------------------------------------- | --------------------------------------------------------- |
| 권한          | 자동 등                                        | 자동이 아니면 실행이 승인 카드마다 멈춥니다               |
| 확인 시점     | 정체될 때만(기본), 게시 전, 매 단계            | 단계 사이에서 내 확인을 받을 시점                         |
| 완료 전 리뷰  | 동작이 바뀔 때(기본), 항상, 끔                 | 켜면 작업 → 리뷰 → 리뷰 지적 수정 단계가 붙습니다         |

## 실행의 단계

```pipeline "완료 전 리뷰가 켜진 실행"
작업 | 지시와 완료 조건대로 일합니다.
리뷰 | 다른 에이전트가 읽기 전용으로 변경을 검토합니다.
수정 | 리뷰에서 나온 문제를 고칩니다.
! 완료 확인 | Stave가 워크스페이스 검사 명령을 직접 실행해 통과를 확인합니다.
@caption 파일을 바꾸지 않은 작업은 리뷰 단계 없이 끝납니다.
```

워크플로가 없는 에이전트는 작업 단계 하나로 실행됩니다.
단계는 AI 단계(지시와 완료 조건)이거나 Stave 동작입니다. Stave 동작은 초안 PR 열기(Open draft PR), 검사 감시(Watch checks), 리뷰 준비 전환(Ready for review), 스크립트 실행(Run script)입니다.

## 실행 상태

```diagram architecture "실행 배지 사이의 이동"
box running 1,2 primary | 실행 중 | 일하거나 기다리는 중 | 기다리는 동안 턴을 쓰지 않음
box answer 2,1 | 답변 필요 | 질문 · 승인 · 단계 시작 확인 | 답하면 다시 실행 중
box paused 2,2 | 일시정지 | 내가 멈춤 · 직접 조작 | 재개하면 다시 실행 중
box halted 2,3 | 멈춤 | 막힘 · 한도 · 대기 만료 | 실행 줄 버튼으로 이어 감
box done 3,1 | 완료 | 완료 조건 충족 | 산출물에 보고서
box stopped 3,3 | 중지됨 | 취소 · 이유 카드 | 다시 시도 · 직접 제어
edge running -> answer : 사람이 필요함
edge running -> paused dashed : 일시 중지
edge running -> halted : 진행할 수 없음
edge running -> done main : 완료 확인 통과
edge halted -> stopped dashed : 중지
@caption 앱 코드의 실행 상태와 배지를 단순화한 그림입니다. 답변 필요, 일시정지, 멈춤에서는 답하거나 재개하면 실행 중으로 돌아갑니다.
```

| 배지      | 뜻                                                                                 | 할 일                                     |
| --------- | ---------------------------------------------------------------------------------- | ----------------------------------------- |
| 실행 중   | 일하는 중. PR 검사, 사용량 한도처럼 기다리는 이유가 붙기도 합니다. 기다리는 동안 턴을 쓰지 않습니다 | 기다립니다                                |
| 답변 필요 | 질문이나 승인 카드가 열렸거나, 다음 단계 시작 확인을 기다립니다                    | 카드에 답합니다                           |
| 일시정지  | 내가 멈췄거나 직접 조작 중입니다                                                   | 작업 패널 > 진행의 **재개**               |
| 멈춤      | 막힘, 복구 필요, 대기 만료, 사용량 한도, 한도 도달                                 | 아래 실행 줄 버튼으로 이어 갑니다         |
| 완료      | 완료 조건을 채웠습니다                                                             | 산출물에서 실행 보고서를 봅니다           |
| 중지됨    | 취소되었거나 이유 카드와 함께 끝났습니다                                           | **다시 시도** 또는 **직접 제어**          |

실행 시간은 **활성 시간**입니다. 일시 중지, 답변이나 단계 시작 확인을 기다린 시간, Stave가 꺼져 있던 시간은 세지 않습니다. 작업 패널 > **진행**의 각 단계에는 그 단계의 턴이 쓴 사용량이 나옵니다. Claude는 비용, Codex는 토큰입니다.

컴포저 위 실행 줄에는 상황에 맞는 버튼이 뜹니다: **다시 시도**, **연장 (+10턴)**, **지금 재개**, **이어서 진행**, **중지**, **직접 제어**(실행을 끝내고 같은 모델의 일반 대화로 이어 감). **Tars** 표시가 붙은, Tars가 맡은 실행에서는 **중지**(여기, 입력창, Esc)가 실행을 취소하지 않고 Tars에서 작업을 일시 정지하며, **직접 제어**는 실행을 끝내지 않고 일시 정지한 채로 넘겨받는 Tars의 직접 맡기입니다.
작업 패널 > **진행**에는 **이 실행이 하는 일**, **완료 조건**, **팀 한도**, 단계 카드(**단계 다시 시도**, **단계 건너뛰기**)가 있습니다.
완료 조건은 **충족됨 · Stave 확인**, **충족됨 · 에이전트 보고**, **미충족**, **검증 안 됨** 중 하나로 표시됩니다.
화면 보기: [진행 탭](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/agent-run-panel.png) · [단계 시작 확인 카드](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/run-sign-off.png)

## 목표를 맡기고 자리 비우기

1. 에이전트의 **실행 방식**에서 권한을 **자동**으로 둡니다.
2. **설정 > 프로젝트 > 워크스페이스 도구**에 검사 명령(예: `bun run typecheck && bun test`)을 추가합니다. 파일을 바꾼 실행은 Stave가 이 명령을 직접 돌려 통과해야 끝납니다.
3. 필요하면 **완료 전 리뷰**를 켜거나, 작업 · 리뷰 · 수정 단계를 직접 만듭니다.
4. **설정 > MCP > 로컬 MCP 서버**를 켜고, PR 단계를 쓰려면 `gh auth login`을 해 둡니다.
5. 에이전트 상세에서 **지정…**을 누르고, 원하는 결과와 그것을 증명할 방법을 적고, **위치**를 고른 뒤 지정합니다. 컴포저에서 에이전트를 골라 보내도 됩니다.
6. 자리를 비웁니다. 실행은 안전한 승인, PR 검사와 리뷰 대기, 사용량 초기화 대기를 스스로 처리합니다.
7. Fleet 보기의 **조치 필요**나 알림이 실행을 가리키면 돌아와 카드에 답하거나 실행 줄 버튼으로 이어 갑니다.
8. 끝나면 산출물의 실행 보고서에서 PR 설명에 추가하거나 Slack에 공유합니다.

## Tars에 일을 계속 맡기기

사이드바의 **Tars**에서 등록된 저장소에 걸친 결과를 맡깁니다.
저장된 Supervisor 에이전트와 달리, Tars는 하나의 개인 이름과 상시 지침,
맡긴 일 목록을 특정 Task 밖에 보관합니다.

주 화면은 하나의 지속 대화입니다. 메시지로 진행 상황을 묻고, 계획을 함께
세우고, 우선순위를 바꾸거나 일을 맡깁니다. 작업 실행 중에도 계속 대화할 수
있습니다. 메시지마다 워크스페이스·모드·작업 폼을 입력하지 않으며, 실행 대상이
불분명할 때 대화에서 확인합니다. 워크스페이스를 바꿔도 같은 대화가 이어지고,
저장소를 등록하기 전에도 일반 대화를 할 수 있습니다.

**보내기** 옆의 **파일 첨부**로 파일을 고르거나 입력창에 끌어 놓거나 붙여 넣습니다. 워크스페이스 밖의 텍스트 파일과 PNG·JPEG·GIF·WebP 이미지도 첨부할 수 있습니다. 최대 8개까지, 텍스트는 합계 32KB, 이미지는 개당 4MB·합계 6MB로 첨부합니다. 이름이 같은 파일도 각각 보존하며, 이름에 번호를 붙여 구분합니다. 보내기 전에 파일 옆의 제거 버튼으로 뺄 수 있습니다. 지원하지 않는 형식이거나 크기를 넘으면 오류를 표시하고 초안을 유지합니다. 선택 당시 내용을 메시지에 저장해 대화 모델에 전달하며, 재시작 후에도 대화에서 첨부 이름을 볼 수 있습니다. 대화에는 첨부를 이름·형식·크기가 보이는 칩으로만 표시하고, 이미지 데이터 같은 내용은 대화를 새로 고칠 때마다 다시 읽지 않고 Tars가 그 메시지를 판단할 때와 그 메시지로 맡긴 작업이 시작될 때만 읽습니다. 파일만 보내 대화할 수 있지만, 작업을 맡기려면 Tars에게 시킬 일을 글로 함께 적어야 합니다.

첨부는 그 메시지로 맡긴 작업에도 전달되므로, 스크린샷을 첨부해 "이거 고쳐 줘"라고 보내면 작업하는 에이전트도 그 스크린샷을 봅니다. 작업의 실행은 첫 턴에 첨부를 파일과 이미지로 함께 받고, 다음 턴부터는 다시 보내지 않습니다. 실행이 부르는 도우미에게는 리드가 넘겨준 내용만 전달됩니다. 한 메시지로 작업을 여러 개 맡기면 각 작업이 첨부를 모두 받으며, 버그마다 스크린샷이 따로 있을 때처럼 Tars가 작업에 필요한 첨부만 골라 줄 수도 있습니다. 대기 중인 작업은 다시 실행한 뒤에도 첨부를 그대로 가지고 있습니다. 작업이 시작될 때 저장된 첨부를 읽지 못하면 첨부 없이 진행하지 않고, 첫 턴을 시작하지 않은 채 이유와 함께 기다립니다. 작업의 **요청** 보기에서 첨부 이름을 볼 수 있습니다.

헤더의 **설정**에서 이름, 상시 지침, 대화 모델과 계정, 실행 모델, Tars가 쓸 수
있는 에이전트, 작업 하나가 쓸 수 있는 턴 한도를 바꿉니다. 처음에는 현재 앱의 모델·계정 설정을
사용하고 이 대화의 설정으로 저장합니다. 대화 모델은 Tars와 대화할 때만 씁니다.
**실행 모델**의 기본값은 **자동**입니다. 맡긴 작업은 Stave Auto가 경로를 정하고,
리뷰는 다른 프로바이더에서 진행할 수 있습니다. 모든 단계와 리뷰를 한 모델에
고정해야 할 때만 모델을 지정하세요. Tars는 Claude와 Codex에서만 작업을 실행하며
Cursor, Kiro, OpenCode는 지원하지 않습니다.

내장 에이전트는 Tars가 항상 쓸 수 있습니다. 저장한 에이전트는 **Tars가 쓸 수 있는
에이전트**에서 허용해야 Tars가 일을 맡길 수 있습니다. Shipper처럼 게시하는
에이전트는 쓰지 않습니다. 게시는 확인 카드에서 확인하신 뒤 Stave만 합니다. 없거나, 허용하지 않았거나,
위임 작업을 맡을 수 없거나, 지정한 실행 모델에서 실행할 수 없거나, 맡기는 작업에
허용된 권한보다 넓게 실행되는 에이전트는 거부하고 대화에 이유를 표시합니다. 이미 맡긴 작업은 선택한 계정과 실행 설정을
유지합니다. 답변은 제안이며, 조치 접수 결과와 작업 상태 변화가 대화에 따로
표시됩니다.

헤더에는 "실행 1 · 대기 2 · 확인 1 · 끝남 3"처럼 맡긴 일의 현황이 보입니다.
**실행**은 실제로 실행 중인 일만 세고, 대기 중이거나 일시 정지되었거나 응답을
기다리는 일은 **대기**, 직접 맡은 일은 **직접**으로 셉니다. 누르면
맡긴 일 트레이가 열리고, 창이 넓으면 트레이가 대화 옆에 계속 열려 있습니다.
트레이는 **확인 필요**, **진행 중**, **끝남**(접힘)으로 나뉩니다. 카드마다 제목과
상태 태그, 담당, Stave가 알고 있을 때의 남은 턴과 작업 중인 보조 Agent, 내 확인을
기다리는 내용이 보입니다. 상태 태그는 색이 겹치지 않습니다. 실행 중인 일만 파란색에
움직이는 표시를 쓰고, 진행 불가는 주황색, 완료는 초록색이며, 대기·응답 대기·일시
정지·직접 진행 중은 중립색에 각자의 기호와 단어로 구분합니다. Stave가 실행을 읽은 카드는 실행 모니터로 보입니다. 지금
단계("지금: 원인, 2회 시도"처럼)와 그 단계에서 지난 시간, 단계마다 한 칸씩(완료,
진행 중, 시작 전, 멈춤) 나뉜 막대, "2/3" 같은 단계 수, 그 단계에서 실행 타임라인을
여는 **타임라인**이 있습니다. **타임라인**과 **요청**은 카드 아래쪽 끝의 아이콘 버튼이며
툴팁에 이름이 나오고, 작업의 브랜치는 담당 아래 줄에 있습니다. 그 아래에는 Stave가 관측한 내용이 나옵니다. 실행의
턴이 지금 하는 일("테스트 실행 중 · 방금 관측"처럼), 진행 중인 턴이 없거나 아직 턴
활동이 이 창에 도착하지 않았으면 그 사실과 마지막 업데이트 시각, 실행 중인데 5분 넘게 관측이 없으면 "7분 동안 관측 없음 · 진행
정보가 오래됐을 수 있습니다"를 주황색으로 보여 줍니다. **최근 진행**에는 실행에 기록된
최근 변화 세 개가 경과 시간과 함께 나옵니다. Stave가 모르는 값은 0으로 표시하지 않고
빼 두며, 실행을 관측하지 못한 일은 "아직 관측된 실행 정보 없음"이라고 표시합니다.
버튼은 주 동작(**일시 정지**, **재개** 등)과
**Task 열기** 두 개만 보이고, **직접 맡기**, **Fleet에서 보기**, **책임 취소**는
카드의 더 보기 메뉴에 있습니다. 대기 중인 작업은 시작된 작업 뒤에 시작할
순서대로 놓입니다. 대기 카드의 주 동작은 **지금 시작**으로, 실행 중인 작업과 함께 그 작업을 바로 시작합니다. 그 메뉴에는 **먼저 하기**와 **나중에 하기**가 더 있고, 손잡이를
드래그해 대기 카드 사이로 옮기거나 **Alt+위쪽 화살표**와 **Alt+아래쪽 화살표**로
옮길 수 있습니다. 옮길 때마다 새 우선순위가 대화에 기록 행으로 남습니다. Tars가 제안하고 내 확인을 기다리는 일이 있으면 주
동작이 **재개 확인**처럼 그 확인 버튼으로 바뀝니다. 자리를 비웠다가(Tars를 닫았거나
창이 가려졌다가) Tars로 돌아오면 트레이 맨 위에 **자리를 비운 사이** 요약이
나타납니다. 마지막으로 Tars를 본 뒤 확인이 필요해진 일, 실패한 일, 끝난 일의 수와
최근 항목이 보이고, 항목을 누르면 보고서나 타임라인이 열립니다. X로 닫을 수 있으며,
처음 방문했거나 바뀐 것이 없으면 나타나지 않습니다. 마지막으로 본 시각은 이 기기에만
저장됩니다. 처음 읽기 전에는 확인 중이라고
표시하며, 읽기에 성공하기 전에는 "맡긴 일 없음"이라고 하지 않습니다. 트레이는
Fleet 보기가 Tars 작업으로 보여 주는 행을 그대로 세므로 두 화면의 숫자가 늘
같습니다. Tars가 일을 맡기면 그 메시지 아래에 작업 흐름이 붙습니다. 요청, Tars의
결정, 실행의 각 단계, 완료 순서이며, "3단계 중 1단계 완료 · 실행 중"처럼 상태 표시와
함께 한 줄로 접힌 채 그 아래에 카드와 같은 관측 줄을 두고 제자리에서 갱신됩니다.
요청을 누르면 맡긴 내용을, 단계를 누르면 실행 기록에서 그 단계를, 리뷰 단계를 누르면
리뷰를, 완료를 누르면 결과 보고서를 보여 줍니다. **Fleet에서 보기**는
각 단계의 더 보기 메뉴에 있습니다.
일이 실행되는 동안 입력창 위 띠에 그 일의 이름, 단계("3단계 중 2단계 · 원인, 2회
시도"처럼), Stave가 마지막으로 관측한 내용과 **타임라인**이 보이며, 실행 중인 일이
두 개를 넘으면 나머지는 개수로 보여 줍니다. Tars가 아직 답을 쓰는 중이면 답이
나올 자리에 움직이는 표시와 함께 **생각 중**이 반짝이며 표시됩니다. 답변 위에는 이름
줄이 없고, 메시지 시각은 메시지에 마우스를 올리거나 포커스할 때만 그 위에 나타나며,
대화 글자 크기는 채팅 글꼴 크기 설정을 따릅니다. 사이드바의 **Tars** 항목에는 실행 중인
일의 수와 움직이는 표시, 확인이 필요한 일의 주황색 개수가 보이고, 사이드바를 접으면
확인이 필요할 때는 주황색, 실행만 있을 때는 파란색 점 하나로 보입니다. 대화에는
말과 결정, 그리고 일이 완료되거나 진행 불가가 되거나 취소된 순간만 상태 태그와 같은
단어로 남습니다. 변경은 새로 고침을 기다리지 않고 Tars가 저장하는 즉시 반영됩니다.

트레이의 네 번째 구역 **산출물**에는 작업이 만든 것이 모입니다. 실행이 끝나면
**결과 보고서**, 파일을 바꿨으면 **변경 사항**, 리뷰어가 보고했으면 **리뷰**, 그리고
보고서에 기록된 풀 리퀘스트 같은 링크(브라우저에서 열림)입니다. 헤더에는
산출물이 있을 때만 "끝남 1 · 산출물 4"처럼 개수가 붙습니다. 산출물이나 작업
카드 아래쪽의 **요청** 아이콘을 누르면 대화 옆에 옆 보기가 열립니다. 넓은 창에서는 트레이 자리를 트레이와 같은 폭으로
차지하므로 대화 폭이 바뀌지 않고, 닫을 때까지 트레이는 헤더 표시로 접힙니다. 각 패널은
제목 줄에 이름이 있습니다. 트레이는 **맡긴 일**, 옆 보기는 **실행 기록**처럼 보기 종류와
그 아래 작업 제목입니다. 좁은 창에서는
대화와 입력창 사이에 화면 높이의 40%까지만 열리고 스크롤됩니다. 위쪽에서
**요청**, **보고서**, **변경 사항**, **기록**, **리뷰**를 바꿔 볼 수 있고, Esc나 닫기 버튼으로
닫으면 연 곳으로 포커스가 돌아갑니다. "보고서 보여줘"처럼 말로 요청해도 됩니다.
Tars는 보기를 열기만 하며 이 방법으로 작업을 바꿀 수 없습니다. 옆 보기를 열고
닫는 일은 대화에 기록되지 않습니다.

- **요청**: 맡긴 내용입니다. 작업이 받아들여진 순간부터 볼 수 있어서, Task나 실행
  없이 대기열에서 기다리는 동안에도, 상태가 바뀌거나 Stave를 다시 실행한 뒤에도
  그대로 열립니다. **보낸 메시지 원문**은 작업을 시작한 메시지를 보낸 그대로,
  보낸 시각과 함께 보여 줍니다(Tars의 질문에 답으로 고른 것이면 그 질문도 함께
  보여 줍니다). **Tars가 정리한 위임 지시**는 Tars가 이 작업을 위해 쓴 지시이며,
  실행에는 보낸 메시지와 함께 전달됩니다. **첨부 N개**에는 보낸 메시지의 파일과
  이미지 중 이 작업이 받은 것의 이름이 나오며, 실행은 첫 턴에 이를 함께 받습니다.
  **완료 기준**에는 저장된 기준이
  나옵니다. 긴 내용, 줄바꿈, 코드도 빠짐없이 보여 주며 각 내용은 복사할 수
  있습니다. 이 보기가 생기기 전에 맡긴 작업은 그 작업을 시작한 메시지를 대화에서
  다시 읽어 **보낸 메시지 원문**으로 보여 주고, 실행에 전달된 지시 전체도 함께
  보여 줍니다. 그 메시지가 대화에 없거나 메시지로 시작한 작업이 아니면 **원문이
  저장되어 있지 않습니다**라고 알리고, 대신 실행에 전달된 지시 전체를 보여 줍니다.
  "queued인 것들 내가 보낸 순서대로 보여 줘"처럼 Tars에게 요청을 보낸 순서대로
  물어볼 수도 있습니다. Tars는 최근 요청 20개까지 보낸 시각, 앞부분 300자, 그
  요청으로 시작한 작업을 보고 답하며, 잘린 부분이 있으면 그렇다고 말하고 전체
  내용은 이 보기에서 보라고 안내합니다.
- **결과 보고서**: 기준마다 판정과 그 판정을 정한 출처(어느 단계의 에이전트 보고,
  또는 Stave 검사와 그 결과)를 확인한 리비전, 그것이 최종 리비전인지와 함께 보여
  줍니다. 근거는 보고한 단계 아래에 한 번만 **Stave에서 검증함**, **프로바이더
  결과**, **에이전트 보고**로 구분해 나옵니다. 실행이 끝난 시각 기준으로 고정된 내용이며,
  충족하지 못한 기준과 남은 일이 이어집니다.
- **변경 사항**: 실행 워크스페이스에서 바뀐 파일과 파일별 diff입니다. 보고서와 달리
  지금의 워크스페이스를 보여 주며, **새로 고침**으로 다시 읽습니다. diff에서 줄을
  선택하고 **이 부분 묻기**를 누르면 파일, 줄 범위, 줄 내용이 입력창에 인용됩니다.
  직접 보내기 전에는 아무것도 보내지 않습니다.
- **기록**: 먼저 **지금**(상태, 실행 중인 단계, Stave가 관측한 내용과 그 시점, 최신순
  최근 진행)이 나오고, 이어서 단계와 시도(진행 중인 단계의 시간은 계속 흐름), 실행이
  스스로 내린 결정(경로, 대기, 재시도), 인계와 제어, 접힌 명령·도구 호출입니다. 실행이
  없는 일은 아직 시작되지 않았는지, 실행이 시작되기 전에 끝났는지를 알려 줍니다.
- **리뷰**: 리뷰어의 판정과 발견 사항을 리뷰어의 말 그대로 보여 줍니다.

Stave가 확인한 완료 작업은 Draft PR로 올릴 수 있습니다. **끝남**의 카드나 보고서에서
**Draft PR 만들기**를 누르거나 Tars에게 "Draft PR 올려줘"처럼 요청하세요. 확인
카드에 저장소, 기준 브랜치와 작업 브랜치, 변경된 파일 수, 커밋 메시지와 PR 제목(둘 다
고칠 수 있고 커밋 유형도 바꿀 수 있습니다), 보고서로 만든 PR 본문이 보입니다.
**Draft PR 열기**나 Enter를 누르면 게시하고, **거절**이나 Esc를 누르면 아무것도
게시하지 않습니다. 그러면 Stave가 커밋하고 작업 브랜치를 푸시한 뒤 Draft PR을 엽니다.
병합, 배포, 강제 푸시는 하지 않으며 매번 다시 확인을 받습니다. 카드는 "Draft PR #12
열림 · 작업 이름 · 클릭" 같은 기록 행으로 접히고, PR은 **산출물**과 보고서에 나타납니다. 단계 하나가 실패하면
**다시 시도**가 카드를 다시 열어 멈춘 단계부터 이어서 합니다.

트레이의 진행 불가 카드는 이유와 함께 **보고서 열기**를 보여 줍니다. 확인할 내용에 진행 불가가
함께 나오면 그 줄 끝에 있습니다. 누르면 보고서의
미충족 기준으로 열리고, 그 작업에 허용되는 다음 동작이 함께 나옵니다. **재개**,
**직접 맡기**, **책임 취소**이며, Stave가 확인하지 못한 완료라면 그 결정 카드입니다.
작업 흐름에서 막히거나 멈춘 단계도 이유를 보여 주고 같은 곳을 엽니다.

작업은 독립 워크트리에서
실행·독립 리뷰·검증을 진행하며 기준 워크스페이스의 미커밋 변경은 복사하지
않습니다. 메시지를 보낼 때 **보내기** 옆의 **작업 중인 변경 포함** 아이콘 버튼을 켜면,
Stave가 내 파일을 건드리지 않고 워크스페이스의 미커밋 변경을 스냅숏으로
저장하고(무시된 파일은 제외) 그 스냅숏에서 작업을 시작합니다. 트레이 카드에는
짧은 커밋과 함께 그렇게 표시됩니다. 이 토글은 보낼 때마다 다시 꺼집니다.
입력 중인 내용은 이 선택과 함께 초안으로 남아 Tars를 떠났다 돌아오거나 앱을
다시 실행해도 그대로 있습니다. 첨부한 파일은 Stave를 종료할 때까지 초안과 함께
남습니다. 전송된 메시지는 초안을 지우고, 전송에 실패하면 초안이 남으며 대화 끝의 알림에서
**다시 시도**할 수 있습니다. 초안을
저장하지 못하면 보내기를 멈추고 초안을 남기며, 종료할 때는 Stave를 열어 두거나 다시
저장하거나 저장하지 않고 종료할 수 있습니다. **일시 정지**, **재개**, **직접 맡기**, **다시 맡기기**, **책임 취소**로
맡긴 작업을 제어합니다. "멈춰", "내가 할게"처럼 말로 요청해도 같은 확인을 거치며,
클릭한 조작은 대화에 기록 행으로 남습니다. Tars가 맡은 작업은 Fleet 보기와
작업의 실행 줄에 **Tars** 표시가 붙습니다. Fleet 행 패널의 **일시 정지**와
**직접 맡기**, 실행 줄의 **직접 제어**, 그 작업의 모든 **중지**(입력창, Esc,
명령 팔레트, 실행 줄)도 Tars를 거칩니다. 실행은 취소되지 않고 일시 정지되며,
기록에는 "일시 정지 · Verified result · Fleet · 적용됨", "… · 작업 화면 · 적용됨"처럼 누른
곳이 함께 남습니다. Tars가 이미 일시 정지한 작업에서 **중지**는 내 턴만 멈춥니다.
입력창에서 에이전트를 바꾸려면 먼저 작업을 직접 맡으세요. 대기 중인 작업을 "바로 실행해"처럼 말로 요청하면 바로 시작합니다. 말로 요청한 재개, 다시 맡기기,
취소는 **확인** 버튼이 있는 결정 카드로 기다리며, 확인해야 적용됩니다. 실행 중인 작업에 "알아서 진행하라고 해"처럼 전해 달라고 한 말도 같습니다. 그 Task에서 턴이 진행 중이면 Stave가 말을 보관했다가 턴이 끝난 뒤 한 번 전달하며, 카드에는 **실행의 현재 턴이 끝나기를 기다리는 중입니다**, 이어서 **턴이 끝난 뒤 Task에 전달했습니다** 또는 그 전에 작업을 직접 맡았거나 취소했거나 작업이 끝나 전달하지 않았다는 안내가 표시됩니다. 같은 작업에 먼저 보관한 말이 남아 있으면 새 말은 그 뒤에 순서대로 전달하며, 직접 맡았다가 다시 맡겨도 그 전에 보관한 말은 전달하지 않습니다. Stave를 다시 실행해도 유지되고 두 번 전달되지 않으며, 권한을 주지 않습니다. 직접 맡은 일은 다시 맡기기 전까지
내 일로 남고, 다시 맡긴 일은 Tars가 완료 전에 다시 검증합니다. 실행이 기준을 모두
충족했다고 보고하는 것만으로는 완료되지 않습니다. 최종 단계에서 Stave가 현재 revision의
검사 통과를 직접 확인했거나, 같은 revision에 대한 독립 리뷰가 통과해야 Tars가 완료로 처리합니다. 그렇지 않으면
결정 카드가 **완료로 인정**, **책임 취소**, **Tars에게 새 검증 작업 요청** 중에서 고르게
합니다. 마지막 항목은 그 요청을 메시지 입력란에 써 둘 뿐 바로 실행하지 않습니다.

Tars가 내 선택이 필요할 때는 대화에 결정 카드를 띄웁니다. 질문과 두 개에서 네 개의
선택지가 있고, 선택지마다 짧은 이유가 붙으며, Tars가 권하는 항목이 있으면 추천으로
표시됩니다. 확인 카드(Tars가 제안한 제어, 또는 Stave가 확인하지 못한 완료)는
"이 작업의 책임을 취소할까요?"처럼 하는 일과 대상 작업을 먼저 보여 주고, Stave가
알고 있을 때 저장소, 워크스페이스, 리비전, 효과를 행으로 보여 줍니다. 되돌릴 수
없는 효과(책임 취소, 완료로 인정)에는 **되돌릴 수 없음** 태그가 붙습니다. 카드
아래쪽에는 결정을 그대로 두고 메시지 입력란으로 돌아가는 **나중에**(Esc)와 키가
표시된 **확인**이 있습니다. 질문의 선택지는 라디오 목록으로, 선택지마다 이름과 그
아래 줄의 이유, 번호 키가 보이고, 추천 항목은 표시와 함께 처음부터 골라져 있습니다.
**답하기**는 고른 항목으로 답합니다. 기다리는 동안 카드에는 주의 색 테두리가
둘러집니다. 선택지를 클릭하거나 카드에 포커스를 두고 **1**~**4** 또는 화살표 키로
고른 뒤 **답하기**나 **Enter**를 누르세요. 메시지 입력란에서 누른 키는 그대로 글자로
입력됩니다. Tars의
마지막 답에서 기다리는 결정이 하나뿐이고 그 뒤로 아무것도 쓰지 않았다면 "1", "응",
"yes" 같은 짧은 답이 그 결정에 대한 답이 됩니다. 숫자는 그 항목을, 긍정의 답은 추천
항목을 고르고, 그 밖의 말은 평소처럼 Tars에게 보내집니다. 책임 취소와 완료로 인정은
기본값이 되지 않으므로 처음부터 골라져 있지 않고 "응"으로도 고를 수 없습니다. 직접
고르면 **답하기** 버튼이 채워진 기본 버튼 대신 위험 색으로 바뀝니다. 답한 카드는
"계속 실행 · 질문 · 클릭 · 답함"처럼 기록 행으로 접힙니다. 제어, 맡긴 일, 게시, 실행 중인
작업에 전할 말의 기록도 같은 행으로, 상태 아이콘, 어떤 작업에 무엇을 했는지, 어디서
했는지, 결과를 보여 주고 적용하지 않은 이유는 그 아래 줄에 표시합니다. 같은 답을 두 번 보내도 한 번만
적용되고, 이미 답한 결정에 다른 답을 보내면 거부됩니다. 다른 이유로 선택을 적용하지
못했다면 카드가 열린 채로 남습니다. 답하기 전에 작업이 바뀌면 카드에
더 이상 유효하지 않다고 표시되고, Tars가 스스로 한 번 다시 묻습니다. 결정 카드는
**확인 필요**와 Fleet 보기에도 함께 기다리며, 선택지가 여러 개인 카드는 Fleet에서 Tars를
열어 답합니다. **에이전트**의
Supervisor 작업 목록에는 Tars가 맡긴 작업이 숨겨지며, **Tars 작업 표시**를 켜면
함께 보입니다.
**생각 중**이나 **대기 중** 옆의 아이콘 버튼인 **메시지 취소**는 미완료 추론을
멈추며 이미 접수된 작업을 되돌리지 않습니다. Tars가 답하지 못한 메시지(중단된 추론
포함)는 답변 자리에 알림이 표시되고 자동으로 다시 실행되지 않습니다. **고쳐서 다시
보내기**를 누르면 그 내용이 입력창에 다시 들어가 새 메시지로 보낼 수 있습니다.

우선순위 숫자가 높은 일부터 시작하고, 같으면 오래된 일부터 시작합니다. 같은 저장소라도
별도 worktree에서 하는 독립 작업은 동시에 시작합니다. 준비도, 실행의 시작·전달할 말·일시정지·취소도
작업마다 따로 처리하므로 시작이나 Task 읽기가 오래 걸리는 작업이 있어도 다른 작업의 시작, 전달, 일시정지는 늦어지지 않습니다. **설정 → 동시에 실행할 작업 수**의
기본값은 **0**으로, 별도 한도를 두지 않습니다. 자원 사용을 제한하려면 양수를 설정하세요.
한도를 낮춰도 이미 시작한 작업을 중단하지 않습니다. **지금 시작**은 선택한 대기 작업에 한해
이 한도를 건너뜁니다. 응답을 기다리는 작업은 자리를 내어주며,
이미 시작한 실행은 제약이 풀리면 재개될 수 있습니다. 이 설정은 실행별 턴 예산과 별개입니다.
대기 카드는 관측된 실행 수와 한도, 또는 다시 시도할 데이터베이스 잠금을 표시합니다.
원인을 관측하지 못했으면 확인되지 않았다고 표시합니다. provider·계정 한도와 작업 소유권
검사는 유지합니다. 다른 실행 설정은 새로 맡기는 일에 적용하며, 진행 중인 실행의 권한을 바꾸지 않습니다.

판단이 필요한 변화가 생기면 Tars가 스스로 이어서 살펴봅니다. 작업이 막혔을 때,
실행이나 그 실행의 도우미가 단계를 멈췄을 때(바로 살펴봅니다), 완료를 확인하지 못했을 때,
기준을 충족하지 못한 채 끝났을 때, 변화 없이 한 시간 기다렸을 때(내가 멈춘 실행,
사용량 한도로 멈춘 실행, 작업에서 내가 답할 승인이나 질문), Tars가 한 질문이 더는
유효하지 않을 때입니다. 이 메시지는
**자동 후속 ·** 뒤에 이유와 작업 제목을 보여 줍니다. 에이전트가 내 입력이나 권한을
받으려고 멈춘 단계와 내 승인을 기다리는 단계는 **결정 필요**로 표시되고, Tars는
에이전트의 질문과 제안한 다음 행동을 함께 받습니다. Stave의 자체 확인에서 멈춘
단계(충족하지 못했거나 확인되지 않은 기준, 보고 없음, 실패한 단계 동작)나 환경 문제로
막힌 단계는 **확인 또는 다음 단계 필요**로 표시되고, Tars는 나에게 질문했다고 말하지
않고 무엇을 확인하거나 다음에 무엇을 할지 알려 줍니다. 질문, **확인**을 기다리는 재개나
취소 제안, 대기 작업의 우선순위 변경, 보기 열기만 할 수 있습니다. 새 작업을 스스로
시작하지 않고 대신 묻습니다. 일시 정지, 인수, 완료로 처리하는 일은 하지 않으며, 내가
멈추거나 인수했거나 끝난 작업에는 아무것도 제안하지 않습니다. 변화마다 한 번만
살펴보고, 한 시간에 최대 여섯 번까지 시작하며, 마지막으로 메시지를 보내거나 답하거나
클릭한 뒤부터 한 번에 턴 한도의 한 턴으로 셉니다. 한도를 다 쓰면 그렇게 알리고
기다립니다. 맡긴 일 카드에는 대기 중인 작업의 **다음 확인**처럼 Tars가
다음에 살펴볼 때가 표시됩니다.

Stave 실행 중 작업을 계속하고 재시작 후 저장된 실행과 연결해 복구합니다. 앱이
종료되거나 컴퓨터가 절전 중이면 실행하지 않으며, 내가 일시 정지한 일은 그대로
멈춰 있습니다. 게시와 외부 전달은 별도 요청이 필요하고, 위임 시 게시 동작 단계를
허용하지 않습니다. 기존 프로바이더 안전장치는 계속 적용되며, 이 지침이 별도의
셸 샌드박스는 아닙니다. 기존 Task를 자동으로 인수하지 않습니다.

## 검토 모드에서 코멘트 보내기

1. 검토 모드에서 diff의 줄에 코멘트를 남깁니다.
2. **에이전트에 리뷰 보내기**(Cmd/Ctrl+Alt+Enter)로 코멘트를 한 번에 보냅니다.
3. 에이전트가 고치면 다시 검토하고, 충분하면 **승인**합니다.

검토 화면의 **diff 코멘트** 목록에서 코멘트를 고르면 그 줄로 이동합니다. 보내기 전 코멘트는 삭제할 수 있고, 보낸 코멘트는 그 뒤 줄이 바뀌었는지 보여 주며 **해결**할 수 있습니다. 보낸 코멘트는 해결할 때까지 다시 시작해도 남습니다.

**검토 완료로 표시**를 누르면 잠시 **실행 취소**가 있는 알림이 뜹니다. 결정을 마치면 주 버튼이 Fleet 보기에서 기다리는 다음 결과나 승인인 **다음 리뷰**로 바뀝니다. 검토 화면에서 J, K로 기다리는 다음·이전 리뷰로 옮겨 갑니다.

## AI 리뷰

AI 리뷰는 같은 워크스페이스에서 읽기 전용 하위 작업으로 한 턴 동안 돌고, 승인 · 수정 후 승인 · 변경 요청 중 하나로 판정합니다.
선반에 리뷰 진행 상황이 보이고, 끝나면 결과를 첨부하거나 보고, 다시 실행하거나, 고친 뒤 **수정 확인**을 누릅니다.

## 위임 작업

에이전트는 다른 에이전트에게 일부를 맡길 수 있습니다. 위임 작업은 부모 작업 아래에 실제 작업으로 생깁니다.
**하위 에이전트** 탭에서 진행, 기다림, 확인 필요, 완료, 실패 상태를 보고, 활동 보기, 기록 열기, 중지를 할 수 있습니다.
**확인 필요**는 질문이나 승인을 요청하고 사람의 답을 기다린다는 뜻이고, **대기 중**은 다음 턴까지 스스로 기다린다는 뜻입니다.
목록 위의 개수는 필터(**전체**, **확인 필요**, **실패**, **실행 중**, **완료**)이고, **실패한 작업 재시도(N)**로 실패한 위임 작업을 한 번의 지침으로 모두 다시 실행할 수 있습니다.
하위 에이전트 둘 이상이 각자 worktree에서 일하면 **함께 바꾼 파일**에 둘 이상이 바꾼 파일과 바꾼 에이전트가 나오고, worktree별 diff를 열 수 있습니다. 파일 단위로만 비교하고 줄은 비교하지 않습니다.
위임된 에이전트가 사람의 답을 기다리면 선반에 알려 주고, 그 작업에서 답하거나 위임 Agent에 답변을 씁니다.

호출한 메시지의 답변 위에도 **하위 작업 결과**가 나옵니다. 하위 작업마다 실행 모니터 카드가 하나씩 표시되고, 여러 개면 가로로 나란히 놓이며 창이 좁으면 다음 줄로 넘어갑니다. 실행 중인 카드는 모델·현재 작업·관측된 시간·보고된 이력을, 반환된 카드는 답변 요약을 보여줍니다. **결과 보기**로 원문 답변과 실행 내역을 한 줄 전체 폭으로 펼치고 **결과 접기**로 닫습니다. 알 수 없는 시간과 비용은 표시하지 않으며, composer의 짧은 요약은 유지됩니다. **결과 도착**은 하위 작업이 답변을 돌려줬다는 뜻이며, 부모가 검증하거나 반영했다는 뜻은 아닙니다. **작업 열기**로 하위 작업에 이동하고, 답변이나 승인을 기다리고 있으면 버튼이 해당 행동을 안내합니다. 진행 중에는 헤더에 현재 작업이 한 줄로 표시됩니다. 완료되면 간단한 완료 요약과 우측의 도구 호출 횟수가 표시되며, 펼쳐서 전체 이력을 읽을 수 있습니다. 질문은 접힌 이력 밖에 남습니다.

Screens: [하위 작업 결과](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/subagent-results.png)

## Fleet 보기

Fleet 보기는 모든 워크스페이스의 작업을 내가 할 일 순서로 모읍니다. 사이드바의 **작업 대기열** 보기도 같은 순서를 씁니다.

```pipeline "먼저 볼 순서"
! 조치 필요 | 질문, 승인, 실패, 단계 시작 확인처럼 내가 답해야 하는 일
진행 중 | AI가 일하고 있거나 실행이 기다리는 일
리뷰 대기 | 결과가 준비됐거나 PR이 있는 일
유휴 | 지금 할 일이 없는 작업
@caption 흐름이 아니라 우선순위입니다. Fleet 보기와 작업 대기열은 위에서부터 이 순서로 보여 줍니다.
```

| 레인      | 들어오는 일                                                          |
| --------- | -------------------------------------------------------------------- |
| 조치 필요 | 질문, 승인, 실패한 실행, 실행의 단계 시작 확인, 막히거나 정체된 실행 |
| 진행 중   | 턴이 돌거나 실행이 기다리는 중인 작업                                |
| 리뷰 대기 | 결과가 준비됐거나 PR이 있거나 한동안 소식이 없는 작업                |
| 유휴      | 할 일이 없는 작업                                                    |

행에서 바로 **허용**과 **거부**로 승인하고(A, D 키), 짧은 질문은 선택지를 골라 답합니다. **항상 허용**은 행을 펼친 패널에 있습니다. Tars가 맡은 작업에는 **Tars** 표시가 붙고, 펼친 패널의 **일시 정지**와 **직접 맡기**는 Tars를 거쳐 Tars 대화에 기록되며, Tars가 거부하면 그 이유를 보여 줍니다. 내 확인을 기다리는 Tars 작업은 **조치 필요**에 따로 행이 생깁니다. 내 결정을 기다리는 일은 **Tars 결정**(제안 하나는 행에서 바로 확인하고, 질문이나 완료를 확인하지 못한 일은 **Tars에서 열기**), Tars가 끝내지 못한 일은 **Tars 진행 불가**로 보이며 해결될 때까지 남습니다. **표** 보기에는 **담당** 열(Tars, 에이전트 실행, 나)이 있고, 도구 막대의 **담당** 메뉴로 트리와 표를 한 담당으로 좁힐 수 있습니다. Tars에서 **Fleet에서 보기**를 누르면 이 화면이 그 작업의 패널을 펼친 채 열리며, 그 행을 가리던 필터만 풀립니다. 그 밖에 열기, 읽음 표시, 닫기, PR 열기, 알림 미루기가 있습니다. 이 동작으로 행이 사라지면 포커스가 다음 행으로 옮겨 가고, **조치 필요** 개수는 "2개가 기다리는 중"처럼 문장으로 읽힙니다. J, K는 화살표 키처럼 행 사이를 옮겨 갑니다. 기다린 시간은 1시간이 지나면 경고 색, 하루가 지나면 실패 색으로 바뀝니다.
밴드 아래의 활동 필터와 **트리** / **카드** / **표** 전환은 각각 Tab 한 번으로 들어가 방향키로 바꿉니다. 필터나 검색으로 보드를 좁히면 툴바 아래에 칩이 나타나며, 하나씩 지우거나 **모두 지우기**로 한 번에 지웁니다.

그 아래 보드는 **트리**로 열립니다. 열린 작업마다 에이전트 카드가 상태, 모델, 사용한 도구, 지금 하는 일을 보여 주고, 위쪽 줄에는 에이전트 수, 실행 중, 확인 필요, 보고된 비용이 나옵니다. 작업 패널에서 하위 에이전트 탭을 연 작업은 카드에 함께 바꾼 파일 수도 나옵니다. 카드를 고르거나 Enter를 누르면 옆에(창이 좁으면 아래에) 하위 에이전트가 펼쳐집니다. 기다리는 하위 에이전트에는 **답변**, 실패한 하위 에이전트에는 **열기**가 있고, 둘 다 그 하위 에이전트의 작업을 엽니다. **카드**는 워크스페이스마다 카드 하나, **표**는 작업마다 한 줄로 보여 줍니다. 표의 열 머리글을 고르면 그 열로 정렬하고, 다시 고르면 반대로, 한 번 더 고르면 작업 대기열 순서로 돌아갑니다. 전에 카드를 쓰고 있었다면 업데이트 후 한 번 트리로 바뀌고, 그 뒤로 고른 보기는 유지됩니다.

인라인 HTML 페이지와 에이전트의 표시 전 검사는 최대 5,120,000자까지 지원합니다. 워크스페이스의 `.html`·`.htm` 파일은 개발 서버 없이 최대 10MiB(10,485,760바이트)까지 미리 볼 수 있습니다. 다른 텍스트 파일의 미리보기 제한은 1MiB입니다.

## 이 판에서 확인한 것과 하지 않은 것

- 라벨과 동작은 기능을 바꾼 변경마다 그 소스와 한국어·영어 문구 파일에서 확인했습니다. 0.33.1 전체를 한 번에 다시 대조하지는 않았습니다.
- 스크린샷은 합성 데이터로 개발용 화면을 찍은 것입니다. 실제 프로바이더에 로그인한 상태의 동작은 이 판에서 다시 실행해 보지 않았습니다.
- Lens 스크린샷은 브라우저 빌드에서 찍어 도구 막대만 보입니다.

## 본문 찾기와 화면 이동

대화나 입력창에 포커스를 두고 Cmd+F / Ctrl+F를 누르거나, 대화 위에 마우스를 올리면 오른쪽 위에 나타나는 검색 버튼을 누르세요. 찾기 막대는 대화 위에 떠서 표시되며 메시지를 밀어내지 않습니다. 화면 밖에 있는 메시지를 포함해 불러온 메시지 본문에서 검색하며, 사고 과정과 도구 실행은 제외합니다. 더 오래된 기록은 먼저 불러온 뒤 검색하세요. Enter와 Shift+Enter로 다음·이전 메시지로 이동합니다.

터미널에서 Cmd+F / Ctrl+F를 누르면 보관된 출력에서 검색합니다. Enter와 Shift+Enter로 결과를 이동하고 Escape로 닫습니다. 머리글에는 실행 중 상태나 완료한 명령의 종료 코드가 표시됩니다.

Fleet, Agents, Schedules, Issues, AI usage를 닫으면 이전 화면으로 돌아갑니다. F6와 Shift+F6으로 창의 영역 사이를 이동할 수 있습니다. 사이드바 보기 전환에는 글자 라벨이 표시됩니다. 저장소가 없는 Fleet에서는 저장소 열기 버튼을 제공합니다.

편집 중인 파일이 디스크에서 변경되면 편집기 배너에서 비교, 내 버전 유지, 디스크에서 다시 불러오기를 선택하세요. 저장을 다시 눌러도 디스크를 자동으로 덮어쓰지 않습니다. 채팅과 Review diff는 설정한 보기 방식을 따르고 바뀌지 않은 줄은 접습니다. 설정의 짧은 컨트롤은 행 끝에 정렬되고 오래된 변경 기록은 접혀 있습니다. Markdown 미리보기는 문단을 자연스럽게 줄바꿈하며 코드 강조와 복사를 제공합니다.
