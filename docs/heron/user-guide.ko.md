## 1. 앱 설치

```bash
brew install gh
gh auth login
gh api -H 'Accept: application/vnd.github.v3.raw+json' repos/sendbird/stave/contents/scripts/install-latest-release.sh | bash
```

설치 스크립트는 최신 릴리스의 `Stave-macOS.zip`을 받아 `~/Applications`(또는 `/Applications`)에 설치하고 앱을 엽니다.
SSO나 권한 범위 오류가 나면 `gh auth refresh -h github.com -s repo,read:org`를 실행한 뒤 다시 설치합니다.
자세한 설치 안내: https://github.com/sendbird/stave/blob/main/docs/install-guide.md

새 버전이 나오면 상단 바에 **앱 업데이트**가 보이고, **설치 후 다시 시작**으로 바로 바꿉니다.

## 2. AI CLI 설치와 로그인

Stave는 내 컴퓨터에 설치된 CLI를 내 로그인으로 실행합니다. 하나 이상 설치하고 로그인하세요.

| 프로바이더   | 로그인 명령           | 참고                                             |
| ------------ | --------------------- | ------------------------------------------------ |
| Claude Code  | `claude auth login`   | 설치: `npm install -g @anthropic-ai/claude-code` |
| Codex        | `codex login`         | 설치: `npm install -g @openai/codex`             |
| Cursor Agent | `agent login`         | 설치하고 로그인하면 설정에 탭이 나타납니다       |
| Kiro CLI     | `kiro-cli login`      | 설치하고 로그인하면 설정에 탭이 나타납니다       |
| OpenCode     | `opencode auth login` | 설치하면 설정에 탭이 나타납니다                  |

Claude와 Codex는 **설정 > 계정**에서 계정을 더 추가하거나 API 게이트웨이를 연결할 수 있습니다.

## 3. 앱에서 첫 설정

1. 첫 화면에서 **저장소 열기**를 누르고 로컬 git 저장소 폴더를 고릅니다.
2. 쓸 수 있는 프로바이더가 아직 없으면 첫 화면에 **시작하기**와 **계정 열기**가 보입니다. **설정 > 계정 > 시작하기**의 단계(프로바이더 CLI 설치, 로그인, 계정 추가, 게이트웨이 연결, 모델 고르기)를 따라갑니다. 계정 추가와 게이트웨이 연결은 선택입니다.
3. **설정 > 일반 > 언어**에서 한국어를 고를 수 있습니다.
4. **설정 > 프로바이더**에서 권한 프리셋을 확인합니다. [권한과 안전](#safety)을 먼저 읽으세요.

macOS가 데스크톱·문서·다운로드 폴더 접근을 물으면 한 번 허용합니다.

**설정 > 계정**에서 Claude 계정의 **[계정] 연결 확인**을 누르면 연결된 MCP 서버, 해당 계정에서 로그인이 필요한 서버, 연결에 실패한 서버를 볼 수 있습니다. 모델에 프롬프트를 보내지 않습니다. 연결된 서버 이름과 확인 시각은 앱을 다시 열어도 최대 12시간 동안 유지됩니다. 최근 확인 기록이 없으면 저장된 설정을 기준으로 목록을 표시합니다.

**Codex의 Claude MCP 사용**은 앱 전체에 적용되며 기본값은 꺼짐입니다. **Codex 작업에서 Claude 계정의 MCP 서버 사용**을 켜고 Claude 계정을 선택하세요. 초기 선택은 **System default**입니다. 목록에는 선택한 계정을 통해 Codex가 추가로 쓸 수 있는 서버가 표시됩니다. 계정 위임을 받은 서브에이전트는 답변을 마친 뒤에도 최대 24시간 동안 후속 요청을 받을 수 있습니다.

```diagram architecture "저장소에서 턴까지"

box task 3,1 primary | 작업 | 대화 하나 | 워크스페이스마다 여러 개

box provider 4,2 | 프로바이더와 모델 | Claude · Codex · Cursor · Kiro · OpenCode | 턴마다 고름
edge repo -> ws main : 담는다
edge ws -> task main : 담는다
edge task -> turn main : 쌓인다
edge info -> task dashed : 맥락
edge provider -> turn dashed : 실행
@caption 앱 코드의 데이터 구조를 바탕으로 관계만 나타낸 개념도입니다.
```

## 네 가지 기본 단위

| 단위         | 무엇인가                             | 알아 둘 점                                                                                                                  |
| ------------ | ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| 저장소       | 사이드바에 등록한 로컬 git 폴더      | 설정에서는 **프로젝트** 페이지가 저장소 설정을 다룹니다                                                                     |
| 워크스페이스 | 브랜치 하나에 묶인 전용 git worktree | 저장소마다 저장소 루트인 **기본** 워크스페이스가 하나 있고, 나머지는 `<저장소>/.stave/workspaces/` 아래에 만들어집니다 |
| 작업         | 워크스페이스 안의 대화 하나          | 탭을 닫아도 보관되지 않습니다. 보관은 탭 메뉴의 **보관**입니다. 작업 중간에 프로바이더를 바꿀 수 있습니다                 |
| 턴           | 요청 하나에 대한 응답 한 번          | 도구 실행, 승인 요청, 질문이 턴 안에서 일어납니다. 턴이 도는 동안 보낸 메시지는 대기열에 쌓입니다                         |

사이드바에서 기본 워크스페이스 이름과 브랜치는 `기본 · main`처럼 한 줄로 표시됩니다. 긴 브랜치는 말줄임 처리하고 브랜치가 없으면 점도 숨깁니다. 상태 아이콘에 마우스를 올리면 상태를 확인할 수 있습니다. 화면 읽기 도구는 워크스페이스 이름과 상태를 함께 읽습니다.

## 워크스페이스를 나누는 이유

기본 워크스페이스에서 바로 일해도 됩니다.
하지만 일마다 워크스페이스를 만들면 브랜치와 파일이 분리되어, 여러 AI 작업을 동시에 돌려도 서로의 변경을 덮어쓰지 않습니다.
일이 끝나 PR이 머지되면 워크스페이스를 보관하고, 필요하면 브랜치도 함께 지웁니다.

## 1. 워크스페이스 만들기

사이드바의 저장소 행에 마우스를 올리면 **새 워크스페이스**, **워크스페이스 킥오프**(반짝이 아이콘), **저장소 설정** 버튼이 보입니다.
**새 워크스페이스** 대화상자에서 **워크스페이스 브랜치 이름**과 선택 항목인 **워크스페이스 레이블**을 적고, 만드는 방법을 고릅니다.
화면 보기: [새 워크스페이스](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/new-workspace.png)

| 만드는 방법                    | 하는 일                                                                         |
| ------------------------------ | ------------------------------------------------------------------------------- |
| 브랜치에서 만들기(기본)        | 기준 브랜치를 검색해 고르고, 거기서 worktree를 만듭니다                         |
| 깨끗한 워크스페이스 만들기     | 새 브랜치로 격리된 worktree를 새로 만듭니다                                     |
| 기존 worktree 연결             | 다른 위치의 worktree를 `.stave/workspaces/`에 심볼릭 링크로 연결하고 브랜치를 유지합니다 |
| PR에서 열기 | GitHub PR URL 또는 `#123` 같은 번호로 현재 저장소의 PR을 엽니다 |

기본 브랜치 이름은 PR의 헤드 브랜치 이름을 따릅니다. PR 체크아웃은 **worktree 만들기** 단계에서 진행됩니다. 정보 패널과 PR 상태 메뉴에서 연결된 PR을 확인할 수 있습니다. 포크 PR 워크스페이스에서는 푸시를 사용할 수 없습니다. 코드를 검토한 다음 필요한 설정 명령을 직접 실행하세요.

기존 워크스페이스를 그대로 둔 채 생성 창에 현재 준비 단계가 표시됩니다. 설정이 끝나면 창이 닫히고 새 작업이 열립니다. 체크아웃이나 설정에 실패하면 생성 창에서 **로그 열기**로 상세 내용을 확인하고, 문제를 해결한 뒤 **다시 시도**를 눌러 이어갈 수 있습니다. 브랜치 이름이 이미 사용 중이면 Git이 안내한 이름으로 새로 만드세요.
화면 보기: [워크스페이스 생성 진행 상태](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/workspace-creation-progress.png)

**생성 후 명령**(예: `bun install`)을 넣으면 만들자마자 실행합니다.
macOS와 Linux에서는 설정 명령 전에 원본 체크아웃의 Git 무시 대상 `node_modules`(패키지 워크스페이스 포함)와 `.venv`를 새 작업 공간으로 복사해 재사용합니다. 루트의 `.worktreeinclude`를 두면 기본 범위 대신 gitignore 형식의 허용 규칙을 적용하며, 환경·인증 파일은 명시적으로 포함해야 합니다. 복사 제한 시간은 30초이며 실패하거나 시간을 넘으면 짧게 안내한 뒤 기본 설정을 계속합니다. 의존성 호환성은 설정 명령에서 확인합니다.

### 킥오프로 시작하기

Jira 이슈, PR, 보고서처럼 이미 있는 자료에서 시작하려면 **워크스페이스 킥오프**를 씁니다.
링크나 설명을 붙여 넣고 **원본 맥락 확인**을 누르면 Stave가 자료를 읽어 브랜치, 레이블, 정보 패널 링크, 첫 작업의 모델과 요청을 제안합니다. 모두 고친 뒤 만들 수 있습니다.
**AI 건너뛰기**는 AI 없이 링크와 텍스트만 읽어 제안합니다.
**담당자**에서 **나** 또는 저장된 에이전트를, **위치**에서 새 워크스페이스 또는 **현재 워크스페이스**를 고릅니다. 새 워크스페이스는 설정을 마친 뒤 첫 요청과 함께 열립니다. **즉시 시작**을 켜면 설정을 마친 다음 요청을 보냅니다. 끄면 컴포저에 초안으로 남습니다.
화면 보기: [워크스페이스 킥오프](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/kickoff.png)

## 2. 작업 열고 요청 보내기

1. Cmd/Ctrl+N을 누르거나 빈 워크스페이스의 **새 작업**을 누릅니다.
2. 컴포저 아래쪽 모델 버튼(**모델 선택**, Alt+P)에서 프로바이더, 모델, 추론 강도를 고릅니다. **Stave Auto**를 고르면 요청의 난이도에 맞춰 Stave가 모델을 고릅니다. Auto가 로컬 규칙을 쓸 때 “코드 리뷰 절차를 설명해줘”는 조사로, “이 diff를 리뷰해줘”는 리뷰로 분류합니다. Agent Run이 자동으로 이어지거나 실행 중인 턴에 Steer를 보낼 때도 모델 버튼에 해당 턴에 기록된 모델과 추론 강도가 표시됩니다.
3. 할 일과 완료 조건을 함께 적습니다. 예: "로그인 후 원래 페이지로 돌아가게 고치고, 리다이렉트 테스트를 추가해 통과시켜 주세요."
4. **보내기**를 누릅니다.

모델명은 별도 줄에 표시합니다. 모델 안내와 호환 조건은 줄바꿈되며, 공개된 토큰
단가가 있으면 그 옆에 표시합니다.

화면 보기: [모델 선택](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/model-picker.png)

컴포저에서 쓰는 기호는 네 가지입니다.

| 기호 | 하는 일                                  |
| ---- | ---------------------------------------- |
| `/`  | 명령(예: `/aside` 곁질문)                |
| `$`  | 스킬을 골라 이번 메시지에 붙입니다       |
| `!`  | 저장한 매크로를 실행합니다               |
| `@`  | 작업, 정보 패널 항목, 파일을 참조합니다  |

## 3. 턴이 도는 동안

```sequence "턴 하나에서 일어나는 일"
participant U 나 | 컴포저
participant S Stave | 데스크톱 앱
participant P 프로바이더 | Claude Code · Codex 등
U -> S: 요청 보내기 | 지침과 맥락을 붙여 전달
S -> P: 턴 시작
P => S: 생각 · 도구 실행 · 응답
P -> S: 승인 요청 | 권한이 필요한 도구
S -> U: 승인 행 표시
U --> S: 한 번 허용 · 항상 허용 · 거부
S --> P: 결정 전달
P => S: 이어서 실행
P --> S: 턴 끝
S --> U: 응답 · 변경 파일 · 요약
@caption 턴 흐름을 단순화한 그림입니다. 승인 단계는 권한 프리셋에 따라 나타나지 않을 수 있습니다.
```

**읽기와 입력**: 언어를 지정하지 않은 코드 블록에는 구문 색을 입히지 않습니다. 답변이 끝나면 텍스트만 담은 표는 열 머리글을 선택해 정렬할 수 있고, 10행을 넘으면 **행 필터** 입력란이 생깁니다. `$…$`, `$$` 블록, `math` 코드 블록은 수식으로 표시합니다. `json` 코드 블록은 접을 수 있는 트리와 **코드 보기**로, `ansi`, `console`, `terminal`, `output` 코드 블록은 터미널 색으로 표시합니다. 입력창은 대화의 글자 크기 설정과 작업 패널의 크기 제한을 따릅니다. 최소형 입력창의 고정폭 글자와 캐럿도 함께 커집니다.

**작업 헤더**에는 **응답 필요**, **문제**, **작업 중**, **완료 · 안 읽음**, **대기 중** 중 하나가 표시됩니다. **응답 필요** 또는 **문제**를 누르면 대기 중인 요청, 실패한 턴, 에이전트 실행 상세, 또는 Tars 결정·보고서로 이동합니다. 검토 화면에서도 같은 방법을 쓸 수 있습니다. 승인과 위임 요청은 입력창에서 열리고, 단계 승인은 해당 단계의 검토 화면에서 열립니다. PR 검사 실패, 충돌, 변경 요청은 PR 상태 버튼에서 확인하세요.

**승인**: AI가 권한이 필요한 도구를 쓰려 하면 컴포저 위에 **한 번 허용**, **항상 허용**, **거부** 버튼이 있는 행이 뜹니다. **항상 허용**은 허용을 계속 유지할 수 있으면 모든 승인 화면에 똑같이 나옵니다. 프로바이더가 직접 유지하거나, 신뢰된 승인 목록에 항목으로 남깁니다. Bash 승인을 저장하면 해당 명령과 뒤에 붙는 일반 인수에 적용됩니다. 행에는 요청이 알려 준 위험(예: **네트워크 접근**)도 나옵니다. 펼침 메뉴는 요청한 하위 에이전트를 알려 주고, **안내로 대체**와 **거부 후 안내**를 담고 있습니다. 승인을 기다리는 동안 입력하면 보내기 버튼이 **거절하고 방향 조정**으로 바뀝니다. 승인 카드 안에서는 Cmd/Ctrl+Enter로 한 번 허용하고, Esc로는 거부하지 않습니다. 아무도 답하지 않은 요청은 제한 시간이 지나면 자동으로 거부되며, 카드와 행의 펼침 메뉴에 그 시각이 나옵니다(**응답이 없으면 오후 4:24에 자동으로 거부합니다**). **항상 허용**으로 답한 카드에는 **신뢰됨: <항목> · 제거**가 붙고, **제거**를 누르면 그 항목을 다시 뺍니다.
화면 보기: [승인 요청](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/approval.png)

**진행 줄**: 턴이 도는 동안 단계 목록 위 줄에 지금 진행 중인 단계(예: **search.ts 읽는 중**)만 나옵니다. 단계가 아직 없으면 **생각 중**으로 표시되며, 경과 시간은 메시지 하단에서 확인합니다. 턴이 끝나면 그 턴의 제목으로 바뀝니다. 웹을 검색하거나 가져온 턴은 답변 아래에 **출처**와 개수가 붙고, 펼치면 페이지마다 한 번씩 보여 줍니다.

진행 중 아이콘은 5×5 격자이며, 동작 줄이기를 켜면 움직이지 않습니다. Thinking 본문은 진행 중과 완료 후 모두 굵은 글씨, 목록, 코드 등의 마크다운을 표시합니다. 도구 인수·출력과 명령어 옆의 복사 아이콘을 누르면 원문이 복사됩니다. 성공하면 체크 표시로 바뀌고, 실패하면 오류를 알려 줍니다. 완료된 명령은 종료 코드를 표시합니다. 프로바이더가 코드를 보내지 않으면 **종료 코드 알 수 없음**으로 표시됩니다. 명령 결과는 **출력 복사**로 복사합니다.

도구 결과, 생각 과정, 접힌 도구 그룹의 본문은 처음 펼칠 때 불러오며 다시 접어도 유지됩니다. 브라우저에서 본문을 검색하거나 인쇄하려면 먼저 펼쳐 주세요.

**질문**: AI가 선택지가 있는 질문을 하면 숫자 키로 고를 수 있습니다. Claude의 선택지에는 코드 조각 같은 미리보기가 붙을 수 있고, 그 선택지에 포커스나 포인터가 있는 동안 선택지 아래에 보입니다. 미리보기가 없는 항목으로 이동해도 미리보기 공간은 유지되어 질문과 선택지가 움직이지 않습니다. 열린 질문에 답변을 작성하는 동안 새 턴 이벤트가 들어와도 입력한 내용과 선택은 유지됩니다. 새 질문 요청은 별도의 답변으로 시작합니다.

**업데이트가 없는 턴**: 도구 실행, 프로바이더 재시도 또는 백그라운드 작업이 보고되면 턴을 유지합니다. 20분간 업데이트가 없으면 경고하고 60분이 지나면 중단합니다. 실행 중인 활동이 보고되지 않으면 5분 후 새 메시지로 이어갈 수 있게 안내하고 20분 후 턴을 중단합니다. 승인이나 필수 질문에 답변이 필요한 동안에는 계속 기다립니다. 작업 패널에서 이전 턴을 열면 Stave가 내린 판단과 그 이유를 확인할 수 있습니다.

**대기열**: 턴이 도는 동안 보낸 메시지는 컴포저 위 선반에 쌓입니다. 다른 작업, 워크스페이스 또는 프로젝트로 이동해도 현재 턴이 끝나면 대기 중인 다음 메시지가 원래 작업에서 전송됩니다. 워크스페이스를 새로고침해 완료된 턴과 응답을 불러온 경우에도 다음 메시지가 전송됩니다. 항목마다 **방향 조정**(지금 턴에 끼워 넣기), **보내기**, **편집**, **삭제**가 있고, **모두 지우기**로 비웁니다. 앱을 다시 시작해 복원된 대기열은 **재개**를 누를 때까지 기다립니다. 턴을 멈추려면 **중지**를 누릅니다.

**대화 기록**: 연달아 보낸 메시지(방향 조정 등)는 한 묶음으로 붙고, 마지막 메시지 아래에 안내가 한 번만 표시됩니다(**활성 턴에 방향 조정 전달됨 · 3**). 각 메시지에 마우스를 올리면 그 메시지의 복사와 시간 동작이 나타납니다. 응답의 프로바이더, 모델 또는 추론 강도가 바로 앞 응답과 다르면 그 응답 위에 바뀐 내용을 알리는 줄이 표시됩니다(**Claude Sonnet 4.6 · 보통 → Claude Opus 4.8 · 높음**).

변경 파일 카드의 **수락으로 표시**와 **거부로 표시**는 검토 결과를 기록합니다.

**턴 이전 파일로 복원**: 완료된 응답의 동작에서 **이 턴 이전으로 파일 복원**을 선택합니다. **대화 유지 및 파일 복원**은 메시지를 그대로 둡니다. **파일 복원 및 대화 되돌리기**는 대화를 되돌릴 수 있을 때만 나타납니다. 지원하지 않으면 **여기서 분기**로 그 지점부터 이어 가세요. 호스트는 사용자 턴이 시작되기 전에 추적 중인 파일, 스테이징한 파일, 추적하지 않는 파일을 저장하며 무시된 파일과 `.stave/workspaces/` 아래의 작업 트리는 제외합니다. 저장할 때 브랜치, 인덱스, 작업 파일은 바뀌지 않습니다. 변경이 없으면 이전 스냅샷을 재사용하며, 보관 개수는 작업당 기본 50개로 조정할 수 있습니다. 저장에 실패해도 턴은 그대로 실행되고, 복원 버튼 대신 **이 턴의 스냅샷이 없습니다**와 이유가 표시됩니다. 복원은 달라진 파일만 바꾸고 파일 권한을 유지하며, 방해되는 항목이 있으면 아무 파일도 바꾸기 전에 멈춥니다. 복원 직전 파일도 먼저 저장하므로 **파일 복원 취소**로 돌아올 수 있습니다. 이 작업이 실행 중이거나, 같은 작업 트리를 다른 실행 중인 작업이 쓰거나, 작업 트리의 터미널에서 명령이 실행 중이거나, 턴 이후 파일이 변경되었을 수 있으면 복원을 막고 이유를 알려 줍니다. 이 기능 이전의 Claude 대화에서는 각 사용자 메시지의 **Claude 파일 되돌리기 미리보기**를 계속 쓸 수 있습니다.

**분기 결과 돌려보내기**: 분기한 작업의 최종 답변에서 **원래 작업에 결과 전달**를 선택합니다. 원래 작업의 입력창에 답변 인용문과 분기 링크가 들어갑니다. 분기 작업도 맥락으로 첨부되어 메시지를 보낼 때 세부 내용을 읽을 수 있습니다. 초안을 검토한 뒤 직접 보내세요. 이 동작은 자동으로 메시지를 보내지 않습니다. 원래 작업과의 연결은 앱을 다시 시작해도 유지됩니다.

**사용 한도**: 프로바이더 사용 한도에 걸리면 선반에 사용 한도 행이 뜹니다. **초기화 시 재개**를 누르면 한도가 풀리는 시각에 자동으로 이어 가고, **지금 재개**는 바로 다시 시도합니다. 일시 정지 상태와 예약은 앱을 다시 시작해도 유지됩니다. 앱이 비정상 종료되어 전송 여부를 확인할 수 없으면 남은 대기열을 멈추고 사용자가 확인할 때까지 기다립니다.

**재시작 후 작업 복구**: **설정 > 일반 > 데스크톱 알림**의 **앱을 다시 시작한 뒤 중단된 작업 이어가기**에서 **물어보기**(기본값), **자동으로**, **이어가지 않기**를 선택합니다. 물어보기는 중단된 일반 작업을 한 안내에 모아 **모두 이어가기**, 작업별 **이어가기**, **닫기**를 제공합니다. 복원된 대기열은 사용자가 재개할 때까지 기다립니다. 이어가기 메시지는 이전 명령이 완료됐을 수 있으니 반복 전에 상태를 확인하고, 되돌릴 수 없는 작업(push, 배포, 삭제, 메시지 전송, 마이그레이션)은 이미 실행됐는지 먼저 확인하도록 요청합니다. 앱 종료로 끊긴 턴만 제안하며, 창을 새로 고쳐도 아직 실행 중인 턴 옆에 두 번째 턴을 시작하지 않습니다. 자동 이어가기는 작업별 5분에 3회까지이며, 이후에는 물어봅니다. 중지한 작업, 승인·입력 대기, 관리형 작업은 제외하며, 제외한 턴은 한 번만 판단하고 하루가 지난 중단은 제안하지 않습니다. 사용 한도 일시 정지와 초기화 시점 재개 예약은 재시작 후에도 유지되며, 지난 예약은 사용량을 다시 확인한 뒤 한 번 이어갑니다.

**시스템 알림에서 응답**: macOS에서는 **알림에서 응답**이 기본으로 켜져 있습니다. 승인은 **한 번 허용**·**거부**로 응답하되, 위험 표시가 있거나 배너에 다 보이지 않는(80자 초과) 요청은 **열어서 검토**·**거부**만 제공합니다. 짧은 질문은 최대 3개 선택지 버튼, 앱의 카드가 텍스트 입력을 받는 질문은 **답장**으로 응답하며, 숫자 질문은 올바른 숫자만 보냅니다. 항상 허용은 제공하지 않으며 소유권과 요청 대기 상태를 다시 확인합니다. 만료된 요청은 **이미 응답한 요청입니다**를 표시하고 중복 응답은 적용하지 않습니다. 응답을 확인하거나 전달하지 못하면 **응답하지 못했습니다. Stave에서 응답해 주세요**를 표시하고 버튼은 다시 쓸 수 있습니다. 설정을 끄면 이미 표시된 알림에서도 응답할 수 없습니다. Windows와 Linux에서는 시스템 알림에 제목과 본문이 표시되며 클릭하면 Stave가 열립니다. 이 플랫폼에서 **알림에서 응답**은 앱의 알림 벨에 적용됩니다. 여러 질문·복수 선택·후속 메시지로 답하는 질문은 전체 답을 보존하도록 앱에서 응답합니다. 운영체제 권한에 따라 알림이 제한될 수 있습니다.

화면 보기: [대기열과 사용 한도](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/queue-usage-limit.png)

**작업 패널**: 오른쪽 레일의 작업 패널은 한 화면입니다. 첫 줄은 작업 상태로 **작업 중**(지금 실행 중인 단계가 `Run command · bun test`처럼 함께 표시됨), **대기 중**(실행이 사용량 초기화, PR 검사, 정한 시각을 기다림. 누구도 할 일이 없고 언제 재개되는지 표시됨), **사용자 확인 대기 중**, **막힘**, **완료**, **중지됨** 중 하나입니다. 그 아래에 해야 할 일(질문, 승인, 단계 시작 확인이 기다릴 때만, **답변하기**나 **요청 보기**와 함께), 결과(풀 리퀘스트, 변경된 파일 수와 그 파일을 그대로 여는 **변경 검토**, **답변 보기**) 또는 멈춘 이유, 아직 남은 완료 조건이 나옵니다. 그 아래에는 탭 다섯 개가 있어 한 번에 하나씩 봅니다. **활동**(**턴** 선택기와 턴의 단계), **단계**(실행 단계), **하위 에이전트**, **백그라운드**, **산출물**입니다. 패널은 **활동** 탭으로 열리므로 실패는 따로 열지 않아도 바로 보이고, 내용을 스크롤해도 탭은 위쪽에 남습니다. 이전 턴을 고르면 상태가 그 턴을 따르고, **최신 턴으로**를 누르면 돌아옵니다. **에이전트 트리**는 가지마다 접을 수 있고 방향키로 이동합니다. 대화에서는 도구 호출의 인수와 출력에 각각 **복사**가 있고, 긴 출력은 정해진 높이 안에서 스크롤되며 아래에 줄 수가 표시됩니다.

대화에서 도구 호출을 펼치면 결과를 확인할 수 있습니다. **Read**는 파일 경로와 보고된 읽기 범위를 표시합니다. 경로를 선택하면 파일이 열리고 시작 줄이 있으면 그 줄로 이동합니다. **Grep**과 **Glob**은 경로를 알아볼 수 있는 결과를 링크로 표시하고, 처음 50개를 넘는 결과는 개수를 표시합니다. 다른 형식은 텍스트로 표시합니다. JSON 객체와 배열을 펼쳐 값을 확인하거나 **원본 출력 복사**로 기록된 JSON을 복사할 수 있습니다. Bash 출력은 화면과 복사한 텍스트에서 모두 터미널 제어 문자를 제거합니다.

화면 보기: [펼친 도구 상세](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/tool-details.png)

작업 패널 > **백그라운드**에는 이번 세션의 현재 턴 또는 가장 최근에 끝난 턴에서 Claude가 보고한 작업이 표시됩니다. 작업마다 프로바이더, 설명, 처음 감지한 시각, 경과 시간, 상태 확인 여부를 볼 수 있습니다. **최근 출력**을 펼치면 제공되는 출력의 마지막 부분을 볼 수 있습니다. 프로바이더가 해당 작업을 개별적으로 중지할 수 있을 때 **중지** 버튼이 나타납니다.

## 4. 변경 확인과 PR

1. 오른쪽 패널의 **소스 제어**에서 바뀐 파일과 기록을 봅니다.
2. 작업 탭 위의 **대화 / 검토** 전환(Cmd/Ctrl+Alt+R)으로 검토 모드를 엽니다. diff에 줄 코멘트를 남기고 **에이전트에 리뷰 보내기**로 고칠 점을 전달합니다. 자세한 내용은 [검토와 위임](#review)을 보세요.
3. 상단 바의 **PR 생성**을 누르면 PR 대화상자가 열립니다. 병합 방식과 자동 병합을 고를 수 있습니다. 워크스페이스에 커밋하지 않은 변경 사항이 있으면 커밋할 파일을 선택하세요. 선택을 해제한 파일의 스테이징 상태는 유지됩니다. GitHub CLI(`gh`) 로그인이 필요합니다.
4. PR이 생기면 상단 바에 상태 칩이 보이고, 준비 완료 표시, 브랜치 업데이트, 병합, GitHub에서 열기를 바로 할 수 있습니다. 워크스페이스 브랜치와 추적 중인 원격 브랜치의 이름이 다르면 Stave가 원격 브랜치의 PR도 확인합니다.
5. 일이 끝나면 워크스페이스 행의 ⋮ 메뉴에서 **워크스페이스 보관**을 고릅니다. **git 브랜치도 삭제**를 켜면 브랜치도 지웁니다.

**소스 제어 → 리뷰**에서 PR을 선택하세요. **대화**에서 PR 댓글을 게시하거나 리뷰 스레드에 답글을 달고, 스레드를 해결 처리하거나 해결을 취소할 수 있습니다. 스레드에는 파일 위치, 댓글 날짜, 이전 변경 사항 여부가 표시됩니다. **검사**에서 GitHub Actions 실행을 펼치면 작업과 실패한 단계를 볼 수 있습니다. 실패 로그 끝부분을 열거나 **실패한 작업 다시 실행**을 선택하세요. **새로고침**으로 최신 실행을 확인할 수 있습니다. **수정 요청 작성**을 누르면 검토 후 보낼 수 있는 Tars 초안이 열립니다. GitHub 작업에는 GitHub CLI에 로그인한 계정이 사용됩니다.

작업을 선택한 상태에서 **에이전트에 근거 첨부…**를 누르면 선택한 PR 근거를 작업에 첨부할 수 있습니다. 조사나 수정을 원하면 에이전트에게 메시지를 보내세요.

### 에이전트가 연 PR 감시와 스택 관리

**설정 → 프롬프트 → PR 완료 → PR 감시**는 기본으로 켜져 있고, 저장소
설정에서 저장소별로 따로 정할 수 있습니다. PR 만들기로 연 PR과 작업 턴 중
에이전트가 연 PR에 모두 적용됩니다. 에이전트가 연 PR은 그 턴에서 PR을 여는
명령을 실행했거나 PR 링크를 알렸고, 기본 브랜치가 아닌 이 저장소의 브랜치에서
내가 작성했으며, 턴 동안 만들어진 경우에만 감시합니다. 두 작업이 모두 그 PR을
열었을 수 있으면 어느 쪽도 감시하지 않고 두 작업에 이유를 표시합니다. 감시는
검사 실패와 병합 충돌을 대상으로 하며, 리뷰 피드백은 직접 켜야 합니다. 작업에는
감시 중인 PR이 표시됩니다. **감시 중지**는 Stave가 직접 추가한 감시에만
나타나고, 내가 예약한 감시는 **일정에서 열기**로 이동합니다. PR이 병합되거나
닫히면 감시가 끝납니다. 병합된 작업 공간은 정리 센터의 **PR 병합됨** 규칙
대상이 될 수 있습니다.

연관 브랜치의 PR을 만들 때 생성 대화상자에서 **스택 PR 만들기**를 선택하세요.
상단 PR 영역과 Fleet에서 스택 내 순서와 부모·자식 PR 링크를 볼 수 있습니다.
`develop`, `release/*`, `staging` 같은 장기 유지 브랜치(**설정 → 프롬프트 →
PR 완료 → 장기 유지 브랜치**에서 편집)는 스택의 상위 PR로 보지 않습니다.
상위 PR이 병합되면 **하위 PR 대상 변경…**에서 내 PR마다 대상 브랜치 변경과
작성자를 확인할 수 있고, 확인하기 전에는 아무것도 바꾸지 않습니다. 다른 사람의
PR은 목록에만 표시하고 바꾸지 않습니다. PR마다 결과가 따로 표시되며, 충돌은
직접 해결하고 나머지는 다시 시도할 수 있습니다. 이 동작은 강제 푸시를 하지
않습니다.

## 맥락을 주는 방법

예약 확인이나 Agent 실행 이벤트로 기본 작업이 재개될 때도 브라우저 접근의 **항상** 설정이 적용됩니다. `@web`을 다시 입력할 필요가 없습니다. 기본 Agent 실행의 요청이나 사용자 답변에 입력한 `@web`도 같은 실행이 이어지는 동안 유지되며, 이벤트 후 자동 재개와 앱 재시작에도 적용됩니다. 실행이 끝나면 이 허용도 끝나고, 다른 실행이나 하위 작업에는 상속하지 않습니다. 브라우저의 사이트별 승인과 민감 작업 확인은 계속 적용됩니다.

| 방법          | 어떻게                                                    | 알아 둘 점                                                                  |
| ------------- | --------------------------------------------------------- | --------------------------------------------------------------------------- |
| 파일·이미지   | 컴포저의 클립 버튼(**파일 첨부**). 붙여 넣거나 컴포저에 끌어다 놓기 | 끌어다 놓으면 **놓아서 첨부**가 보이고 붙여 넣기와 같은 방식으로 첨부됩니다 |
| 긴 텍스트     | 데스크톱 앱의 작업 컴포저에 5줄 이상 또는 800자 이상 붙여 넣기  컴포저에는 번호가 붙은 칩 하나가 표시되고, 원문은 메시지에 포함됩니다. Backspace를 누르면 블록 전체가 지워집니다. 워크스페이스에서는 칩 메뉴의 **파일로 첨부**로 원문을 `.txt` 파일로 저장할 수 있습니다. 첨부에서 **텍스트로 유지**를 선택하면 다시 칩으로 돌아옵니다. |
| 다른 작업     | `@`와 작업 제목 일부, 또는 사이드바에서 작업을 끌어 놓기  | **최신 응답** 또는 **최근 대화**를 고릅니다. 메시지당 최대 5개              |
| 스킬          | `$`를 입력하고 고르기                                     | 고른 스킬의 SKILL.md 전체가 함께 전달됩니다                                 |
| `@web`        | 메시지에 `@web`                                           | 프로바이더의 Chrome 연동을 씁니다. 범위는 설정 > 브라우저 > 멘션            |
| 정보 패널     | 메모, 할 일, 링크를 적어 둠                               | 프롬프트에 붙인 Jira·PR 링크는 자동으로 패널에 추가됩니다                   |
| 저장소 지침   | 설정 > 프로젝트 > 저장소 > **저장소 지침**                | 이 저장소의 모든 Claude·Codex 턴에 들어갑니다                              |
| 저장소 메모리 | 정보 > **메모리**                                         | 수집은 기본 꺼짐. 항목당 280자, 한 턴에 최대 6개. 삭제는 확인 없이 바로 되고, 뒤이어 뜨는 알림의 **실행 취소**로 되살림. 항목이 8개 이상이면 검색과 종류 칩이 나타남 |

```callout note "정보 패널이 전달되려면"
정보 패널, 작업 맥락, 최근 턴 요약은 **설정 > MCP > 로컬 MCP 서버**가 켜져 있을 때만 턴에 붙습니다. AI가 메모나 링크를 모르는 것 같으면 먼저 이 설정을 확인하세요.
```

## 흐름을 끊지 않는 기능

- **곁질문**: 컴포저에서 첨부 옆에 있는 **곁질문** 아이콘(물음표가 있는 말풍선), `/aside`, 또는 Cmd/Ctrl+K 다음 Q. 답은 읽기 전용이고 작업 대화에 추가되지 않습니다. Claude와 Codex에서만 됩니다.
- **대화 폭**: **설정 > 채팅 > 레이아웃 > 대화 폭**에서 작업과 Tars의 메시지와 입력창 폭을 **좁게**, **기본**, **넓게** 중에서 고릅니다. 대화 영역이 넓어질수록 단계적으로 넓어지며, 좁은 영역에서는 전체 폭을 씁니다. 코드 블록은 메시지 열 안에 머물고 그 안에서 가로로 스크롤되며, 열이 더 필요한 표만 열 가운데를 기준으로 열보다 넓어집니다.
- **다시 오셨네요**: 15분 넘게 자리를 비웠다 돌아오면 마지막으로 본 메시지 바로 아래에 카드가 나타나, 확인이 필요한 일, 그동안 끝난 턴, 마지막 결정을 한 줄씩 버튼과 함께 보여 줍니다. **확인**을 누르면 같은 자리에 한 줄 구분선으로 접히고, 구분선을 누르면 다시 펼쳐집니다.
- **인계**: 작업 패널에는 더 이상 인계 탭이 없습니다. 이전에 저장한 인계 기록은 남아 있고, 프로바이더가 작업을 시작하거나 돌아올 때 여전히 이 기록을 먼저 받습니다. 재개할 때 마지막으로 확인한 코드 상태와 처음 할 검사를 알려 줍니다. 중단 중 파일이 바뀌었다면 관련 검사를 다시 실행한 뒤 기존 결과를 참고합니다. 지금 요청한 내용에 남은 작업이 포함될 때만 그 작업을 진행합니다.
- **프롬프트 개선**: 컴포저의 지팡이 아이콘이 요청 문장을 다듬습니다. **설정 > 모델 > 백그라운드 AI > 프롬프트 개선 > 재작성 깊이**에서 기본값인 **명확하게**를 고르면 문장과 구조를 다듬습니다. **깊게**를 고르면 요청 범위를 유지하면서 조사 방법과 결과를 확인할 방법을 덧붙입니다. **프롬프트 개선됨** 알림에서 **실행 취소**와 **변경 보기**를 고를 수 있고, **변경 보기**는 지운 단어를 취소선으로, 추가한 단어를 밑줄로 보여 주며 **유지**와 **원래대로 되돌리기**를 둡니다. 보내기 전에 원래 언어와 작업 범위, 파일 경로와 `$skill` 토큰이 그대로인지 확인하세요.
- **컨텍스트 표시**: 컴포저에서 대화가 얼마나 찼는지와 남은 토큰을 보여 줍니다. Claude는 **구성**에 무엇이 채우는지(시스템 프롬프트, 도구, MCP 도구, 메모리 파일, 스킬, 추정한 대화)를 나열하고, 다른 프로바이더는 합계만 알려 줍니다. **컨텍스트 압축**은 대화가 길어졌을 때 줄입니다. 넓은 입력창은 사용량 / 한도 토큰 수를, 좁은 입력창은 퍼센트를 보여 줍니다. 압축 중에는 시작 시각을 알면 경과 시간을 표시하며, 복원된 비활성 메시지는 시간을 계속 세지 않습니다.
- **매크로**: 컴포저 도구 막대에서 저장한 매크로 목록을 열고 이름, `!slug`, 설명으로 검색합니다.

@page safety | 일하기 | 권한과 안전 | guide
@lead 프로바이더마다 AI가 묻지 않고 할 수 있는 범위를 모드 프리셋으로 정합니다. 새로 설치하면 모든 프로바이더가 가장 넓은 **자동** 프리셋으로 시작하니, 처음에 한 번 확인하세요.

```callout warning "기본값은 자동입니다"
새 설치에서는 Claude, Codex, Cursor, Kiro, OpenCode가 모두 **자동** 프리셋입니다. Codex는 전체 디스크 접근, 승인 없음, 네트워크 켜짐으로 시작합니다. 확인이 필요한 저장소라면 **설정 > 프로바이더 > 모드 프리셋**에서 **안내형**이나 **수동**으로 바꾸세요.
```

## 프리셋별 동작

화면 보기: [설정 > 프로바이더](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/settings-providers.png)

| 프로바이더 | 수동                                         | 안내형                                     | 자동                                                     |
| ---------- | -------------------------------------------- | ------------------------------------------ | -------------------------------------------------------- |
| Claude     | 기본 권한 모드, 샌드박스 켜짐                | 파일 편집은 자동 허용, 샌드박스 꺼짐        | Claude 분류기가 판단, 샌드박스 꺼짐                      |
| Codex      | 읽기 전용, 필요할 때 승인 요청, 네트워크 꺼짐 | 워크스페이스 쓰기, 신뢰하지 않는 명령은 승인, 네트워크 꺼짐 | 전체 디스크 접근, 승인 없음, 네트워크 켜짐, 실시간 검색 |
| Cursor     | 도구 호출마다 묻기                           | Cursor 자체 자동 검토                      | 모든 도구 호출 실행, MCP 서버 신뢰                        |
| Kiro       | 도구 호출마다 묻기                           | 없음                                       | 모두 자동 승인                                           |
| OpenCode   | 읽기까지 포함해 매번 묻기, 하위 에이전트 없음 | 없음                                       | 모든 요청 승인. OpenCode의 `deny` 규칙은 그대로 적용     |

컴포저의 프리셋 메뉴와 **설정 > 프로바이더**는 선택한 프리셋 아래에 그 프리셋에서 바로 실행하는 일과 먼저 물어보는 일을 행동별로 보여 줍니다(파일 읽기, 파일 편집, 명령 실행, 웹 도구, MCP 도구 등). Claude는 켜 둔 가드레일(G1–G3)도 함께 보여 주며, 이 항목은 에이전트 모드에서 프리셋과 상관없이 항상 먼저 물어봅니다. 다른 프로바이더에는 이런 고정 항목이 없습니다.

세부 항목을 바꾸면 프리셋 표시가 **사용자 지정**으로 바뀝니다. 컴포저의 런타임 칩은 현재 상태를 **안전**, **사용자 지정**, **확장됨**으로 보여 줍니다.

## 저장소마다 다르게 쓰기

설정 맨 위의 적용 대상 선택기(처음에는 **모든 프로젝트**)에서 저장소를 고르면 모델, 추론 강도, 권한을 그 저장소에만 따로 정할 수 있습니다. 원래 값으로 돌리려면 항목의 전역 값 사용을 누릅니다.

## 에이전트 실행의 안전장치

작업이 에이전트로 실행될 때는 저장소 밖에 쓰기, 자격 증명 경로 접근, 되돌릴 수 없는 원격 작업을 막는 안전장치(G1~G3)가 기본으로 켜집니다. Claude는 훅으로 셋 모두를 막고, Codex는 샌드박스로 저장소 밖 쓰기(G1)만 막습니다.

## 시크릿

API 키 같은 값은 채팅에 붙여 넣지 마세요. 에이전트가 값을 요청하면 컴포저 위에 가려진 입력 카드가 뜹니다. **저장 및 연결**로 저장하거나 **저장된 시크릿 사용**으로 고릅니다. 값은 운영체제의 자격 증명 저장소에 저장되고, AI에게는 변수 이름만 전달됩니다. 직접 관리하려면 **설정 > 시크릿 > 시크릿 추가**를 씁니다.

@page agents | 맡기기 | 에이전트와 실행 | concept
@lead 에이전트는 지침, 모델, 권한, 단계를 저장해 둔 작업자입니다. 작업에 에이전트를 지정하면 실행(Run)이 시작되고, Stave가 단계와 완료 조건을 확인하며 끝까지 이어 갑니다.

```diagram architecture "에이전트, 작업, 실행의 관계"
box agent 1,1 primary | 에이전트 | 저장된 정의 | 지침 · 모델 · 권한 · 단계
box task 2,1 | 작업 | 에이전트가 지정된 대화 | 한 번에 실행 하나
box run 3,1 primary | 실행 | 단계를 차례로 진행 | 완료 조건 · 팀 한도
box stage 4,1 | 단계 | AI 단계 또는 Stave 동작 | 초안 PR · 검사 감시 · 스크립트
box sub 3,2 | 위임 작업 | 하위 에이전트 | 리뷰어 등
box fleet 4,2 | Fleet 보기 | 내 조치가 필요할 때 | 답변 · 승인 · 확인
edge agent -> task main : 지정
edge task -> run main : 시작
edge run -> stage main : 차례로
edge run -> sub dashed : 위임
edge run -> fleet dashed : 사람이 필요함
@caption 앱 코드의 에이전트 모델을 바탕으로 한 개념도입니다. 에이전트 자체는 아무것도 시작하지 않고, 지정될 때 실행이 생깁니다.
```

## 에이전트 만들기

사이드바의 **에이전트**(Cmd/Ctrl+K 다음 G)를 엽니다. 탭은 **에이전트**, **내 기준**, **성과**입니다.
**새 에이전트**를 누르고 **에이전트 초안 작성**으로 설명에서 초안을 만든 뒤 고칩니다.
에이전트는 출처에 따라 내장, 사용자 지정, 저장소(`.claude/agents/` 같은 파일)로 나뉩니다.
상세 화면에서 **지정…**, **복제**, **보관**을 할 수 있습니다.
화면 보기: [에이전트](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/agents.png)

**실행 방식** 섹션의 주요 설정:

| 설정          | 선택지                                         | 뜻                                                        |
| ------------- | ---------------------------------------------- | --------------------------------------------------------- |
| 권한          | 자동 등                                        | 자동이 아니면 실행이 승인 카드마다 멈춥니다               |
| 확인 시점     | 정체될 때만(기본), 게시 전, 매 단계            | 단계 사이에서 내 확인을 받을 시점                         |
| 완료 전 리뷰  | 동작이 바뀔 때(기본), 항상, 끔                 | 켜면 작업 → 리뷰 → 리뷰 지적 수정 단계가 붙습니다         |

## 실행의 단계

```pipeline "완료 전 리뷰가 켜진 실행"
작업 | 지시와 완료 조건대로 일합니다.
리뷰 | 다른 에이전트가 읽기 전용으로 변경을 검토합니다.
수정 | 리뷰에서 나온 문제를 고칩니다. 파일을 바꾸면 한 번 더 리뷰합니다. 첫 독립 리뷰가 확인되면 수정분만 보고, 확인할 수 없으면 원래 작업도 검토합니다.
! 완료 확인 | Stave가 워크스페이스 검사 명령을 직접 실행해 통과를 확인합니다.
@caption 파일을 바꾸지 않은 작업은 리뷰 단계 없이 끝납니다.
```

Implementer, Lead, Supervisor, Debugger, UI Polisher는 각자 하나의 작업 단계를 맡습니다.
Debugger는 그 안에서 문제를 재현하고 원인을 찾아 수정한 뒤 확인합니다.
UI Polisher는 수정 전 Lens에서 문제 화면을 캡처하고 수정한 뒤 같은 페이지와 작업 단계에서 다시 캡처합니다. 보고서에는 두 이미지, 비교 조건, 의도한 화면 차이를 기록합니다.
Lead와 Supervisor는 작업을 위임할 때 하위 에이전트에게 어떤 문제를 풀어야 하는지, 어떤 자료부터 봐야 하는지, 결과는 어떻게 확인할지 전달합니다. Reviewer는 변경된 값을 실제로 읽는 호출 경로를 확인합니다. Researcher는 설계 이유를 물으면 당시 커밋이나 논의에서 근거를 찾습니다.
AI 계획 단계에서는 테스트, 명령 출력, 렌더링된 화면, 실제 실행 등으로 확인할 수 있는 완료 조건을 작성합니다.
단계 보고에서는 해당 리비전에서 성공한 검사와 마지막 독립 리뷰 결과를 구분합니다. 두 번째 리뷰에서도 변경을 요청하면 마지막 수정 후 자동 리뷰가 끝납니다.

Lead와 Supervisor는 하위 작업의 결과를 완료 조건별로 확인합니다. 웹만 확인했다면 데스크톱은 미확인으로 남깁니다. 같은 조건이 같은 이유로 두 번 다시 열리면 Supervisor는 재시도 한도 안에서 앞선 두 수정이 공통으로 전제한 내용을 먼저 검증합니다.

코드 흐름을 물으면 Researcher는 정상 경로와 실패 경로를 그림으로 설명하고 **산출물**에서 소스와 테스트를 찾을 수 있게 합니다. 실행 상태에 문제가 있으면 Debugger는 상태도에 실패 지점을 표시하고 로그와 회귀 검사 위치를 남깁니다. 첨부한 CPU 프로파일은 확인 가능한 함수와 소스 위치에 연결합니다. 반복되는 오류는 Implementer나 Debugger에게 요청해 기존 결함에서 실패하고 정상 변경에서 통과하는 검사로 막을 수 있는지 확인하세요. 성능 비교에서는 전후의 성공 건수, 오류 수, 측정값의 변동 폭을 함께 봅니다.

두 UI 시안을 비교하려면 UI Polisher에게 같은 예시 데이터로 조작 가능한 미리보기를 만들고, 두 시안에서 같은 과제를 시도해 달라고 요청하세요. 예를 들어 대기 중인 결정을 찾는 과제라면 각각 어디에서 찾았는지와 추천 이유를 확인합니다.

기본값에서는 파일이 바뀌면 독립 리뷰를 받고, 지적이 있으면 수정 단계로 이어집니다.
요청의 완료 조건은 실행 마지막에 확인합니다. 단계가 추가한 조건을 다음 단계로 넘길 수 있는 경우는 다음 단계도 AI 단계일 때뿐입니다. Stave 동작 바로 앞 단계는 자신이 추가한 조건을 충족해야 합니다. 각 단계는 결과를 보고하고 그 단계에 설정된 요건을 충족합니다.

작업 대화 끝의 결과 카드에서 처음 작업한 내용과 리뷰 후 수정 사항, 최종 리뷰 결과,
마지막 리비전에서 Stave가 확인한 검사를 볼 수 있습니다.

사용자 에이전트에는 단계를 직접 정할 수 있습니다. 단계는 AI 단계(지시와 완료 조건)이거나 Stave 동작입니다. Stave 동작은 초안 PR 열기(Open draft PR), 검사 감시(Watch checks), 리뷰 준비 전환(Ready for review), 스크립트 실행(Run script)입니다.

에이전트 실행은 Claude 또는 Codex에서 시작합니다. 다른 프로바이더를 선택하면 초안을 유지하고 모델을 바꾸거나 채팅을 선택하라고 안내합니다. 긴 요청도 원문 전체를 실행에 보내고, 실행 기록의 작업 지시에는 처음 8,000자까지 저장합니다.

## 실행 상태

```diagram architecture "실행 배지 사이의 이동"
box running 1,2 primary | 실행 중 | 일하거나 기다리는 중 | 기다리는 동안 턴을 쓰지 않음
box answer 2,1 | 답변 필요 | 질문 · 승인 · 단계 시작 확인 | 답하면 다시 실행 중
box paused 2,2 | 일시정지 | 내가 멈춤 · 직접 조작 | 재개하면 다시 실행 중
box halted 2,3 | 멈춤 | 막힘 · 한도 · 대기 만료 | 실행 줄 버튼으로 이어 감
box done 3,1 | 완료 | 완료 조건 충족 | 산출물에 보고서
box stopped 3,3 | 중지됨 | 취소 · 이유 카드 | 다시 시도 · 직접 제어
edge running -> answer : 사람이 필요함
edge running -> paused dashed : 일시 중지
edge running -> halted : 진행할 수 없음
edge running -> done main : 완료 확인 통과
edge halted -> stopped dashed : 중지
@caption 앱 코드의 실행 상태와 배지를 단순화한 그림입니다. 답변 필요, 일시정지, 멈춤에서는 답하거나 재개하면 실행 중으로 돌아갑니다.
```

| 배지      | 뜻                                                                                 | 할 일                                     |
| --------- | ---------------------------------------------------------------------------------- | ----------------------------------------- |
| 실행 중   | 일하는 중. PR 검사, 사용량 한도처럼 기다리는 이유가 붙기도 합니다. 기다리는 동안 턴을 쓰지 않습니다 | 기다립니다                                |
| 답변 필요 | 질문이나 승인 카드가 열렸거나, 다음 단계 시작 확인을 기다립니다                    | 카드에 답합니다                           |
| 일시정지  | 내가 멈췄거나 직접 조작 중입니다                                                   | 작업 패널 > 단계의 **재개**               |
| 멈춤      | 막힘, 복구 필요, 대기 만료, 사용량 한도, 한도 도달(이전 버전)                      | 아래 실행 줄 버튼으로 이어 갑니다         |
| 완료      | 완료 조건을 채웠습니다                                                             | 산출물에서 실행 보고서를 봅니다           |
| 중지됨    | 취소되었거나 이유 카드와 함께 끝났습니다                                           | **다시 시도** 또는 **직접 제어**          |

실행 시간은 **활성 시간**입니다. 일시 중지, 답변이나 단계 시작 확인을 기다린 시간, Stave가 꺼져 있던 시간은 세지 않습니다. 작업 패널 > **단계**의 각 단계에는 그 단계의 턴이 쓴 사용량이 나옵니다. Claude는 비용, Codex는 토큰입니다.

진행에 꼭 필요한 조건이 충족되지 않으면 에이전트가 차단을 보고합니다. 실행 환경이나 외부 서비스 문제로 멈춰야 할 때는 실패한 작업이나 사용할 수 없었던 서비스 등 구체적인 근거를 함께 보고해야 합니다. 단계 카드에서 에이전트가 보고한 근거를 볼 수 있으며, Tars도 다음에 무엇을 확인할지 판단할 때 이 내용을 참고합니다.

컴포저 위 실행 줄에는 상황에 맞는 버튼이 뜹니다: **다시 시도**, **재개**, **지금 재개**, **이어서 진행**, **중지**, **직접 제어**(실행을 끝내고 같은 모델의 일반 대화로 이어 감). **Tars** 표시가 붙은, Tars가 맡은 실행에서는 **중지**(여기, 입력창, Esc)가 실행을 취소하지 않고 Tars에서 작업을 일시 정지하며, **직접 제어**는 실행을 끝내지 않고 일시 정지한 채로 넘겨받는 Tars의 직접 맡기입니다.
작업 패널 위쪽에는 실행 상태와 아직 남은 **완료 조건**이 나오고, **단계** 탭에는 **이 실행이 하는 일**, **완료 조건**, **팀 한도**, 단계 카드(**단계 다시 시도**, **단계 건너뛰기**)가 있습니다.
완료 조건은 **충족됨 · Stave 확인**, **충족됨 · 에이전트 보고**, **미충족**, **검증 안 됨** 중 하나로 표시됩니다.
화면 보기: [작업 패널의 실행](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/agent-run-panel.png) · [단계 시작 확인 카드](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/run-sign-off.png)

## 목표를 맡기고 자리 비우기

1. 에이전트의 **실행 방식**에서 권한을 **자동**으로 둡니다.
2. **설정 > 프로젝트 > 워크스페이스 도구**에 검사 명령(예: `bun run typecheck && bun test`)을 추가합니다. 파일을 바꾼 실행은 Stave가 이 명령을 직접 돌려 통과해야 끝납니다.
3. 파일 변경을 검토받으려면 **완료 전 리뷰**를 기본값인 **동작이 바뀔 때**로 두세요. 사용자 워크플로에서 단계를 직접 정할 수도 있습니다.
4. **설정 > MCP > 로컬 MCP 서버**를 켜고, PR 단계를 쓰려면 `gh auth login`을 해 둡니다.
5. 에이전트 상세에서 **지정…**을 누르고, 원하는 결과와 그것을 증명할 방법을 적고, **위치**를 고른 뒤 지정합니다. 컴포저에서 에이전트를 골라 보내도 됩니다.
6. 자리를 비웁니다. 실행은 안전한 승인, PR 검사와 리뷰 대기, 사용량 초기화 대기를 스스로 처리합니다.
7. Fleet 보기의 **조치 필요**나 알림이 실행을 가리키면 돌아와 카드에 답하거나 실행 줄 버튼으로 이어 갑니다.
8. 끝나면 산출물의 실행 보고서에서 PR 설명에 추가하거나 Slack에 공유합니다.

## Tars에 일을 계속 맡기기

PR 메뉴의 **Tars에서 CI 실패 원인 요약**을 선택하거나 Tars에 GitHub PR 링크를 붙여 넣고 보내세요. 답변에서 확인한 커밋과 실패한 검사를 보고, 검사 링크를 열어 근거를 확인할 수 있습니다. 로그 접근 권한이 없거나 조회 중 커밋이 바뀌면 다음에 할 일을 알려줍니다. CI를 조회하는 동안 브랜치와 검사 상태는 그대로 유지됩니다. 실패한 검사가 있으면 답변 아래 **수정 요청 작성**을 선택해 같은 PR의 후속 요청을 작성하고, 내용을 확인한 뒤 보내세요.

Tars가 시작한 Task의 헤더에서 **Tars에 맡긴 원래 요청 열기**를 선택하면 요청 원문과 같은 요청에서 시작한 다른 작업을 찾을 수 있습니다. 결정이 필요하면 제안의 전체 내용을 열어 확인하세요. Task가 생기기 전에 요청이 거절됐다면 **활동**에서 사유를 확인하고 원문을 펼쳐 다시 작성할 수 있습니다. 수정 검증이 끝나고 초안 PR 생성만 실패한 경우에는 **게시 다시 시도**로 해당 단계부터 이어갑니다.

화면: [Task에서 원래 요청 열기](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/tars-task-request.png)

Tars가 맡은 작업의 **Needs you**나 하위 작업의 Run block은 먼저 Tars가 판단합니다. **균형 있게**·**맡겨 두기**에서는 기존 지시나 프로젝트 근거로 답할 수 있는 일반 질문에 Tars가 답하고, 막히거나 정체된 하위 작업에는 같은 Run에서 처리할 복구 지시를 돌려보낼 수 있습니다. 하위 작업의 권한·계정·모델 제약은 유지합니다. 보고나 단계가 바뀌면 이전 지시는 적용하지 않습니다. **신중하게**에서는 확인을 받습니다. 도구 승인·명시적인 단계 승인·인증 정보·새 권한·사용자만 정할 수 있는 선택은 계속 사용자에게 요청하며, 기존 지시로 판단할 수 없을 때도 질문합니다. 일시 정지·직접 맡기·취소한 작업을 이 경로로 다시 시작하지 않습니다.

Tars가 맡긴 Task에서 사용자가 직접 이어 말해도(예: "구현해서 PR 올려") 작업은 끝나지 않고 Task를 따라갑니다. 몇 초 안에 작업이 사용자가 시작한 실행을 따라가고, 그 실행은 사용자의 권한을 그대로 유지하며, 작업의 상태·보고서·결과물(그 실행이 연 PR 포함)도 그 실행을 따라갑니다. 이미 끝난 작업에서도 같습니다. Tars는 그 Task, 그 작업의 워크스페이스와 저장소에 있는 실행만 따라갑니다. Tars는 사용자의 실행을 지켜보기만 하고 그 안에서 직접 행동하지 않습니다. 그 실행의 질문에 답하거나, 실행을 제어하거나, 대기 중인 후속 지시를 보내거나, 결과를 게시하는 일을 스스로 하지 않습니다. 해야 할 일이 있으면 카드로 묻고, 사용자가 확인해야만 적용됩니다. 사용자가 새 실행을 시작하기 전에 승인된 제어는 아무 효과 없이 거절됩니다. 사용자의 실행이 목표가 요구한 결과를 만들면(PR 목표라면 작업의 저장소에서 작업 브랜치의 커밋을 담아 기준 브랜치로 열린 PR) Tars의 검증 없이 사용자가 마친 작업으로 기록하고, 그렇지 않으면 작업은 열린 채로 남습니다. **일시 정지**, **직접 맡기**(Task에서는 **직접 제어**), **취소**는 이전과 같이 동작하며, Task의 에이전트를 해제하거나 바꿔도 Tars가 빠집니다.


자동 실행은 새 작업을 배정하기 전에 저장된 Claude·Codex 계정의 사용량을 확인합니다. 현재 계정의 여유가 부족하거나 소진됐거나 사용량을 모르면, 여유가 확인된 프로바이더를 우선합니다. 사용량을 모르는 계정을 여유 있는 계정으로 취급하지 않습니다. 명시적으로 고정한 모델과 에이전트의 프로바이더 제약은 유지합니다. 시작한 실행은 프로바이더와 계정을 유지하고, 사용량 정보가 없거나 오래되면 다음 턴 전에 다시 확인합니다.

한 담당자가 같은 Task에서 구현·디버그·검증을 이어서 처리합니다. 독립된 일은 병렬로 진행할 수 있지만, 한 작업의 구현·디버그·검증을 따로 인계하지 않습니다. 파일을 변경하면 Work 뒤에 독립 리뷰 한 번을 거치고, 결함이 있을 때만 수정 단계를 엽니다. Tars가 관리하는 Task와 하위 Task의 일반 완료·내부 실행 알림은 팝업과 소리 없이 읽은 기록으로 남습니다. 최종 결과·결정·진행 불가는 Tars가 알립니다. 직접 답해야 하는 승인·질문·단계 확인 요청은 계속 알리며, 작업을 직접 맡으면 일반 알림으로 돌아갑니다.


**이슈**에서 GitHub·Jira·Crane 이슈의 **Tars에게 요청**을 누르면 제목, 링크, 본문 일부와 연결된 저장소·워크스페이스 제안이 초안에 들어갑니다. `gh auth login` 후 **설정 > 연동 > 이슈**에서 GitHub를 켜세요. 할당된 이슈를 최대 200개까지 읽으며 원본을 변경하지 않습니다. 이슈 시작 폼에서 GitHub 저장소 연결을 기억할 수 있습니다.

Markdown 편집기의 **더 보기 > Tars에게 요청**은 현재 문서 내용을 첨부합니다. `.stave/context/plans/*.md`도 지원하며 텍스트 첨부는 합계 32 KB까지입니다. 문서를 링크로 전달하려면 메시지에 링크를 붙여 넣으면 됩니다. 기존 초안과 첨부는 유지됩니다. 요청을 검토하고 직접 전송해야 작업을 시작합니다. Tars는 상태를 완료, 안 되는 일, 내 확인 필요, 다음 단계로 나누어 최대 네 줄로 답하며 빈 항목은 생략합니다. 결과에는 한 줄 요약을 보여 줍니다. 전체 요약을 열면 원문, 완료 조건, 근거와 진단을 확인할 수 있습니다. 긴 기록은 마우스를 올리면 전체 내용을 볼 수 있습니다.

Tars는 작업에 관해 답하기 전에 보고서, 변경 내용, 최근 실행 대화, 기록된 검사 결과와 풀 리퀘스트 상태를 읽을 수 있습니다. 읽는 동안 상태 줄에 대상이 표시됩니다. 메시지마다 최대 두 번 더 자료를 확인하며, 큰 결과는 일부만 읽고 확인할 수 없는 근거는 미확인으로 남깁니다. 사용자에게 보기를 여는 동작과 Tars가 자료를 읽는 동작은 별개입니다. 답변이 저장되기 전에 Stave가 닫히면 메시지를 중단됨으로 표시하고 자동으로 다시 실행하지 않습니다.

이전에 한 작업을 확인하고 정정·보완을 요청하면 Tars는 새 워크스페이스 대신 그 작업의 **작업에 전달** 카드를 제안합니다. 카드에 적힌 말을 확인하면 같은 실행 작업으로 순서대로 전달합니다. 완료된 작업은 같은 작업·워크스페이스에서 새 검토·검증 실행을 시작하며, 브랜치·코드·대화·산출물과 이전 실행 보고서를 보존합니다. 독립적인 요청은 새 작업으로 맡기고, 어느 작업인지 모호하면 짧게 되묻습니다. 일시 정지·취소·직접 맡은 작업은 후속 요청만으로 재개하지 않습니다. 실행 위치를 다시 쓸 수 없으면 대체 워크스페이스를 만들지 않고 이유를 표시합니다. 후속 지시는 기존 텍스트 메시지 길이 제한을 따르며, 새 첨부가 필요하면 실행 작업에서 직접 추가하세요.

대기 중인 메시지 기록의 **요청 철회**는 그 요청만 철회하며, 이전 완료 작업과 다른 요청은 보존합니다. Stave가 실행 시작 여부를 확인하지 못하면 철회 확인 상태를 유지하며, 앱을 다시 시작해도 그 요청의 새 실행을 막습니다. 이미 시작한 실행은 취소하지 않습니다. 해당 작업을 열어 기존 제어를 사용하세요.

헤더의 **Tars 사용 안내**에서 **일 맡기기 → 진행 확인하기 → 결과 보기** 세 단계를 확인합니다. 커밋·푸시 확인과 Stave 실행 조건은 항상 표시하며, **작업 실행에 대해 더 보기**을 펼치면 나머지 조건을 볼 수 있습니다. 예시를 누르면 입력창만 채우고 보내지는 않습니다. 아이콘 버튼에 마우스를 올리거나 키보드로 포커스하면 기능 설명이 나옵니다.

맡긴 일과 결과 보고서는 실행 종료와 요청한 완료 목표를 따로 보여 줍니다. PR 생성이 목표이면 자율 실행 정책에 따라 해당 실행의 PR이 기록될 때까지 **결과 준비됨**으로 남습니다. 기존 PR은 대상 브랜치와 작업 브랜치, 커밋이 게시 내용과 모두 맞을 때만 다시 사용합니다. 게시에 실패해도 목표는 닫히지 않습니다. PR 링크만으로 CI나 머지를 확인했다고 표시하지 않으며, 여기서는 머지 완료를 관측하지 않습니다. 완료 범위가 불명확하면 목표를 닫기 전에 확인해 주세요. 완료 범위가 저장되지 않은 기존 작업도 이력을 보존하고 결과 준비됨으로 표시하여 검증이나 명시적 확인을 기다립니다. 추가 수정은 Tars에게 같은 작업을 대상으로 요청하고 신중하게에서는 메시지 카드도 확인합니다. 완료되었거나 결과가 준비된 실행은 기존 Task·워크스페이스·브랜치에서 새 실행으로 이어집니다. 원래 목표와 이전 보고서·산출물·PR 링크는 남으며, 과거 보고서는 해당 실행의 결과를 엽니다. 새 실행은 다시 검증하며 게시는 자율 실행 정책을 따릅니다. 재시작해도 후속 요청은 유지되며, 일시 정지·취소·직접 맡은 작업은 메시지만으로 다시 시작하지 않습니다.

**보내기** 옆의 **파일 첨부**로 파일을 고르거나 입력창에 끌어 놓거나 붙여 넣습니다. 워크스페이스 밖의 텍스트 파일과 PNG·JPEG·GIF·WebP 이미지도 첨부할 수 있습니다. 최대 8개까지, 텍스트는 합계 32KB, 이미지는 개당 4MB·합계 6MB로 첨부합니다. 이름이 같은 파일도 각각 보존하며, 이름에 번호를 붙여 구분합니다. 보내기 전에는 이미지를 작은 미리보기로, 텍스트 파일을 칩으로 보여 주며, 각각의 제거 버튼으로 뺄 수 있습니다. 지원하지 않는 형식이거나 크기를 넘으면 오류를 표시하고 초안을 유지합니다. 선택 당시 내용을 메시지에 저장해 대화 모델에 전달하며, 재시작 후에도 대화에서 첨부를 볼 수 있습니다. 보낸 메시지에도 이미지는 같은 미리보기로, 텍스트 파일은 이름·형식·크기가 보이는 칩으로 표시합니다. 이미지를 누르거나 이미지에서 Enter·Space를 누르면 크게 열립니다. 같은 메시지의 다른 이미지는 화살표 키나 보기 화면의 버튼으로 넘겨 보고, Esc나 닫기 버튼으로 닫으면 처음 연 이미지로 돌아옵니다. 미리보기는 화면에 보일 때 그 이미지 하나만 읽으며, 읽지 못한 이미지는 칩으로 표시합니다. 그 밖의 내용은 대화를 새로 고칠 때마다 다시 읽지 않고 Tars가 그 메시지를 판단할 때와 그 메시지로 맡긴 작업이 시작될 때만 읽습니다. 파일만 보내 대화할 수 있지만, 작업을 맡기려면 Tars에게 시킬 일을 글로 함께 적어야 합니다.

확인을 받습니다. 적용 기록에는 **되돌리기**가 표시됩니다. 이후 정보 패널이
수정되었거나 워크스페이스의 저장소 등록이 변경되면 새 내용을 보호하기 위해
복원을 거부합니다. 같은 요청을 재시도해도 중복 적용하지 않으며 자동 후속
확인은 정보를 수정할 수 없습니다. 필드·워크스페이스 생성과 정보 조회는 이
액션에 포함되지 않습니다.

**Tars가 스스로 하는 범위**는 세 단계 중 하나를 고르는 설정입니다.
**동작별 실행·확인 기준**을 펼치면 고른 단계에서 알아서 하는 일, 먼저 묻는 일,
항상 묻는 일, 하지 않는 일을 볼 수 있습니다. **신중하게**는 새 작업 시작,
순서 변경, 작업 이어가기 전에 확인을 기다립니다. **균형 있게**(기본값)와
**맡겨 두기**는 자동 후속 확인에서도 작업 재개, 단계 재시도, Tars 실행에
지시 보내기와 변경 요청을 바로 적용합니다. 실행에는 늘릴 턴 한도가 없으며,
이전 버전의 턴 한도에서 멈춘 실행은 내가 확인해야 재개합니다. 각 동작은 기록으로
남습니다. 재개·재시도의 **되돌리기**는 같은 실행을 일시정지합니다. 이미
보낸 지시나 사용한 턴은 되돌릴 수 없습니다.
저장소 파일을 바꾸는 작업은 다른 종착점을 지정하거나 게시하지 말라고 하지 않는 한
초안 PR까지가 목표입니다. 목표가 PR 생성이나 병합이면 균형 있게·맡겨 두기에서
**초안 PR**을 자동으로 엽니다. Stave가 돌린 검사도, 독립 리뷰 통과도 없는 결과라면
초안 PR은 그대로 열되 설명에 **Not verified by Stave**라고 적습니다. PR의 CI와 리뷰로
판단하시면 됩니다. 그 밖의 게시는 "PR 올릴까요?"라고 묻고,
신중하게에서는 항상 확인을 기다립니다. 실행 브랜치와 변경 여부를 다시
검사하며 기본 브랜치 푸시, 강제 푸시, 병합, 배포는 하지 않습니다. 취소,
단계 건너뛰기, 완료 수락, 도구 승인, 사용자가 가져간 권한 돌려주기, 사인오프,
사용자 대신 질문에 답하기, 지우기는 어느 단계에서나 확인이 필요합니다.
일시정지·가져오기·도구 거절은 항상 바로 적용합니다. 자동 후속 확인은 새 일을
시작하거나 사용자가 멈추거나 가져간 일을 되찾지 않습니다.
허용 가능한 확인 카드에서 **항상 허용**을 누르면 동작을 실행하고 해당
저장소의 허용 규칙을 저장합니다(최대 24개). 균형 있게와 맡겨 두기에서는
직접 요청과 자동 후속 확인 모두에서 같은 동작을 확인 없이 실행하며,
게시 가능한 초안 PR도 포함됩니다. 신중하게, 항상 확인이 필요한 동작,
해당하는 하지 말 것 규칙은 계속 확인을 받습니다. 기록의 **되돌리기**와
설정의 **삭제**는 규칙만 지우며 이미 실행한 동작은 되돌리지 않습니다.

**하지 말 것**에는 "production 브랜치는 건드리지 않기"처럼 직접 쓴
규칙을 둡니다. Tars는 이 규칙을 넘지 말아야 할 한계로 전달받고, 제안한 동작이
규칙에 적힌 저장소·브랜치·동작과 겹치면 Stave가 먼저 묻고 카드에 그 규칙을
보여 줍니다. 규칙은 Tars의 판단을 이끄는 것이며, Stave가 규칙만으로 동작을
막지는 않습니다. 저장한 변경은 Tars의 다음 결정부터 적용됩니다.

Tars 헤더의 **활동**(Tars 안에서 Ctrl/Command+Shift+A)은 보관된 실행 기록과
작업의 변화를 날짜별·최신순으로 보여 줍니다. **전체**, **Tars가 한 일**,
**내 확인 필요**로 골라 볼 수 있으며 시간, 작업, 일어난 일과 출처가 표시됩니다.
안전하게 복원할 수 있는 기록에만 **되돌리기**가 나오며, 이후 작업이 바뀌었다면
복원을 거부합니다. 정리했거나 보관 기간이 지난 기록은 포함하지 않습니다.
“Fleet 보여줘”, “활동 열어줘”, “작업 화면 열어줘”처럼 말해 Tars가 맡은 작업이나
등록된 워크스페이스도 열 수 있습니다. 화면 열기는 즉시 적용되고 기록되며,
권한을 부여하거나 작업을 바꾸지는 않습니다.

헤더의 **아는 것과 사용량**(책 아이콘)은 주로 읽기만 하는 화면 두 개를 엽니다.
**Tars가 아는 것**은 Tars가 메시지와 메시지 사이에 계속 가지고 있는 내용을
보여 줍니다. **모든 곳**에는 상시 지침(직접 작성했는지 Stave 기본값인지, 마지막
저장 시각)과 작업을 맡길 수 있는 에이전트가, **저장소별**에는 저장소마다 브랜치
이름 규칙과 저장소 메모리가 나옵니다. 메모리는 Tars가 직접 읽지 않으며, Tars가
그 저장소에서 시작한 작업이 턴마다 관련 있는 메모리를 최대 6개 받습니다. 각
항목의 **편집**은 원래 그 항목을 고치는 화면(**대화 설정** 또는 **설정 >
저장소**)을 열고, 메모리는 해당 행에서 편집하거나 삭제합니다. Tars가 기억하지
않는 것도 함께 알려 줍니다. Tars는 메시지마다 대화의 최근 메시지 8개만 다시
읽고, 대화 내용을 메모리로 저장하지 않습니다. **사용량**은 Tars가 시작한 작업이
쓴 양을 현지 시간 기준 **오늘**, **7일**, **30일**로 보여 줍니다. 토큰, 턴, 작업
시간을 작업별·모델별로 나누어 보여 주며, 작업 제목을 누르면 그 작업이 열립니다.
비용은 프로바이더가 보고한 경우에만 나오고 추정한 값은 없습니다. Tars 자신의
답변은 횟수만 세고 토큰은 기록되지 않으며, 보조 작업의 턴은 포함되지 않습니다.

**설정 > 프로바이더** 하단의 **오늘의 일일 한도**에서 프로바이더별 토큰 한도를
설정합니다. 비용을 보고한 프로바이더는 USD도 선택할 수 있습니다. 기본은
꺼짐입니다. **AI 사용량 > 할당량**에서 **계정 할당량** 아래의 **오늘의 일일 한도**를
펼쳐 보세요. 이 영역과 Tars 사용량에는 보조 작업을 포함해 모든 계정과
워크스페이스의 오늘 기록된 작업 사용량이 나옵니다. 완료된 턴의 현지 시작
날짜를 기준으로 세며 현지 자정에 초기화됩니다. 보고된 사용량만 세고 Tars의
대화 답변은 포함하지 않습니다. 한도에 도달하면 해당 프로바이더의 새 작업을
시작하지 않습니다. 진행 중인 턴은 마친 뒤 다음 단계 전에 일시정지하며, 동시
실행된 턴 때문에 한도를 넘을 수 있습니다. **일일 한도 변경**을 눌러 한도를
높이거나 끄거나, 내일까지 기다린 뒤 재개하세요. 일일 한도로 멈춘 실행은 앱을
다시 시작해도 멈춰 있으며 자동으로 재개되지 않습니다.

정리하려면 헤더의 **대화 정리**(지우개 아이콘)나 트레이 **끝남**·**산출물**
구역의 **정리**를 누르거나, "대화 지워줘", "done 정리해줘"처럼 말하세요. 말로
요청하면 Tars가 카드를 띄우고, **정리**(Enter)를 눌러야 적용됩니다. 정리는
화면에서 숨길 뿐 삭제하지 않습니다. 정리할 때마다 **되돌리기**(대화는
**복원**)가 있는 기록이 남고, 다시 실행한 뒤에도 유지됩니다. 대화를 정리하면 첫
화면이 다시 보이고 Tars의 최근 대화 기억이 새로 시작되지만, 답변 중인 메시지,
결정을 기다리는 항목과 확인을 기다리는 정리 카드, 작업에 전달을 기다리는 말은
계속 보이고 **끝남**과 **산출물**의 **되돌리기**도 남습니다. **끝남**과
**산출물**에서는 끝난 작업만 빠집니다. 진행 중이거나 기다리는 작업, 막힌 작업,
직접 맡은 작업, Draft PR이 아직 끝나지 않았거나 확인을 기다리는 작업은 남습니다.
숨긴 작업은 Fleet과 해당 작업에 그대로 있습니다.

**대화 정리** 창에서 **Work도 초기화**를 고르면 Work 패널(진행 중·확인
필요·끝남)도 비웁니다. 적용 전에 취소할 진행 중 작업, 숨길 끝난 작업과 산출물,
그대로 둘 작업의 개수를 보여 줍니다. Tars가 맡은 진행 중인 작업은 일반
**취소**로 멈추며 각 실행이 중지되고, 그 작업을 기다리던 Tars의 질문은 닫혀
다시 묻지 않습니다. 질문의 대상이 모두 끝났다면 초기화 중에 끝난 작업도
포함해 질문을 닫습니다. 이미 끝났거나 초기화 중에 완료된 작업을 취소한
작업으로 표시하지 않습니다. 직접 맡았거나 일시정지한 작업, 초안 PR을 게시 중인 작업은
그대로 둡니다. 취소가 거부된 작업도 남기고 기록에 "유지"로 표시합니다.
"In Progress 정리해줘"처럼 말하면 Tars는 질문 없이 정리 카드 하나를 띄우고,
**정리하고 취소**를 눌러야 적용됩니다. 기록의 **복원**은 카드만 다시 보이게
하며 취소한 작업을 다시 시작하지 않습니다. 정리할 항목이 없는 카드는
**닫기**로 마무리되어 다시 실행해도 대기로 돌아오지 않습니다. **나중에**도
선택을 저장하므로 다시 들어오거나 앱을 재시작해도 카드가 열리지 않습니다.

Tars는 요청한 일을 바로 시작하며, 나중에 실행하거나 반복하도록 맡을 수는
없습니다. 그런 일은 **일정**에서 만듭니다([자동화](#automation) 참고).

입력창이 비어 있으면 Tars에 저장된 대화 모델이 현재 작업에 대한 추천 요청을
최대 네 개 만듭니다. 도구를 사용하지 않는 별도의 읽기 전용 호출입니다.
생성 중, 생성 실패, 추천할 요청이 없는 상태를 구분해 표시합니다. 저장된 모델이
없으면 Tars 모델을 먼저 선택하고, 실패하면 **다시 시도**를 누르세요. 작업 정보,
언어, 모델 설정이 바뀌면 다시 생성하며 오래된 응답은 표시하지 않습니다.
Tars를 닫았다 열면 다시 생성할 수 있습니다. 추천 요청을 누르면 모델이 만든
요청이 입력창에 들어가고 포커스가 이동합니다. 직접 보내기 전에는 전송되지 않습니다.

대화가 비어 있거나 대화를 정리하면 첫 화면이 보입니다. 첫 화면에는 인사말,
**지금 상황**(확인이 필요한 일, 실행 중인 일, 최근 하루 동안 끝난 일의 수. 누르면
맡긴 일 목록의 해당 구역이 열립니다), **이렇게 요청해 보세요**(일 맡기기부터
정리까지 Tars가 할 수 있는 일별로 묶은 예시 요청. 누르면 입력창만
채워집니다), 그리고 등록된 저장소 이름이
있습니다. 저장소가 없으면 사이드바의 **저장소 열기**로 추가하는 방법을 안내합니다.

내장 에이전트는 Tars가 항상 쓸 수 있습니다. 저장한 에이전트는 **Tars가 쓸 수 있는
에이전트**에서 허용해야 Tars가 일을 맡길 수 있습니다. Shipper처럼 게시하는
에이전트는 쓰지 않습니다. 게시는 자율 실행 정책에 따라 Stave만 합니다. 없거나, 허용하지 않았거나,
위임 작업을 맡을 수 없거나, 지정한 실행 모델에서 실행할 수 없거나, 맡기는 작업에
허용된 권한보다 넓게 실행되는 에이전트는 거부하고 대화에 이유를 표시합니다. 이미 맡긴 작업은 선택한 계정과 실행 설정을
유지합니다. 답변은 제안이며, 조치 접수 결과와 작업 상태 변화가 대화에 따로
표시됩니다.

헤더에는 "확인 필요 1 · 진행 중 2 · 끝남 3"처럼 맡긴 일의 현황이 트레이 구역
이름과 구역 머리글의 숫자 그대로 보입니다. 실행 중이지만 내 확인이 필요한 일은
**확인 필요**에서 셉니다. 숫자는 그 구역에 있는 카드 수입니다. 내 확인을 기다리는
일이 한 작업에 여러 개 있어도 카드는 하나이고 한 번만 셉니다. 누르면
맡긴 일 트레이가 열리고, 창이 넓으면 트레이가 대화 옆에 계속 열려 있습니다.
트레이는 **확인 필요**, **진행 중**, **끝남**(접힘)으로 나뉩니다. 구역 머리글은
카드를 스크롤하는 동안 트레이 위쪽에 고정되고, 빈 구역은 0과 함께 머리글만
남기고 접힙니다. 카드는 세 줄로 읽힙니다. 제목, 지금 하는 일이나
내게 필요한 것 또는 나온 결과를 알려 주는 한 문장, 그리고 상태와 동작 하나입니다.
상태는 Task 패널과 같은 여섯 가지 중 하나입니다. **작업 중**(시작한 일이며, 실제로
실행 중인 일만 움직이는 표시를 씁니다),
**대기 중**(문제가 없고 누구도 할 일이 없는 일입니다. 시작 순서를 기다리거나,
워크스페이스를 준비 중이거나, 사용량 초기화·PR 검사·정한 시각을 기다리거나, 일시
정지했거나, 내가 직접 맡은 일이며 카드가 무엇을 기다리는지 알려 줍니다),
**사용자 확인 대기 중**, **막힘**(Tars가 끝내지 못했거나 오류로 멈춘 일), **완료**,
**중지됨**입니다. 동작은 상태에 맞는 하나만 보입니다. Tars가
제안하고 내 확인을 기다리면 **재개 확인** 같은 확인 버튼, Tars가 질문하면
**답변하기**(입력창 위에 결정 카드를 보여 줍니다), 작업 안에서 질문이나 승인이
기다리면 **작업 열기**(보조 에이전트의 작업이 요청했다면 그 작업을 엽니다), 막힌
일이나 확인할 결과에는 **보고서 열기**, 일시 정지한 일에는 **재개**, 직접 맡은
일에는 **다시 맡기기**, 시작 순서를 기다리는 일에는 **지금 시작**, 실행 중인
일에는 **작업 열기**, 완료된 일에는 **PR #12 열기** 또는 **보고서 열기**입니다.
내가 할 일이 없는 카드에는 동작이 없습니다. 사용량 초기화·PR 검사·정한 시각을
기다리는 일과, 아직 준비 중이라 작업이 만들어지지 않은 일이 그렇습니다. 병합 준비가 된 PR이나 한동안 조용한 턴은
상태를 바꾸지 않고 카드 상세에만 나옵니다.
내가 Task에서 직접 이어 한 일은 내 실행의 상태를 그대로 따르고, 누구의 실행인지
문장으로 알려 줍니다. 내 실행이 도는 동안에는 **작업 중**이며 내가 이어 했고 Tars는
지켜보기만 한다고 알려 줍니다. 내 실행이 목표에 이르면 **완료**이며 Tars가 검증하지
않았다고 알려 주고, 목표에 이르지 못하고 끝나면 **막힘**이며 동작은 **작업 열기**입니다.
카드를 펼치면 **작업 취소**를 선택할 수 있고, 담당은 나로 표시됩니다.
실행 배지에는 **Tars 관찰 중**이 표시되며 Fleet에서는 담당이 **나**입니다.
카드 제목을 선택하면(또는 제목에서 Enter나 Space를 누르면) 세 줄 아래에 상세가
펼쳐지고, 다시 선택하면 접힙니다. 나머지 정보는 모두 상세에 있습니다. 담당과
Stave가 알고 있을 때의 작업 중인 보조 에이전트, 작업의 브랜치, 실행 중일
때 선택된 모델, 지금 단계("지금: 원인, 2회 시도"처럼)와 그 단계에서 지난 시간,
단계마다 한 칸씩(완료, 진행 중, 시작 전, 멈춤) 나뉜 막대, 완료 목표, Stave가 관측한
내용("테스트 실행 중 · 방금 업데이트"처럼, 실행 중인데 5분 넘게 관측이 없으면
"7분 동안 업데이트 없음 · 진행 정보가 오래됐을 수 있습니다"를 주황색으로), 내 확인을 기다리는 내용입니다. 최근 변화와 경과 시간은 **타임라인**에서 봅니다. 실행 중인 작업이 하나면 해당 타임라인을 보는 동안 입력창의 실행 바로가기를 숨깁니다. Stave가 모르는 값은 0으로 표시하지 않고 빼 두며, 실행을 관측하지 못한
일은 "아직 진행 정보 없음"이라고 표시합니다. 작업이 멈췄거나 단계를 시작하지 못하면
카드가 그 사실을 사용 중인 언어로 알려 주고, 도구가 남긴 원래 메시지는 상세의
**기술 정보** 아래에 둡니다. 다른 제어도 상세에 있습니다. 상태에 맞는 제어(**일시
정지**, **재개** 등), **작업 열기**, **이어서 요청**, 게시할 수 있는 일의 **Draft PR
만들기**, 그리고 **직접 맡기**, **Fleet에서 보기**, **작업 취소**가 있는 더 보기
메뉴입니다. 상세 끝에는 "2/3" 같은 단계 수와, 툴팁에 이름이 나오는 **요청**·**타임라인**
아이콘 버튼이 있고, **타임라인**은 그 단계에서 실행 타임라인을 엽니다. 대기 중인
작업은 시작된 작업 뒤에 시작할 순서대로 놓입니다. 그 메뉴에는 **먼저 하기**와
**나중에 하기**가 더 있고, 상태 줄 앞의 손잡이를 드래그해 대기 카드 사이로 옮기거나
**Alt+위쪽 화살표**와 **Alt+아래쪽 화살표**로 옮길 수 있습니다. 옮길 때마다 새
우선순위가 대화에 기록 행으로 남습니다. 대화에는 **자리를 비운 사이**
카드가 있습니다. 대화 끝을 마지막으로 본 뒤
10분 이상 지나 돌아왔고 그사이 일이 있었다면, 자리를 떠난 지점에 카드 하나가
나타납니다. 결정을 기다리는 일, 진행할 수 없거나 실패한 작업, 끝난 작업, 새로 열린
Draft PR의 수와 작업 이름이 보이고, 각 항목에서 결과 보고서, 실행 기록, 결정 카드로
이동할 수 있습니다. **첫 새 항목으로 이동**을 누르면 처음 보는 항목으로 가고,
**닫기**를 누르면 카드가 사라지며 다시 시작해도 돌아오지 않습니다. 카드 아래 기록은
그대로 남습니다. 처음 읽기 전에는 확인 중이라고
표시하며, 읽기에 성공하기 전에는 "맡긴 일 없음"이라고 하지 않습니다. 트레이는
Fleet 보기가 Tars 작업으로 보여 주는 행을 그대로 세므로 두 화면의 숫자가 늘
같습니다. Tars가 일을 맡기면 그 메시지 아래에 작업 흐름이 붙습니다. 요청, Tars의
결정, 실행의 각 단계, 완료 순서이며, 작업 제목 한 줄로 접혀 있습니다. 일이 지금
어디까지 왔는지는 카드가 알려 주므로 대화에서는 되풀이하지 않습니다. 펼친 뒤
요청을 누르면 맡긴 내용을, 단계를 누르면 실행 기록에서 그 단계를, 리뷰 단계를 누르면
리뷰를, 완료를 누르면 결과 보고서를 보여 줍니다. **Fleet에서 보기**는
각 단계의 더 보기 메뉴에 있습니다.
일이 실행되는 동안 입력창 위에는 "지금 2개 실행 중" 한 줄이 보이고, Stave가 한동안
아무것도 관측하지 못한 일이 있으면 "1개 최근 업데이트 없음"이 덧붙습니다. 이 줄을
선택하면 맡긴 일 트레이가 열리고 실행 중인 일의 카드로 이동합니다(프로젝트별로 묶어 접어 둔 경우 그 묶음도 펼칩니다). Tars가 아직 답을 쓰는 중이면 답이
나올 자리에 움직이는 표시와 함께 **생각 중**이 반짝이며 표시됩니다. 답변 위에는 이름
줄이 없습니다. 날짜가 바뀌는 곳에는 얇은 구분선이 그날의 이름을 보여 주고, 메시지
시각은 메시지에 마우스를 올리거나 포커스할 때만 내 말풍선 옆에 나타납니다. 기록은
메시지 사이의 타임라인 레일에 놓이고, 이어지는 기록 중 첫 행에 시각이 보입니다.
대화 글자 크기는 채팅 글꼴 크기 설정을 따릅니다. 사이드바의 **Tars** 항목에는 실행 중인
일의 수와 움직이는 표시, 확인이 필요한 일의 주황색 개수가 보이고, 사이드바를 접으면
확인이 필요할 때는 주황색, 실행만 있을 때는 파란색 점 하나로 보입니다. 대화에는
말과 결정, 그리고 일이 완료되거나 진행 불가가 되거나 취소된 순간만 상태 태그와 같은
단어로 남습니다. 결과 카드 구간에서는 타임라인 연결선이 끊기고, 텍스트 기록끼리는
선으로 이어집니다. 완료, 진행 불가, 실패한 일은 그 자리에 다른 대화 카드와 왼쪽 외곽선을 맞춘 결과 카드를 보여 줍니다. 완료
기준은 **전체 요약·완료 기준·검증 근거** 안에서 **검사 통과**, **리뷰 확인**, **보고됨**,
**미충족**, **미확인**, **보고 없음** 배지로 짧게 표시합니다. 상세 상단은 확인된 기준 수를
집계하며, 에이전트 보고만 있으면 **2/2 충족 보고**로 표시합니다. **근거와 리뷰**를 펼치면
전체 출처와 단계별 검사, **리뷰 열기**를 볼 수 있습니다. 마지막 버전의 검사나 리뷰가 확인한
항목만 확인됨에 포함합니다. 완료 제목 위 간격을 넓혀 앞선 결과와 구분합니다. 결과 카드와 **보고서**는 짧은 최종 요약과 기록된 산출물 링크를 먼저 보여 줍니다. 상세에는 단계별 전체 요약, 기준, 출처, 버전과 근거가 보존됩니다. 요약이 없으면 없다고 표시합니다. 미충족·미검증 기준과 남은 일, 요약에 명시된 제약, Stave 검증 없이 수락한 완료는 접힌 상태에서도 보입니다. 이전 단계의 제약은 단계명과 함께 당시 기록으로 표시하며, 이후 변경되었을 수 있음을 알립니다. 현재도 미해결이라고 단정하지 않습니다. 중단·취소 이유는 요약보다 먼저 보입니다. 결과 카드는 대화 글자 크기 설정을 따르고, 보고서는 패널 글자 크기를 사용합니다. **보고서 열기**, 변경된 파일과 **변경 사항 보기**, 리뷰 결과, Draft PR도 나옵니다. 진행 불가나
실패한 일에는 이유, **기술 정보** 아래 도구가 남긴 메시지, **재개**처럼 그 상태에서 할 수
있는 조작이 함께 나옵니다. 취소는 한 줄로 남습니다. 변경은 새로 고침을 기다리지 않고
Tars가 저장하는 즉시 반영됩니다.

트레이의 네 번째 구역 **산출물**에는 작업이 만든 것이 모입니다. 실행이 끝나면
**결과 보고서**, 파일을 바꿨으면 **변경 사항**, 리뷰어가 보고했으면 **리뷰**, 그리고
보고서에 기록된 풀 리퀘스트 같은 링크(브라우저에서 열림)입니다. 항목마다 종류
아이콘이 있고, 끝의 아이콘으로 대화 옆에서 열리는지 브라우저에서 열리는지
알려 줍니다. 헤더에는
산출물이 있을 때만 "끝남 1 · 산출물 4"처럼 개수가 붙습니다. 산출물이나 작업
카드 아래쪽의 **요청** 아이콘을 누르면 대화 옆에 옆 보기가 열립니다. 넓은 창에서는 트레이 자리를 트레이와 같은 폭으로
차지하므로 대화 폭이 바뀌지 않고, 닫을 때까지 트레이는 헤더 표시로 접힙니다. 각 패널은
제목 줄에 이름이 있습니다. 트레이는 **맡긴 일**, 옆 보기는 **실행 기록**처럼 보기 종류와
그 아래 작업 제목입니다. 좁은 창에서는
대화와 입력창 사이에 화면 높이의 40%까지만 열리고 스크롤됩니다. 위쪽에서
**요청**, **보고서**, **변경 사항**, **기록**, **리뷰**를 바꿔 볼 수 있고, Esc나 닫기 버튼으로
닫으면 연 곳으로 포커스가 돌아갑니다. "보고서 보여줘"처럼 말로 요청해도 됩니다.
Tars는 보기를 열기만 하며 이 방법으로 작업을 바꿀 수 없습니다. 옆 보기를 열고
닫는 일은 대화에 기록되지 않습니다.

- **요청**: 맡긴 내용입니다. 작업이 받아들여진 순간부터 볼 수 있어서, 작업나 실행
  없이 대기열에서 기다리는 동안에도, 상태가 바뀌거나 Stave를 다시 실행한 뒤에도
  그대로 열립니다. **보낸 메시지 원문**은 작업을 시작한 메시지를 보낸 그대로,
  보낸 시각과 함께 보여 줍니다(Tars의 질문에 답으로 고른 것이면 그 질문도 함께
  보여 줍니다). **Tars가 정리한 위임 지시**는 Tars가 이 작업을 위해 쓴 지시이며,
  실행에는 보낸 메시지와 함께 전달됩니다. **첨부 N개**에는 보낸 메시지의 파일과
  이미지 중 이 작업이 받은 것의 이름이 나오며, 실행은 첫 턴에 이를 함께 받습니다.
  **완료 기준**에는 저장된 기준이
  나옵니다. 긴 내용, 줄바꿈, 코드도 빠짐없이 보여 주며 각 내용은 복사할 수
  있습니다. 이 보기가 생기기 전에 맡긴 작업은 그 작업을 시작한 메시지를 대화에서
  다시 읽어 **보낸 메시지 원문**으로 보여 주고, 실행에 전달된 지시 전체도 함께
  보여 줍니다. 그 메시지가 대화에 없거나 메시지로 시작한 작업이 아니면 **원문이
  저장되어 있지 않습니다**라고 알리고, 대신 실행에 전달된 지시 전체를 보여 줍니다.
  "queued인 것들 내가 보낸 순서대로 보여 줘"처럼 Tars에게 요청을 보낸 순서대로
  물어볼 수도 있습니다. Tars는 최근 요청 20개까지 보낸 시각, 앞부분 300자, 그
  요청으로 시작한 작업을 보고 답하며, 잘린 부분이 있으면 그렇다고 말하고 전체
  내용은 이 보기에서 보라고 안내합니다.
- **결과 보고서**: 기준마다 판정과 그 판정을 정한 출처(어느 단계의 에이전트 보고,
  또는 Stave 검사와 그 결과)를 확인한 리비전, 그것이 최종 리비전인지와 함께 보여
  줍니다. 근거는 보고한 단계 아래에 한 번만 **Stave에서 검증함**, **프로바이더
  결과**, **에이전트 보고**로 구분해 나옵니다. 실행이 끝난 시각 기준으로 고정된 내용이며,
  충족하지 못한 기준과 남은 일이 이어집니다.
- **변경 사항**: 실행 워크스페이스에서 바뀐 파일과 파일별 diff입니다. 보고서와 달리
  지금의 워크스페이스를 보여 주며, **새로 고침**으로 다시 읽습니다. diff에서 줄을
  선택하고 **이 부분 묻기**를 누르면 파일, 줄 범위, 줄 내용이 입력창에 인용됩니다.
  직접 보내기 전에는 아무것도 보내지 않습니다.
- **기록**: 먼저 **지금**(상태, 실행 중인 단계, Stave가 관측한 내용과 그 시점, 최신순
  최근 진행)이 나오고, 이어서 단계와 시도(진행 중인 단계의 시간은 계속 흐름), 실행이
  스스로 내린 결정(경로, 대기, 재시도), 인계와 제어, 접힌 명령·도구 호출입니다. 실행이
  없는 일은 아직 시작되지 않았는지, 실행이 시작되기 전에 끝났는지를 알려 줍니다.
- **리뷰**: 리뷰어의 판정과 발견 사항을 리뷰어의 말 그대로 보여 줍니다.

Stave가 확인한 완료 작업은 Draft PR로 올릴 수 있습니다. **끝남**의 카드 상세나 보고서에서
**Draft PR 만들기**를 누르거나 Tars에게 "Draft PR 올려줘"처럼 요청하세요.
균형 있게·맡겨 두기에서는 검증된 PR·병합 목표의 초안 PR을 자동으로 엽니다. 그 밖에는 확인
카드에 저장소, 기준 브랜치와 작업 브랜치, 변경된 파일 수, 커밋 메시지와 PR 제목(둘 다
고칠 수 있고 커밋 유형도 바꿀 수 있습니다), 보고서로 만든 PR 본문이 보입니다. 본문은
마크다운으로 보이며, **원문**을 누르면 실제로 보내는 텍스트 그대로 볼 수 있습니다.
**Draft PR 열기**나 Enter를 누르면 게시하고, **거절**이나 Esc를 누르면 아무것도
게시하지 않습니다. 그러면 Stave가 검증한 커밋을 작업 브랜치로 푸시한 뒤 Draft PR을 엽니다.
병합, 배포, 강제 푸시는 하지 않습니다. 카드는 "Draft PR #12
열림 · 작업 이름 · 클릭" 같은 기록 행으로 접히고, PR은 **산출물**과 보고서에 나타납니다. 단계 하나가 실패하면
**다시 시도**가 카드를 다시 열어 멈춘 단계부터 이어서 합니다.

Tars는 검증한 리비전과 일치하는 깨끗한 작업 공간만 게시합니다. 변경 사항은 커밋하고 다시 검증하세요. PR 감시는 일시 오류를 자동으로 재시도합니다. 감시가 중단되면 안내의 **계속 감시**를 선택해 자동 수정 한도는 유지하고 3시간 동안 다시 감시할 수 있습니다. 병합 목표는 PR 병합을 확인했을 때 완료되며 Tars가 직접 병합하지는 않습니다.

트레이의 진행 불가 카드는 이유와 함께 **보고서 열기**를 보여 줍니다. 확인할 내용에 진행 불가가
함께 나오면 그 줄 끝에 있습니다. 누르면 보고서의
미충족 기준으로 열리고, 그 작업에 허용되는 다음 동작이 함께 나옵니다. **재개**,
**직접 맡기**, **작업 취소**이며, Stave가 확인하지 못한 완료라면 그 결정 카드입니다.
작업 흐름에서 막히거나 멈춘 단계도 이유를 보여 주고 같은 곳을 엽니다.

작업은 독립 워크트리의 자체 브랜치에서
진행합니다. Tars가 파일을 수정하는 기본 에이전트(Implementer, Debugger, UI Polisher)를
지정하면 그 에이전트 하나가 작업 전체를 직접 합니다. 코드를 읽고, 고치고, 작업
중에는 바뀐 범위의 체크만, 마지막에 전체 체크를 한 번 돌리고, 검증한 작업을 그
브랜치에 커밋합니다. 그 밖의 작업은 Supervisor가 이끌며, 작은 일은 직접 하고 나머지는
도우미에게 맡깁니다. 다른 프로바이더의 독립 리뷰는 파일이 바뀐 경우에만, 수정
단계는 리뷰가 수정을 요청한 경우에만 진행합니다. 게시를 확인하기 전에는 아무것도
push하지 않습니다. 기준 워크스페이스의 미커밋 변경은 복사하지
않습니다. 메시지를 보낼 때 **보내기** 옆의 **작업 중인 변경 포함** 아이콘 버튼을 켜면,
Stave가 내 파일을 건드리지 않고 워크스페이스의 미커밋 변경을 스냅숏으로
저장하고(무시된 파일은 제외) 그 스냅숏에서 작업을 시작합니다. 트레이 카드에는
짧은 커밋과 함께 그렇게 표시됩니다. 이 토글은 보낼 때마다 다시 꺼집니다.
입력 중인 내용은 이 선택과 함께 초안으로 남아 Tars를 떠났다 돌아오거나 앱을
다시 실행해도 그대로 있습니다. 첨부한 파일은 Stave를 종료할 때까지 초안과 함께
남습니다. 전송된 메시지는 초안을 지우고, 전송에 실패하면 초안이 남으며 대화 끝의 알림에서
**다시 시도**할 수 있습니다. 초안을
저장하지 못하면 보내기를 멈추고 초안을 남기며, 종료할 때는 Stave를 열어 두거나 다시
저장하거나 저장하지 않고 종료할 수 있습니다. **일시 정지**, **재개**, **직접 맡기**, **다시 맡기기**, **작업 취소**로
맡긴 작업을 제어합니다. "멈춰", "내가 할게"처럼 말로 요청해도 같은 확인을 거치며,
클릭한 조작은 대화에 기록 행으로 남습니다. Tars가 맡은 작업은 Fleet 보기와
작업의 실행 줄에 **Tars** 표시가 붙습니다. Fleet 행 패널의 **일시 정지**와
**직접 맡기**, 실행 줄의 **직접 제어**, 그 작업의 모든 **중지**(입력창, Esc,
명령 팔레트, 실행 줄)도 Tars를 거칩니다. 실행은 취소되지 않고 일시 정지되며,
기록에는 "일시 정지 · Verified result · Fleet · 적용됨", "… · 작업 화면 · 적용됨"처럼 누른
곳이 함께 남습니다. Tars가 이미 일시 정지한 작업에서 **중지**는 내 턴만 멈춥니다.
입력창에서 에이전트를 바꾸려면 먼저 작업을 직접 맡으세요. 대기 중인 작업을 "바로 실행해"처럼 말로 요청하면 바로 시작합니다. 말로 요청한 재개, 다시 맡기기,
취소는 **재개**, **작업 취소**처럼 하는 일을 이름으로 단 버튼이 있는 결정 카드로 기다리며, 확인해야 적용됩니다. 실행 중인 작업에 "알아서 진행하라고 해"처럼 전해 달라고 한 말도 같습니다. 그 작업에서 턴이 진행 중이면 Stave가 말을 보관했다가 턴이 끝난 뒤 한 번 전달하며, 카드에는 **실행의 현재 턴이 끝나기를 기다리는 중입니다**, 이어서 **턴이 끝난 뒤 작업에 전달했습니다** 또는 그 전에 작업을 직접 맡았거나 취소했거나 검증되지 않은 완료를 직접 수락해 전달하지 않았다는 안내가 표시됩니다. 검증을 거쳐 자동으로 완료된 경우에는 설정한 동시 실행 한도 안에서 보관한 후속 요청을 같은 작업에서 이어갑니다. 실행 중지, 불완전한 보고서, 오래되거나 누락된 검증으로 실행을 이어갈 수 없으면 전달하지 않은 이유를 표시하고 요청 문구는 기록에 남깁니다. 같은 작업에 먼저 보관한 말이 남아 있으면 새 말은 그 뒤에 순서대로 전달하며, 직접 맡았다가 다시 맡겨도 그 전에 보관한 말은 전달하지 않습니다. Stave를 다시 실행해도 유지되고 두 번 전달되지 않으며, 권한을 주지 않습니다. 직접 맡은 일은 다시 맡기기 전까지
내 일로 남고, 다시 맡긴 일은 Tars가 완료 전에 다시 검증합니다. 실행이 기준을 모두
충족했다고 보고하는 것만으로는 완료되지 않습니다. 최종 단계에서 Stave가 현재 revision의
검사 통과를 직접 확인했거나, 같은 revision에 대한 독립 리뷰가 통과해야 Tars가 완료로 처리합니다. 그렇지 않으면
결정 카드가 **완료로 인정**, **작업 취소**, **Tars에게 새 검증 작업 요청** 중에서 고르게
합니다. 마지막 항목은 그 요청을 메시지 입력란에 써 둘 뿐 바로 실행하지 않습니다.

답변을 기다리는 결정과 게시 확인은 입력창 위에 하나씩 표시됩니다. 개수 표시와
**이전 대기 항목** / **다음 대기 항목**으로 답하지 않고도 다른 항목을 볼 수 있고,
고른 선택지와 수정한 게시 문구는 각 카드에 남습니다. 답이 처리되면 다음 항목으로
넘어가고, 실패하거나 거절되면 오류와 함께 같은 카드가 남습니다. **나중에**(Esc)는
답하지 않은 채 다음 항목으로 넘어가며, 하나뿐이면 입력창으로 돌아갑니다. 이력에는
질문과 **입력창 위에서 확인**이 남고, 처리되면 결과 기록으로 바뀝니다. 긴 카드는
그 안에서 스크롤하므로 입력창에 계속 접근할 수 있습니다.

Tars는 PR을 연 뒤 1~5분 간격으로 최대 3시간 동안 검사를 확인합니다.
Balanced 또는 Hands-off에서는 같은 작업·브랜치·PR에서 CI를 최대 두 번 자동으로
수정하며, 검증을 통과한 새 실행만 같은 PR을 갱신합니다. 이후에도 실패하면 사용자에게
묻습니다. 모든 검사가 통과하면 **리뷰 요청 상태로 전환** 또는 **초안으로 유지**를
선택합니다. 리뷰 요청 상태로 전환하려면 반드시 사용자의 선택이 필요하며 병합은
지원하지 않습니다. GitHub CLI에 접근할 수 없으면 한 번 알리고 감시를 중단합니다.

현재 게시 커밋의 미해결 코드 댓글이나 수정 요청 리뷰가 도착하면 리뷰 라운드마다 Tars가 한 번 이어서 처리합니다. 균형 있게·맡겨 두기에서는 같은 작업·브랜치·PR을 수정하고 검증 후 다시 게시하며, 신중하게에서는 먼저 확인합니다. 리뷰 자동 수정은 재시작이나 새 커밋에도 PR당 최대 2회이고, 이후에는 사용자에게 묻습니다. 승인이나 수정 요청이 없는 리뷰는 짧은 알림만 남깁니다. 기존 PR 감시 시간 안에서 읽으며 GitHub에 리뷰 답글을 게시하지 않습니다.

Tars가 내 선택이 필요할 때는 입력창 위에 결정 카드를 띄웁니다. 질문과 두 개에서 네 개의
선택지가 있고, 선택지마다 짧은 이유가 붙으며, Tars가 권하는 항목이 있으면 추천으로
표시됩니다. Tars가 이전 관찰을 인용하면 **앞서 확인한 근거**에 출처와 결과를 보여 줍니다.
Fleet과 작업 복귀 요약에서도 같은 선택지, 이유, 추천과 근거를 볼 수 있습니다. 해당
결정에 답하려면 **Tars에서 열기**를 선택하세요. 완료를 확인하지 못한 경우에도 두 화면에서 가능한 선택지를 볼 수 있습니다.

[Tars 질문](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/tars-question.png)

확인 카드(Tars가 제안한 제어, 또는 Stave가 확인하지 못한 완료)는
"이 작업의 책임을 취소할까요?"처럼 하는 일, 대상 작업, 그 효과를 한 문장으로 먼저
보여 줍니다. 승인할 도구 요청은 코드 블록으로 보이고, 저장소와 워크스페이스는
접힌 **세부 정보** 안에 있습니다. 작업 취소, 완료로 인정, 도구 요청 승인처럼 되돌릴 수
없는 동작은 **되돌릴 수 없음**을 한 번만 표시하고 버튼이 빨간색입니다. 카드 아래쪽에는
결정을 그대로 두는 **나중에**(Esc)와, **재개**, **작업 취소**,
**승인**처럼 하는 일을 이름으로 단 버튼과 키가 있습니다. 질문의 선택지는 라디오 목록으로, 선택지마다 이름과 그
아래 줄의 이유, 번호 키가 보이고, 추천 항목은 표시와 함께 처음부터 골라져 있습니다.
**답하기**는 고른 항목으로 답합니다. 기다리는 동안 카드에는 주의 색 테두리가
둘러집니다. 선택지를 클릭하거나 카드에 포커스를 두고 **1**~**4** 또는 화살표 키로
고른 뒤 **답하기**나 **Enter**를 누르세요. 메시지 입력란에서 누른 키는 그대로 글자로
입력됩니다. Tars의
마지막 답에서 기다리는 결정이 하나뿐이고 그 뒤로 아무것도 쓰지 않았다면 "1", "응",
"yes" 같은 짧은 답이 그 결정에 대한 답이 됩니다. 숫자는 그 항목을, 긍정의 답은 추천
항목을 고르고, 그 밖의 말은 평소처럼 Tars에게 보내집니다. 작업 취소와 완료로 인정은
기본값이 되지 않으므로 처음부터 골라져 있지 않고 "응"으로도 고를 수 없습니다. 직접
고르면 **답하기** 버튼이 채워진 기본 버튼 대신 위험 색으로 바뀝니다. 답한 카드는
"계속 실행 · 질문 · 클릭 · 답함"처럼 기록 행으로 접힙니다. 제어, 맡긴 일, 게시, 실행 중인
작업에 전할 말의 기록도 같은 행으로, 상태 아이콘, 어떤 작업에 무엇을 했는지, 어디서
했는지, 결과를 보여 주고 적용하지 않은 이유는 그 아래 줄에 표시합니다. 같은 답을 두 번 보내도 한 번만
적용되고, 이미 답한 결정에 다른 답을 보내면 거부됩니다. 다른 이유로 선택을 적용하지
못했다면 카드가 열린 채로 남습니다. 답하기 전에 작업이 바뀌면 카드에
더 이상 유효하지 않다고 표시되고, Tars가 스스로 한 번 다시 묻습니다. 기다리는 카드에는
모두 **닫기**도 있습니다. 선택하지 않고 카드를 완전히 닫으며, 아무것도 적용하지 않고
**확인 필요**와 Fleet에서도 그 결정을 뺍니다. 닫은 카드는 "닫음" 기록으로 접힙니다.
Stave가 확인하지 못한 완료를 묻는 카드를 닫으면 작업은 막힌 상태 그대로 트레이에 남고,
그 작업의 제어 버튼으로 이어서 처리할 수 있습니다. 질문과 제안된 제어는 새 메시지를
보내 그 작업을 다시 지목하면 더 이상 기다리지 않으며("대화가 다음으로 넘어갔습니다"), 더 이상 맞지 않는
이전 카드는 Tars가 스스로 거둬들일 수 있습니다("Tars가 거둬들임"). 결정 카드는
**확인 필요**와 Fleet 보기에도 함께 기다리며, 선택지가 여러 개인 카드는 Fleet에서 Tars를
열어 답합니다. **에이전트**의
Supervisor 작업 목록에는 Tars가 맡긴 작업이 숨겨지며, **Tars 작업 표시**를 켜면
함께 보입니다.
**생각 중**이나 **대기 중** 옆의 아이콘 버튼인 **메시지 취소**는 미완료 추론을
멈추며 이미 접수된 작업을 되돌리지 않습니다. Tars가 답하지 못한 메시지(중단된 추론
포함)는 답변 자리에 알림이 표시되고, **고쳐서 다시 보내기**를 누르면 그 내용이
입력창에 다시 들어가 새 메시지로 보낼 수 있습니다. 시간 초과(시도당 5분), 중간에 잘린
답, 모델의 일시적인 문제는 한 번만 자동으로 다시 시도하며, 그동안 메시지에 한 번 더
시도한다고 표시됩니다. 그 밖의 실패나 두 번째 실패는 다시 시도하지 않습니다.
Codex 모델 턴이 시작되기 전 일시적인 워크스페이스 라우팅 조회 실패는 짧은 간격으로
최대 두 번 더 시도합니다. 그래도 시작하지 못하면 잠시 후 다시 시도하라는 짧은 오류를
보여 줍니다. 이 복구로 이미 실행 중인 턴을 다시 실행하지는 않습니다. Tars의
답에 들어 있는 작업 하나가 형식에 맞지 않으면 그 작업만 빼고, 몇 개를 뺐는지 메시지에
표시합니다. 답과 나머지 작업은 그대로 남습니다. 대기 중인 메시지는 왜 기다리는지(이전
작업의 결과, 또는 저장된 에이전트 불러오기)를 보여 주고 최대 1분만 기다립니다. 그 뒤에는
이어서 처리하고, 저장된 에이전트를 끝내 불러오지 못하면 이유와 함께 멈추므로 다시 보내면
됩니다.

우선순위 숫자가 높은 일부터 시작하고, 같으면 오래된 일부터 시작합니다. 같은 저장소라도
별도 worktree에서 하는 독립 작업은 동시에 시작합니다. 준비도, 실행의 시작·전달할 말·일시정지·취소도
작업마다 따로 처리하므로 시작이나 작업 읽기가 오래 걸리는 작업이 있어도 다른 작업의 시작, 전달, 일시정지는 늦어지지 않습니다. **설정 → 동시에 실행할 작업 수**의
기본값은 **0**으로, 별도 한도를 두지 않습니다. 자원 사용을 제한하려면 양수를 설정하세요.
한도를 낮춰도 이미 시작한 작업을 중단하지 않습니다. **지금 시작**은 선택한 대기 작업에 한해
이 한도를 건너뜁니다. 응답을 기다리는 작업은 자리를 내어주며,
이미 시작한 실행은 제약이 풀리면 재개될 수 있습니다.
대기 카드는 관측된 실행 수와 한도, 또는 다시 시도할 데이터베이스 잠금을 표시합니다.
원인을 관측하지 못했으면 확인되지 않았다고 표시합니다. provider·계정 한도와 작업 소유권
검사는 유지합니다. 다른 실행 설정은 새로 맡기는 일에 적용하며, 진행 중인 실행의 권한을 바꾸지 않습니다.

판단이 필요한 변화가 생기면 Tars가 스스로 이어서 살펴봅니다. 작업이 막혔을 때,
실행이나 그 실행의 도우미가 단계를 멈췄을 때(바로 살펴봅니다), 완료를 확인하지 못했을 때,
기준을 충족하지 못한 채 끝났을 때, 변화 없이 한 시간 기다렸을 때(내가 멈춘 실행,
사용량 한도로 멈춘 실행, 작업에서 내가 답할 승인이나 질문), Tars가 한 질문이 더는
유효하지 않을 때입니다. 이 메시지는
**Tars 후속 확인 ·** 뒤에 이유와 작업 제목을 보여 주고, 그 아래에 Tars의 답을 묶어 Tars가
스스로 쓴 한 항목으로 보이게 합니다. 에이전트가 내 입력이나 권한을
받으려고 멈춘 단계와 내 승인을 기다리는 단계는 **답변이나 승인 필요**로 표시되고, Tars는
에이전트의 질문과 제안한 다음 행동을 함께 받습니다. Stave의 자체 확인에서 멈춘
단계(충족하지 못했거나 확인되지 않은 기준, 보고 없음, 실패한 단계 동작)나 환경 문제로
막힌 단계는 **Stave 검사에서 멈춤**으로 표시되고, Tars는 나에게 질문했다고 말하지
않고 무엇을 확인하거나 다음에 무엇을 할지 알려 줍니다. 질문, 확인을 기다리는 재개나
취소 제안, 대기 작업의 우선순위 변경, 보기 열기만 할 수 있습니다. 새 작업을 스스로
시작하지 않고 대신 묻습니다. 일시 정지, 인수, 완료로 처리하는 일은 하지 않으며, 내가
멈추거나 인수했거나 끝난 작업에는 아무것도 제안하지 않습니다. 변화마다 한 번만
살펴보고, 한 시간에 최대 여섯 번까지 시작합니다. 마지막 메시지 이후의 횟수로 멈추지 않으므로, 내 확인이 필요 없는 작업이 다음 메시지를 기다리며 서 있지 않습니다. 후속 확인 두 번 사이에 진전(새 실행 턴, 단계 시도, 보고서)이 없는데 같은 작업이 다시 물으면 Tars는 더 답하지 않고 대화에 알린 뒤, 작업이 움직이거나 내가 행동할 때까지 질문을 내게 남깁니다. 실행이 끝난 작업도 같습니다. 균형 있게와 맡겨 두기에서는 후속 확인이 그 작업을 새 실행으로 바로 이어갈 수 있는데, 이렇게 이어간 실행이 두 번 연달아 앞과 같은 결과(새 커밋이나 워크스페이스 변화 없음, 같은 결말·리뷰 판정·미충족 기준)로 끝나면 Tars는 세 번째로 이어가지 않습니다. 워크스페이스 revision처럼 Stave가 읽지 못한 부분은 변화로 보지 않고, 두 결과를 번갈아 내는 경우에도 멈추며, 내 행동 사이에 끝난 작업을 다섯 번보다 많이 이어가지 않습니다. 대화와 작업 카드에 이어서 진행해도 계속 같은 결과로 끝났거나 한도에 이르렀다고 알리고, 다음 단계(완료 수락, 게시, 취소, Tars에게 메시지)는 내가 고릅니다. 후속 확인, CI 수정·리뷰 반영 후속 확인, 내 메시지에 대한 Tars의 답 등 무엇이 제안했든 자동으로 이어간 실행은 모두 같은 횟수에 들어가고, 자동 답변 하나는 작업마다 한 번만 이어갑니다. Tars가 멈춘 뒤 그 작업에 남아 있던 메시지는 보내지 않습니다. 내가 직접 시작한 이어가기는 막지 않습니다. 내가 그 작업에 행동하면 다시 0부터 세며, 다시 실행해도 횟수는 유지됩니다. 이전 버전에서 턴 한도로 멈춘 실행은 즉시 후속 확인을 하지만, Tars는 재개를 제안만 합니다. 자율 실행 수준과 관계없이 내가 확인해야 이어집니다. 무관한 메시지는 다른 작업의 질문을 닫지 않습니다. 답변 전송이 끝나지 않으면 이유를 표시하고 1분 안에 뒤 메시지의 대기를 해제합니다. 전송 중인 답변은 중복 전송하지 않으며, 전송이 끝나면 대기열을 다시 확인합니다. 저장소 경합은 최대 지연 간격을 유지하며 자동 재시도합니다. 맡긴 일 카드의 상세에는 대기 중인 작업의 **다음 확인**처럼 Tars가
다음에 살펴볼 때가 표시됩니다.

Stave가 나 없이 이어 갈 일이 있는 동안(진행 중인 턴, 실행 중인 에이전트 실행이나
Tars 작업, 사용량 초기화나 PR 검사 같은 외부 이벤트를 기다리는 실행)에는 Mac이 유휴
상태로 잠들지 않게 합니다. 남은 일이 모두 나를 기다리면(승인, 질문, 비밀값 요청, 단계 시작
확인, 내가 풀어야 하는 일시 정지) 다시 잠들 수 있습니다. 화면은 꺼질 수 있으며, Mac의
덮개를 닫으면 여전히 잠들 수 있습니다. 혼자 진행하는 작업은 턴 수가
아니라 시간과 제공사 사용량에서 끝납니다. 실행, 위임한 보조 작업, Tars 작업은 긴 턴에도 계속되고
사용량이 초기화되면 스스로 이어갑니다. 끝내지 못한 채 보조 에이전트와 함께 200턴을 진행해 반복에
빠진 것으로 보일 때만 Stave가 멈춥니다. 리드가 변경을 통합하고 커밋한 뒤, 결과를 보고하는
같은 턴에 최종 검사를 직접 실행합니다. 워크스페이스 검사 스크립트가 있으면 Stave를
통해 실행합니다. 보조 에이전트는 푸시하거나 PR을 열면 안 됩니다.

Stave 실행 중 작업을 계속하고 재시작 후 저장된 실행과 연결해 복구합니다. 앱이
종료되거나 컴퓨터가 절전 중이면 실행하지 않으며, 내가 일시 정지한 일은 그대로
멈춰 있습니다. 게시와 외부 전달은 별도 요청이 필요하고, 위임 시 게시 동작 단계를
허용하지 않습니다. 기존 프로바이더 안전장치는 계속 적용되며, 이 지침이 별도의
셸 샌드박스는 아닙니다. 기존 작업을 자동으로 인수하지 않습니다.
실행의 완료 보고와 Stave가 직접 확인한 검사, 실제 외부 결과는 구분합니다.

새 큐 이동 기록의 **되돌리기**는 함께 재정렬된 항목까지 이전 우선순위로 복원합니다.
실행이 한 번도 시작되지 않은 큐 항목의 일시정지·가져오기 기록도 되돌릴 수 있습니다.
그사이 작업이나 큐, 등록된 작업 범위가 바뀌면 이후 변경을 덮어쓰지 않고 되돌리기를
거부합니다. 이전 값이 저장되지 않은 과거 기록, 실행 중인 작업 제어, 실행 시작,
작업에 보낸 답변, 완료 결정과 게시에는 되돌리기가 없습니다. 정리의 되돌리기는
기존대로 사용할 수 있습니다.

Tars가 결정을 기다리거나, 다음 단계를 정할 결과를 준비했거나, 작업이 막히면
알림 벨로 알려 줍니다. PR 리뷰 전환 결정과 자동 CI 수정 시도 한도에 도달한
경우도 알립니다. 같은 상황은 한 번만 알리고 더 이상 내 조치가 필요하지 않으면
자동으로 해제합니다. Tars가 스스로 적용한 동작은 알리지 않습니다. 알림을 열면
Tars의 해당 결정 카드나 작업 보고서로 이동합니다. 기존 소리·데스크톱 알림 설정을
따르며, Stave 창에 포커스가 있으면 데스크톱 알림은 울리지 않습니다.

입력창에서 **@**를 입력한 뒤 이어서 제목, 저장소 또는 ID를 입력해 기존 작업을 검색합니다.
후보는 커서의 **@** 입력 중에만 나타나며, 상시 선택창이나 별도 검색창은 없습니다.
방향키와 Enter로 선택하고 Escape를 누르거나 입력창을 벗어나면 후보가 닫힙니다.
선택하면 주변 초안은 유지되고 작업 칩에 제목·현재 상태·짧은 저장소 이름이 표시됩니다.
제목과 화살표를 누르면 결과 보고서를 엽니다. 별도의 ×(**선택 해제**)는 선택만 지우고
내용을 그대로 둔 입력창으로 포커스를 돌려줍니다. 다른 **@** 후보를 고르면 대상이 바뀝니다.
제목에 마우스를 올리거나 키보드로 포커스하면 전체 경로와 작업 ID를 확인할 수 있습니다.
같은 제목은 저장소 경로의 짧은 구분명으로, 제목과 저장소가 모두 같으면 작업 번호로 구분합니다.
선택한 작업이 없어지면 확인할 수 없다는 안내를 표시하며, 선택을 해제하거나 바꾸기 전까지 초안은 유지됩니다. 작업 카드, 결과 카드 또는 옆 보기의 **이어서 요청**은 해당 작업을
선택하고 입력창으로 이동합니다. 메시지는 자동으로 보내지 않습니다. **결과 보기**는 해당 작업의 보고서를 엽니다.
초안과 선택한 작업은 재시작 후에도 유지됩니다. 후속 메시지와 질문의 선택형 응답은 제목이나 상태가 바뀌어도
같은 작업 ID를 유지합니다.
작업을 선택한 동안 Tars는 그 작업에만 동작합니다. 새 작업, 정리와 다른 작업에 대한 동작은 거부됩니다.
독립적인 새 작업을 요청하거나 여러 작업을 함께 다루려면 먼저 선택을 해제합니다.
완료한 작업을 포함해 선택한 작업에 대한 후속 요청은 기존 확인과 소유권 검사를 거쳐 원래 작업에서 이어서 실행합니다.
이 요청이 거부되면 작업에 아무것도 전달되지 않고 대체 작업도 만들지 않습니다.
대상 선택은 도구 승인이나 게시 권한을 부여하지 않습니다. PR 요청에는 기존 완료 검사와 최종 확인 절차가 적용됩니다.

## Tars 일괄 제어와 정리

Tars에게 “모든 일 멈춰줘”, “진행 중인 일 모두 일시정지해줘”, “모두 재개해줘” 또는 “선택한 일을 취소해줘”라고 요청하세요. 저장소나 작업 목록으로 범위를 좁힐 수 있습니다. 확인 카드 한 장에는 그 동작을 적용할 수 있는 일만 나오고, 제외한 항목에는 이유가 붙습니다. 이미 끝난 일은 목록에 넣지 않고 개수만 한 줄로 보여 줍니다. 자율성 수준과 관계없이 확인해야 실행됩니다. 일시정지와 재개는 확인하는 시점의 상태를 기준으로 적용합니다. 취소는 카드가 뜬 뒤 바뀐 일을 건너뛰고, 직접 넘겨받은 일은 취소하지 않습니다. 취소는 되돌릴 수 없으며 Enter 기본 단축키가 없습니다.

“끝난 일 정리해줘”라고 말하거나 완료 영역에서 **끝난 일 정리**를 선택하세요. 이 정리는 실행 워크스페이스를 보관할 뿐 Work 카드를 없애지 않습니다(카드는 정리로 숨기세요). 워크스페이스가 없는 끝난 작업은 **보관할 워크스페이스가 없음**으로 표시하고, 보관할 항목이 하나도 없으면 비활성 버튼 대신 이유와 **닫기**만 보여 줍니다. 완료되거나 취소된 일 중 실행 중인 활동, 대기 중이거나 열린 PR, 변경 파일, 미푸시 커밋이 없는 워크스페이스만 보관하며, 끝나지 않은 일은 개수만 한 줄로 보여 줍니다. 실행 직전에 호스트가 다시 확인합니다. 풀 리퀘스트 상태를 확인할 수 없으면 모든 항목을 건너뛰고, GitHub CLI에 로그인하거나 워크스페이스 정리 화면을 사용하라는 안내를 한 줄로 보여 줍니다. 결과 기록의 **복원**으로 보관한 워크스페이스를 되돌릴 수 있으며, 브랜치가 삭제된 보관 항목은 읽기 전용으로 복원됩니다. 정리나 일괄 제어가 진행되는 중에 Stave가 멈추면, 기록에 처리된 항목이 남고 나머지를 **이어서 진행**할 수 있습니다. 브랜치 삭제와 이미 보관된 워크스페이스의 영구 삭제는 명시적으로 요청해야 하며 되돌릴 수 없습니다. 강제 삭제는 사용하지 않습니다.

## 검토 모드에서 코멘트 보내기

1. 검토 모드에서 diff의 줄에 코멘트를 남깁니다.
2. **에이전트에 리뷰 보내기**(Cmd/Ctrl+Alt+Enter)로 코멘트를 한 번에 보냅니다.
3. 에이전트가 고치면 다시 검토하고, 충분하면 **승인**합니다.

검토 화면의 **diff 코멘트** 목록에서 코멘트를 고르면 그 줄로 이동합니다. 보내기 전 코멘트는 삭제할 수 있고, 보낸 코멘트는 그 뒤 줄이 바뀌었는지 보여 주며 **해결**할 수 있습니다. 보낸 코멘트는 해결할 때까지 다시 시작해도 남습니다.

**검토 완료로 표시**를 누르면 잠시 **실행 취소**가 있는 알림이 뜹니다. 결정을 마치면 주 버튼이 Fleet 보기에서 기다리는 다음 결과나 승인인 **다음 리뷰**로 바뀝니다. 검토 화면에서 J, K로 기다리는 다음·이전 리뷰로 옮겨 갑니다.

## AI 리뷰

AI 리뷰는 같은 워크스페이스에서 읽기 전용 하위 작업으로 한 턴 동안 돌고, 승인 · 수정 후 승인 · 변경 요청 중 하나로 판정합니다.
선반에 리뷰 진행 상황이 보이고, 끝나면 결과를 첨부하거나 보고, 다시 실행하거나, 고친 뒤 **수정 확인**을 누릅니다.
에이전트는 리뷰 답변을 그 리뷰를 첨부한 메시지에서만 받습니다.

## 위임 작업

에이전트는 다른 에이전트에게 일부를 맡길 수 있습니다. 위임 작업은 부모 작업 아래에 실제 작업으로 생깁니다.
작업 패널의 **하위 에이전트** 탭에서 진행, 기다림, 확인 필요, 완료, 실패 상태를 보고, 진행 보기, 기록 열기, 중지를 할 수 있습니다.
**진행 보기**를 누르면 대화 옆 오른쪽 레일에 **에이전트** 패널이 열립니다. 어디서 시작된 에이전트인지, 상태와 사실 줄(종류, 모델, effort, 경과 시간, 단계 수), 지금 하는 일, 받은 지시, `src/main.tsx 읽는 중`처럼 문장으로 적힌 단계, 최종 답이 차례로 보입니다. 연속된 도구 호출은 한 묶음으로 접히고, 실행 중이거나 실패한 단계는 늘 보입니다. 이 에이전트가 시작한 하위 에이전트는 같은 패널에서 열리고 뒤로 돌아갈 수 있으며, 맨 아래를 보고 있을 때만 새 단계를 따라갑니다. 턴 활동의 에이전트 행, 대화의 하위 에이전트 카드에 있는 **진행 보기**, 입력창 위 리뷰의 **보기**도 같은 패널을 엽니다.

Fleet에서는 하위 에이전트 카드를 선택하세요. 작업이 연결된 비교 후보와 에이전트 실행이 연결된 Tars 작업 카드에서도 **진행 보기**를 열 수 있습니다. 단계에서 **시간축**을 선택하면 여러 작업이 동시에 진행된 구간을 볼 수 있습니다. 그래프에서 단계 이름을 누르면 해당 단계의 상세가 열립니다. 시간을 측정할 수 없는 단계는 그래프 아래에 표시됩니다. 메시지와 도구 상세, 하위 에이전트 결과는 **목록**에서 확인할 수 있습니다. [에이전트 진행 시간축](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/agent-progress-timeline.png)

**산출물**에서는 하위 에이전트에 배정된 Scratch 폴더의 파일과 결과에 인용된 Scratch 파일을 미리 볼 수 있습니다. **백그라운드**에서는 해당 에이전트의 명령과 기록된 로그를 확인할 수 있습니다. 각 탭은 표시할 항목이 있을 때 열립니다. [에이전트 산출물](https://github.com/sendbird/stave/blob/main/docs/screenshots/guide/ko/agent-progress-outputs.png)
**확인 필요**는 질문이나 승인을 요청하고 사람의 답을 기다린다는 뜻이고, **대기 중**은 다음 턴까지 스스로 기다린다는 뜻입니다.
목록 위의 개수는 필터(**전체**, **확인 필요**, **실패**, **실행 중**, **완료**)이고, **실패한 작업 재시도(N)**로 실패한 위임 작업을 한 번의 지침으로 모두 다시 실행할 수 있습니다.
하위 에이전트 둘 이상이 각자 worktree에서 일하면 **함께 바꾼 파일**에 둘 이상이 바꾼 파일과 바꾼 에이전트가 나오고, worktree별 diff를 열 수 있습니다. 파일 단위로만 비교하고 줄은 비교하지 않습니다.
위임된 에이전트가 사람의 답을 기다리면 선반에 알려 주고, 그 작업에서 답하거나 위임 Agent에 답변을 씁니다.
위임 작업의 승인이나 질문은 부모 작업의 composer 위에도 나타납니다. **계속** 또는 **응답 거절**을 눌러 위임 작업에 응답이 전달되면 질문 카드가 닫힙니다. 전달에 실패해 질문이 아직 대기 중이라면 카드에서 이유를 확인하고 다시 시도할 수 있습니다. 다른 곳에서 이미 답했거나 만료된 요청은 **닫기**(×)로 없앨 수 있습니다.

부모는 하위 작업 답변을 앱을 다시 시작한 뒤에도 한 번씩 받습니다. 답변은 자르지 않고 전달하며, 4,000자를 넘는 답변만 앞부분과 원문을 읽을 참조로 전달합니다. 이번 턴에 들어가지 못한 답변은 다음 턴에 그대로 전달합니다. 답변을 실은 부모 턴을 공급자가 받아들이면 그 턴을 중지해도 받은 것으로 봅니다. 시작하지 못한 턴에 실린 답변은 다음 턴에 전달합니다. 답변을 받았다는 기록을 남기지 못하면 다음 턴에 다시 보내고, 세 번 연속 실패하면 더 보내지 않고 작업에 한 번 알립니다. 그 답변은 **하위 에이전트** 탭에서 읽을 수 있습니다.

호출한 메시지의 답변 위에도 **하위 작업 결과**가 나옵니다. 하위 작업마다 실행 모니터 카드가 하나씩 표시되고, 여러 개면 가로로 나란히 놓이며 창이 좁으면 다음 줄로 넘어갑니다. 진행 상황은 백그라운드로 옮겨진 하위 작업을 포함해 해당 하위 작업의 카드에만 표시되고(다시 이어서 실행한 하위 작업의 카드에는 그 실행의 진행 상황만 표시됩니다), 어느 하위 작업인지 밝히지 않은 진행 상황은 하위 작업 하나만 실행 중일 때 그 카드에 표시됩니다. 실행 중인 카드는 모델·현재 작업·관측된 시간·보고된 이력을, 반환된 카드는 답변 요약을 보여줍니다. **결과 보기**로 원문 답변과 실행 내역을 한 줄 전체 폭으로 펼치고 **결과 접기**로 닫습니다. 알 수 없는 시간과 비용은 표시하지 않으며, composer의 짧은 요약은 유지됩니다. **결과 도착**은 하위 작업이 답변을 돌려줬다는 뜻이며, 부모가 검증하거나 반영했다는 뜻은 아닙니다. **작업 열기**로 하위 작업에 이동하고, 답변이나 승인을 기다리고 있으면 버튼이 해당 행동을 안내합니다. 실행 중에는 헤더에 현재 활동이 표시됩니다. 턴이 끝나면 헤더가 한 줄로 접히고 "3분 12초 동안 작업"처럼 작업한 시간과 우측의 단계 수가 표시되며, 최종 답변은 메시지 본문에서 읽을 수 있습니다. 헤더를 선택하면 모든 단계를 순서대로 볼 수 있습니다. 실행 중에는 가장 최근 중간 메시지와 실행 중인 하위 작업이 보입니다. 실패한 도구 호출은 해당 행에만 표시되고 헤더는 바뀌지 않습니다. 답변이나 승인을 기다리는 질문과 요청은 계속 보입니다. 활동과 대화 검색에서 해당 단계로 바로 이동할 수 있습니다.

## Fleet 보기

Fleet와 긴 사이드바 목록은 화면 주변의 행을 렌더링합니다. 선택과 키보드 이동은 필터에 맞는 펼친 목록 전체에 적용됩니다.


행의 체크박스, Cmd/Ctrl+클릭, Shift+클릭으로 여러 작업을 선택합니다.
행에 포커스가 있으면 **X**로 선택을 바꾸고, **Shift+방향키**로 범위를
늘리고, **Cmd/Ctrl+A**로 표시된 작업을 모두 선택하며, **Esc**로 선택을
지웁니다. 접힌 그룹은 전체 선택에서 제외하며, 대화상자나 메뉴에서는 뒤쪽
목록의 선택 단축키가 작동하지 않습니다. 선택한 개수는 스크린 리더에도
안내합니다. 선택한 작업이 있을 때만 한 줄 도구 모음이 나타납니다. 개수와
Esc 힌트가 있는 선택 해제 버튼 옆에 **중지**, **보관**이 있습니다.
**알림 미루기** 메뉴에서 1시간·4시간·1일·1주를 고릅니다. **더 보기**에는
**읽음 표시**, **검토함 표시**, 한 개 선택 시 **열기**, **영구 삭제**가
있습니다. 너비가 좁으면 주요 작업도 더 보기로 이동합니다. 적용할 항목이
없는 동작은 숨기며, 버튼과 확인창에는 실제 적용할 개수를 표시합니다.
건너뛴 작업은 이유를 알려 줍니다. 보관과 알림 미루기는 토스트의 **실행
취소**나 토스트가 남아 있는 동안 Cmd/Ctrl+Z로 되돌립니다.

**중지**는 부모 턴을 먼저 멈춘 뒤 실행 중인 하위 작업을 멈춥니다.
이미 끝난 하위 작업은 그대로 둡니다. 담당자가 관리하는 일은 담당자를 통해
일시정지하거나 건너뛰며, 거절되면 하위 작업도 직접 중지하지 않습니다.
**모두 중지**는 실행 중인 작업이 있을 때만 Fleet 머리글에 나타납니다.
중지를 열면 턴·하위 작업·실행·담당자가 관리하는 항목의 개수를 확인받습니다.
팔레트에는 저장소별 중지, **이 워크스페이스의 종료된 작업 보관**, **모두
읽음 표시**가 있습니다. 모두 읽음 표시는 되돌릴 수 없어 확인창을 엽니다.

**보관**은 실행 중인 턴·하위 작업·실행과 대기 중인 승인·질문을 제외합니다.
보관과 실행 취소는 보고 있는 워크스페이스를 바꾸지 않습니다. **영구 삭제**는
먼저 보관해야 사용할 수 있습니다. 보관 직후에는 실행 취소가 가능합니다.
실행 중인 일이나 대기 중인 요청이 없는 보관된 작업만 삭제하며 보호된 작업은
건너뜁니다. 확인창에 적용할 개수와 되돌릴 수 없다는 안내가 표시됩니다.
처음에는 취소에 포커스가 있어 Enter만 눌러서는 삭제되지 않습니다. 종료된
하위 작업의 내용은 보존하며 부모를 삭제하면 독립된 작업으로 남습니다.
하위 작업을 삭제해도 부모의 기록은 보존됩니다. **작업 기록**에서도 여러
작업을 골라 **복원 (n)**이나 **영구 삭제 (n)**를 한 번에 실행합니다.

트리와 표에서는 **상태별 묶기**를 선택해 **확인 필요**, **작업 중**,
**검토 준비됨**, **대기**, **종료됨** 순으로 볼 수 있습니다. 끝난 작업에
읽지 않은 결과나 열린 PR 상태가 있으면 검토 준비됨에 표시합니다.
묶음 머리글은 개수를 보여 주고 표시된 작업을 선택합니다. 선택한 묶기
방식은 저장되며 기본값은 기존 저장소별 묶기입니다.


Fleet 보기는 모든 워크스페이스의 작업을 내가 할 일 순서로 모읍니다. 사이드바의 **작업 대기열** 보기도 같은 순서를 씁니다.

```pipeline "먼저 볼 순서"
! 조치 필요 | 질문, 승인, 실패, 단계 시작 확인처럼 내가 답해야 하는 일
진행 중 | AI가 일하고 있거나 실행이 기다리는 일
리뷰 대기 | 결과가 준비됐거나 PR이 있는 일
유휴 | 지금 할 일이 없는 작업
@caption 흐름이 아니라 우선순위입니다. Fleet 보기와 작업 대기열은 위에서부터 이 순서로 보여 줍니다.
```

| 레인      | 들어오는 일                                                          |
| --------- | -------------------------------------------------------------------- |
| 조치 필요 | 질문, 승인, 실패한 실행, 실행의 단계 시작 확인, 막히거나 정체된 실행 |
| 진행 중   | 턴이 돌거나 실행이 기다리는 중인 작업                                |
| 리뷰 대기 | 결과가 준비됐거나 PR이 있거나 한동안 소식이 없는 작업                |
| 유휴      | 할 일이 없는 작업                                                    |

행에서 바로 **허용**과 **거부**로 승인하고(A, D 키), 짧은 질문은 선택지를 골라 답합니다. **항상 허용**은 행을 펼친 패널에 있습니다. Tars가 맡은 작업에는 **Tars** 표시가 붙고, 펼친 패널의 **일시 정지**와 **직접 맡기**는 Tars를 거쳐 Tars 대화에 기록되며, Tars가 거부하면 그 이유를 보여 줍니다. 내 확인을 기다리는 Tars 작업은 **조치 필요**에 따로 행이 생깁니다. 내 결정을 기다리는 일은 **Tars 결정**(제안 하나는 행에서 바로 확인하고, 질문이나 완료를 확인하지 못한 일은 **Tars에서 열기**), Tars가 끝내지 못한 일은 **Tars 진행 불가**로 보이며 해결될 때까지 남습니다. **표** 보기에는 **담당** 열(Tars, 에이전트 실행, 나)이 있고, 도구 막대의 **담당** 메뉴로 트리와 표를 한 담당으로 좁힐 수 있습니다. Tars에서 **Fleet에서 보기**를 누르면 이 화면이 그 작업의 패널을 펼친 채 열리며, 그 행을 가리던 필터만 풀립니다. 그 밖에 열기, 읽음 표시, 닫기, PR 열기, 알림 미루기가 있습니다. 이 동작으로 행이 사라지면 포커스가 다음 행으로 옮겨 가고, **조치 필요** 개수는 "2개가 기다리는 중"처럼 문장으로 읽힙니다. J, K는 화살표 키처럼 행 사이를 옮겨 갑니다. 기다린 시간은 1시간이 지나면 경고 색, 하루가 지나면 실패 색으로 바뀝니다.
밴드 아래의 활동 필터와 **트리** / **카드** / **표** 전환은 각각 Tab 한 번으로 들어가 방향키로 바꿉니다. 필터나 검색으로 보드를 좁히면 툴바 아래에 칩이 나타나며, 하나씩 지우거나 **모두 지우기**로 한 번에 지웁니다.

그 아래 보드는 **트리**로 열립니다. 열린 작업마다 에이전트 카드가 상태, 모델, 사용한 도구, 지금 하는 일을 보여 주고, 위쪽 줄에는 에이전트 수, 실행 중, 확인 필요, 보고된 비용이 나옵니다. 작업 패널에서 하위 에이전트를 연 작업은 카드에 함께 바꾼 파일 수도 나옵니다. 카드를 고르거나 Enter를 누르면 옆에(창이 좁으면 아래에) 하위 에이전트가 펼쳐집니다. 기다리는 하위 에이전트에는 **답변**, 실패한 하위 에이전트에는 **열기**가 있고, 둘 다 그 하위 에이전트의 작업을 엽니다. **카드**는 워크스페이스마다 카드 하나, **표**는 작업마다 한 줄로 보여 줍니다. 표의 열 머리글을 고르면 그 열로 정렬하고, 다시 고르면 반대로, 한 번 더 고르면 작업 대기열 순서로 돌아갑니다. 전에 카드를 쓰고 있었다면 업데이트 후 한 번 트리로 바뀌고, 그 뒤로 고른 보기는 유지됩니다.
한 작업에서 여러 질문이나 승인 요청이 들어오면 **조치 필요**에 각각 한 줄씩 표시되고 개수에도 따로 반영됩니다.

## 알림과 이슈

Stave를 다시 열면 더 이상 답할 수 없는 요청은 기록에 남고, 아직 답할 수 있는 요청은 계속 표시됩니다. 기존 알림을 복원할 때는 소리나 배너가 나오지 않습니다.

- 상단 바의 **알림**에 질문, 승인, 완료 소식이 모입니다. 알림과 Dock 배지에는 응답이나 조치가 필요한 작업 수가 표시됩니다. 에이전트 실행은 단계 확인 요청, 막힘, 정체, 완료 때 한 번씩 알립니다. 승인은 **한 번 허용**이나 **거부**(A, D 키)를 선택합니다. 행에는 요청 요약과 명령이 먼저 표시되며, 위험 표시가 있거나 내용이 길어 한 줄에 들어가지 않는 요청은 **거부**와 **작업 열기**만 제공합니다. 선택지가 네 개 이하인 짧은 단일 선택 질문은 선택지를 누르면 바로 답할 수 있습니다. 긴 질문, 여러 단계로 구성된 질문, 복수 선택이나 직접 입력이 필요한 질문, 계속 적용할 승인은 **작업 열기**에서 처리합니다. 응답을 보내면 잠시 확인 문구가 뜬 뒤 기록으로 이동합니다. 응답할 수 없는 요청은 응답을 보내지 않고 기록으로 이동합니다. 전송에 실패하면 **작업 열기**로 요청을 확인할 수 있습니다. 데스크톱 알림의 **알림에서 응답** 설정으로 이 기능을 켜거나 끕니다. 새 알림은 상단 중앙에 토스트로도 표시됩니다. 브랜치 상태 알림은 오른쪽 아래에서 입력창과 상태 표시줄을 가리지 않도록 그 위에 뜹니다.
- 상단 바의 **이슈**에는 나에게 할당된 Crane과 Jira 이슈가 보이고, 목록, 보드 또는 상세 화면에서 **에이전트에 배정**을 누르면 킥오프가 열립니다. 시작하기 전에 작업 지시를 편집할 수 있습니다. 이슈 본문, 재현 절차, 연결된 PR은 작업에 참고 자료로 첨부됩니다. 목록이 더 최신이면 상세 정보를 다시 조회합니다. 최신 상세 정보를 가져올 수 없으면 이슈 요약과 목록에서 확인할 수 있는 PR 링크를 첨부합니다. 연결은 **설정 > 통합 > 이슈**에서 합니다. **필터**는 소스, 상태, 우선순위, 프로젝트, 레이블 값을 한 목록에서 검색해 고르고, 옆의 **업데이트**는 오늘, 최근 7·30·90일, 이번 달 중에 업데이트된 티켓만 남기며, 적용된 필터는 칩으로 보여 하나씩 지우거나 **모두 지우기**로 지우고, 옆에 일치하는 이슈 수가 표시됩니다. 버그 수정 PR이 이미 연결되어 있다면 신고자가 사용한 조작을 PR의 기준 버전과 수정 버전에서 재현해 달라고 요청하세요. 두 리비전과 각각의 결과를 확인할 수 있습니다.

## Stave 밖 활동

사이드바의 **활동**은 터미널에서 실행한 `claude`처럼 Stave 밖에서 시작한 Claude Code와 Codex 세션, 그리고 Claude Code 세션이 실행하는 하위 에이전트를 보여 줍니다. 기본값은 꺼짐입니다. **설정 > 일반 > Stave 밖 활동**을 켜거나 페이지에서 **켜기**를 누르세요. 켜면 Stave가 이 컴퓨터에 있는 두 도구의 기록 파일을 메모리에서만 읽고, 저장하거나 어디에도 보내지 않습니다. 꺼져 있으면 아무것도 읽지 않습니다.

- 세션이나 하위 에이전트 카드에서 **진행 보기**를 누르면 최근 메시지와 도구 호출을 최대 32개까지 볼 수 있습니다. 새 기록은 화면에 바로 반영되며, 패널을 닫거나 Esc를 누르면 카드 목록으로 돌아갑니다.
- 최근 30분 안에 기록된 세션을, 그 폴더를 포함하는 Stave 프로젝트별로 묶어 보여 줍니다. 세션마다 상태(**작업 중**, **입력 대기**, **유휴**), 브랜치, 지금 하는 일, 경과 시간, 단계 수, 컨텍스트 크기, "에이전트 M개 중 N개 실행 중"이 보이고, 하위 에이전트마다 카드가 하나씩 있습니다.
- 사이드바 배지는 작업 중인 세션과 실행 중인 하위 에이전트 수를 더한 값입니다. Stave가 시작한 세션은 해당 작업에 있으며 여기에는 나오지 않습니다.
- 읽기 전용이라 여기서 세션을 조종하거나 멈출 수 없습니다. Claude Code와 Codex의 하위 에이전트는 부모 세션이 목록에 있으면 그 아래에 표시됩니다.

| Lens              | 오른쪽 패널 Lens, Cmd/Ctrl+K 다음 L                        | 내장 브라우저 탭. **요소 선택**과 **시각적 댓글**로 작업 초안에 화면 맥락을 붙입니다  |
| 정보 패널         | 오른쪽 패널 **정보**, Cmd/Ctrl+K 다음 I                    | 할 일, 메모, 링크, 문서, 메모리. 링크 행에서 **작업 만들기**                          |
| 스크래치          | 오른쪽 패널 **스크래치**                                   | 결과물에서 HTML, 이미지, Markdown과 `artifacts/`에 저장한 파일을 확인합니다. 종류를 선택해 좁히거나 **전체 파일**에서 에이전트가 `.stave/scratch/`에 저장한 스크린샷, 로그, 명령 출력, JSON을 최신순으로 보고 바로 미리 봅니다. Lens 스크린샷은 `.stave/scratch/lens/`에 저장되고, 하위 에이전트의 파일은 **하위 에이전트 <id>** 아래에 묶입니다. Claude 하위 에이전트가 시작되면 유형과 짧은 해시를 조합한 이름으로 전용 스크래치 폴더를 안내합니다. 버튼의 점은 아직 보지 않은 파일이 생겼다는 뜻입니다. **크게 보기**로 본문을 넓히거나 이미지를 확대합니다. 긴 Markdown은 처음부터 나눠 읽고, 큰 HTML은 원할 때 엽니다(최대 10 MiB). 256 KB가 넘는 로그는 끝부분만 보이며 **편집기에서 열기**로 전체를 봅니다. 행을 마우스 오른쪽 버튼으로 누르거나 클립 아이콘을 눌러 **메시지에 첨부**합니다. 프로젝트의 원본 체크아웃에서는 30일이 지난 파일이 자동으로 삭제됩니다 |
| 인라인 HTML 페이지 | 에이전트가 대화 안에 표시                                 | 차트, 표, 목업을 대화에서 보고 **소스 보기**, **HTML 파일로 저장**                     |
| 데이터 뷰         | 에이전트가 대화 안에 표시                                 | 표, 차트, 지표 타일, 타임라인, 히트맵을 테마에 맞춰 표시. 표는 정렬, **행 필터**, 페이지 이동, **CSV 내보내기** |
| 독립 CLI          | 상단 바 **독립 CLI 열기**                                  | 워크스페이스와 상관없이 CLI를 엽니다. 폴더는 설정 > 일반에서 정합니다                 |
| MCP               | 설정 > MCP                                                 | **서버 추가** 후 **변경 사항 검토**와 **변경 사항 적용**. **로컬 MCP 서버** 카드      |

에이전트는 답변에 표, 그룹별·시간별 수치, 핵심 지표, 일정이 있으면 요청하지 않아도 데이터 뷰를 표시하고, 흐름·구조·레이아웃을 설명하거나 맞춤형·인터랙티브 페이지가 필요하면 인라인 HTML 페이지를 표시합니다. 데이터 뷰는 데이터를 그 안에 담고(최대 256KB, 표는 최대 500행에 페이지당 10행) 아무것도 실행하지 않습니다. 답변 안의 `stave-view` 코드 블록도 같은 뷰로 그립니다. 페이지 글자는 주변 답변과 같은 14픽셀로 시작합니다. 직접 추가한 MCP 서버의 도구는 도구 행에 자체 뷰를 표시할 수 있습니다. 뷰 머리글의 **텍스트 결과 보기**를 누르면 도구의 텍스트 결과를 **복사** 버튼과 함께 볼 수 있고, 실패한 호출처럼 뷰가 그릴 데이터가 없으면 이 텍스트가 처음부터 열립니다. 인라인 HTML 페이지와 에이전트의 표시 전 검사는 최대 5,120,000자까지 지원합니다. 워크스페이스의 `.html`·`.htm` 파일은 개발 서버 없이 최대 10MiB(10,485,760바이트)까지 미리 볼 수 있습니다. 다른 텍스트 파일은 1MiB까지 편집할 수 있습니다.

데스크톱 앱의 탐색기나 대화 링크에서 PDF를 열면 읽기 전용 뷰어에 전체 페이지 수가 표시됩니다. 화면 근처 페이지부터 표시하며, **너비 맞춤**과 **실제 크기**를 선택할 수 있습니다. 최대 64MiB까지 열 수 있습니다.

편집 한도를 넘는 UTF-8 텍스트 파일은 읽기 전용으로 열립니다. **이전 구간**과 **다음 구간**으로 내용을 살피고, **파일에서 찾기**로 입력한 문자열을 그대로 검색합니다. **최신 내용 따라가기**를 켜면 새 출력이 추가될 때 끝으로 이동합니다. 줄 번호가 있는 대화 링크는 해당 줄로 이동합니다. 터미널 색상 코드는 제거합니다. 읽는 중 파일이 바뀌면 **다시 읽기**를 눌러 최신 버전을 엽니다.

Lens 미리보기에서 **맞춤** 메뉴를 열고 **390픽셀**, **820픽셀**, **1280픽셀** 중 하나를 골라 반응형 레이아웃을 확인합니다. 패널보다 넓은 미리보기는 전체 너비가 보이도록 축소됩니다. 패널 너비를 다시 따르려면 **맞춤**을 선택합니다.


Stave 저장소에서는 `config/workspace-check-candidates.json`의 결정 흐름 검사와 Lens 캡처 검사를 워크스페이스 도구에 등록해 워크스페이스 검사로 사용할 수 있습니다. 데스크톱 앱이 로컬 테스트 데이터로 정상 동작과 실패 시 복구·거부 동작을 확인합니다.

데스크톱 앱의 **워크스페이스 도구 > 프로세스 > 수신 대기 포트**에는 에이전트나 터미널에서 직접 실행한 서버도 표시됩니다. 수신 주소와 프로세스 이름을 확인한 뒤 **Lens에서 열기**를 선택합니다. **Stave 관리**는 등록된 터미널이나 스크립트에서 실행한 프로세스이고, **소속 추정**은 작업 디렉터리나 부모 프로세스로 소속을 판단한 경우입니다.

Lens는 데스크톱 앱에서만 열립니다. CLI 탭을 닫으면 그 프로세스도 끝납니다.

에이전트는 Lens 탭이 숨겨져 있어도 스크린샷을 찍을 수 있습니다. Lens에서 캡처할 화면을 준비할 수 없다는 메시지가 나오면 탭을 표시한 뒤 다시 캡처하세요.

## 이 판에서 확인한 것과 하지 않은 것

- 라벨과 동작은 기능을 바꾼 변경마다 그 소스와 한국어·영어 문구 파일에서 확인했습니다. 0.35.0 전체를 한 번에 다시 대조하지는 않았습니다.

- Lens 스크린샷은 브라우저 빌드에서 찍어 도구 막대만 보입니다.

## 본문 찾기와 화면 이동

대화나 입력창에 포커스를 두고 Cmd+F / Ctrl+F를 누르거나, 대화 위에 마우스를 올리면 오른쪽 위에 나타나는 검색 버튼을 누르세요. 찾기 막대는 대화 위에 떠서 표시되며 메시지를 밀어내지 않습니다. 두 글자 이상 입력하면 불러온 메시지와 로컬 색인을 함께 검색합니다. 저장 전 스트리밍 텍스트, 이전 형식으로 저장된 메시지, 아직 불러오지 않은 과거 대화와 읽을 수 있는 도구 요약을 포함하며 같은 메시지는 한 번만 표시합니다. 사고 과정과 도구 원시 데이터는 제외합니다. 검색 결과를 선택하면 해당 메시지가 있는 구간을 자동으로 불러옵니다. 이후 메시지를 더 불러오거나 **최신 메시지로 이동**을 눌러 현재 위치로 돌아갈 수 있습니다. Enter와 Shift+Enter로 다음·이전 메시지로 이동합니다. 과거 메시지의 색인 생성이 끝나도 선택한 위치는 유지합니다. 메시지를 보내거나 **최신 메시지로 이동**을 누르면 실시간 대화로 돌아옵니다.

검색에서 연 보관된 작업은 읽기 전용입니다. **보관된 작업 · 복원** 안내에서 복원한 뒤 메시지를 보낼 수 있습니다.

명령 팔레트에 두 글자 이상 입력하면 제목 결과 아래에 **메시지 내용** 결과가
표시됩니다. 등록한 저장소의 사용자 메시지, 답변, 읽을 수 있는 도구 요약을
검색하며 한국어와 단어 일부도 찾습니다. 결과에는 강조된 문맥, 일치 개수,
최근 활동과 보관·위임 상태가 표시됩니다. Enter를 누르면 과거 기록도 해당
메시지로 바로 이동합니다. Fleet에서는 **메시지 내용 포함**을 켜서 같은
내용을 검색할 수 있습니다. 기존 기록을 준비하는 동안 색인 진행 상황이
표시됩니다. 검색은 로컬에서만 실행되며 내용을 프로바이더로 보내지 않습니다.

터미널에서 Cmd+F / Ctrl+F를 누르면 보관된 출력에서 검색합니다. Enter와 Shift+Enter로 결과를 이동하고 Escape로 닫습니다. 머리글에는 실행 중 상태나 완료한 명령의 종료 코드가 표시됩니다.

출력이 많아 터미널이나 CLI 화면이 응답하지 않아도 명령은 계속 실행될 수 있습니다. 화면에는 실시간 출력 일부가 누락되었을 수 있다는 안내가 표시됩니다.

Fleet, Agents, Schedules, Issues, AI usage를 닫으면 이전 화면으로 돌아갑니다. F6와 Shift+F6으로 창의 영역 사이를 이동할 수 있습니다. 사이드바 보기 전환에는 글자 라벨이 표시됩니다. 저장소가 없는 Fleet에서는 저장소 열기 버튼을 제공합니다.

편집 중인 파일이 디스크에서 변경되면 편집기 배너에서 비교, 내 버전 유지, 디스크에서 다시 불러오기를 선택하세요. 저장을 다시 눌러도 디스크를 자동으로 덮어쓰지 않습니다. 채팅과 Review diff는 설정한 보기 방식을 따르고 바뀌지 않은 줄은 접습니다. 설정의 짧은 컨트롤은 행 끝에 정렬되고 오래된 변경 기록은 접혀 있습니다. Markdown 미리보기는 문단을 자연스럽게 줄바꿈하며 코드 강조와 복사를 제공합니다.


## Tars에 저장된 비교안

Tars 보고서나 결과물에서 저장된 HTML을 열면 Stave 안에서 볼 수 있습니다.
로컬 이미지·CSS·독립 실행 JavaScript가 HTML과 함께 보관되어 Stave를 다시
시작하거나 실행 워크스페이스를 제거해도 열 수 있습니다. 원본과 수정본은
별도 보관본으로 구분합니다. localhost 링크만 남은 예전 보고서는 원본 파일이
필요하며, 종료된 서버를 복구할 수는 없습니다. 보관본은 로컬 앱 데이터를
삭제할 때까지 유지됩니다.

실행 워크스페이스 안의 스크린샷·로그·텍스트·JSON·PDF 파일(20 MB 이하)도 같은
방식으로 복사되어 이름 옆에 **보관된 사본**이 표시되며, 누르면 시스템 기본 앱으로
사본을 엽니다. 이보다 크거나 워크스페이스 밖에 있는 파일은 원본 링크로 남습니다.

프리뷰에는 에이전트가 보고한 실제 컴포넌트 렌더링·예시 데이터·캡처·출처 미보고
여부가 표시됩니다. 이 표시가 독립적인 검증을 뜻하지는 않습니다. 저장된 비교안은
서버 없이 열리며 백엔드에 접근하지 않습니다. 기존 Workspace Tools 프로세스가
연결되어 있다면 **실제 앱 실행**을 누른 뒤 **실제 앱 열기**로 URL에 접속합니다.
로그인·백엔드·워크스페이스가 필요하고, 프로세스 시작이 앱 준비 완료를 보장하지는
않습니다. 실행에 실패해도 저장된 비교안은 계속 볼 수 있습니다. 저장된 결과물을
여는 것만으로 프로세스가 실행되지는 않습니다.

같은 원본과 내용은 저장본을 재사용하고, 내용이 바뀌면 별도 버전으로 보관합니다.
이름이 같은 결과물은 버전과 저장 시각으로 구분합니다. 출처와 시각은 Stave가
기록합니다. 하위 에이전트는 실행 워크스페이스 안의 로컬 HTML 경로를 담당 작업에
전달할 수 있지만 다른 작업의 인라인 결과물을 승격할 수는 없습니다. 실제 앱 실행
설정은 저장된 HTML이나 로컬 HTML에만 지정할 수 있습니다. HTTP 링크에서는 이를
제외해야 합니다. 루트 기준 자산 경로는 상대 경로로 내보내야 합니다. 외부로 복사한
Markdown에는 앱 전용 주소 대신 Stave에 로컬로 보관되었다는 안내가 표시됩니다.

## 워크스페이스 정리와 복원

정리하기 전에 확인만 하려면 에이전트에게 아무 작업도 실행하지 말고
워크트리 정리를 미리 보여 달라고 요청하세요.
`stave_list_workspace_cleanup`에 `preview: true`를 지정하면 디스크 사용량,
브랜치와 PR의 병합 상태, 커밋하지 않은 변경 사항, 실행 중인 작업 등
정리를 막는 이유를 확인할 수 있습니다. 병합된 PR의 마지막 커밋이 현재 로컬
브랜치의 마지막 커밋과 같을 때만 PR을 병합됨으로 표시합니다. 확인할 수 없는
상태는 미확인으로 표시하고, 일부만 측정한 크기는 최소 사용량을 뜻합니다. 미리보기는
워크트리, 파일, 브랜치를 변경하지 않습니다.

명령 팔레트, 저장소 메뉴 또는 Fleet 헤더에서 **워크스페이스 정리**를
엽니다. 등록된 모든 저장소의 정리 후보와 브랜치, 정리를 막는 이유,
선택적으로 확인한 디스크 크기를 검토하고 보관·복원·삭제할 항목을
선택합니다. 수동으로 보관하면 관리 대상 워크트리를 제거하고 로컬 커밋을
포함한 브랜치와 대화 기록은 유지합니다. 정리 화면의 실행 취소 또는 저장소
보기의 **보관됨**에서 복원할 수
있습니다. 저장된 변경 사항과 브랜치가 모두 없으면 기록을 읽기 전용으로 열고 새 워크스페이스의
초안으로 이어갈 수 있습니다.

사이드바의 워크스페이스 메뉴에서도 **보관**할 수 있습니다. 확인을 누르면
커밋하지 않은 변경 사항을 저장한 뒤 워크트리를 제거합니다. 워크스페이스
정리 화면에서는 확인 창의 **커밋하지 않은 변경 사항을 저장하고 보관**을
선택하세요. 브랜치를 이동하지 않고 스테이징한 변경, 스테이징하지 않은
변경과 추적하지 않는 파일을 저장합니다. 수동·자동 보관 시 Git이 무시하는
민감 파일(예: `.env`, 인증 정보, 키)을 파일당 1 MiB, 최대 50개까지 저장합니다.
저장 대상에서 제외한 파일이 있으면 알리고, 복사에 실패하면 워크트리를
유지합니다. 의존성, 빌드 결과물, 캐시 등 나머지 무시 파일은 삭제합니다.
복원할 위치에 민감 파일이 이미 있으면 기존 파일을 유지하고 충돌을 알립니다.
충돌한 사본은 직접 회수하거나 워크스페이스를 영구 삭제할 때까지 Stave 앱
데이터에 남습니다. Git 작업이 진행 중이면 워크트리 제거를 중단합니다.
Git이 일부 파일을 삭제하지 못하면 워크스페이스는 보관된 상태로 남습니다.
복원하기 전에 사이드바의 보관 확인 창이나 워크스페이스 정리 화면에서
**휴지통으로 이동**을 선택하세요. 보관 목록에는
**저장된 변경 사항**이 표시됩니다. 복원하면
파일과 스테이징 상태가 돌아오며 경로에 파일이 이미 있으면 덮어쓰지 않고
충돌을 알린 뒤 중단합니다. 저장에 실패하면 작업 트리를 제거하지 않습니다.
영구 삭제하면 저장한 참조도 제거합니다. 저장된 변경 사항이 있으면 삭제된
브랜치도 다시 만들 수 있으며, 복원한 파일을 보호하기 위해 초기화 명령은
실행하지 않습니다. 자동 정리는 이 옵션을 켜지 않습니다.

워크트리 제거를 중단한 경우 폴더를 열어 조치하고 다시 시도할 수 있습니다.
**파일을 디스크에 남기고 보관**이 표시되면 그대로 보관할 수도 있습니다.
복원하면 같은 파일을 다시 엽니다. 남겨 둔 워크트리를 제거하려면 먼저
워크스페이스를 복원하세요.

**영구 삭제**는 별도 동작이며 기록과 깨끗한 작업 트리의 삭제를
확인합니다. 확인 창은 취소 버튼에 포커스를 두고 열립니다. Escape는
확인 창만 닫고 Enter로는 영구 삭제하지 않습니다. 연결한 워크스페이스를
보관하면 외부 작업 트리와 브랜치는 유지합니다. 복원 시 의존성 링크와
설정한 초기화 명령을 다시 적용하며 진행 상황과 실패를 표시합니다.
생성 옵션이 저장되지 않은 기존 워크스페이스는 확인된 의존성 링크와
현재 저장소의 초기화 명령을 사용합니다.
브랜치 삭제는 선택 사항입니다. 병합되지 않은 브랜치를
강제로 삭제하려면 기본으로 꺼진 확인란을 직접 선택해야 합니다.

**설정 > 워크스페이스**에서 PR 병합 후, 미사용 기간 후, 보관된 작업
트리 제거, 저장소별 작업 트리 개수 제한을 각각 설정합니다. 모두
기본으로 꺼져 있습니다. 호스트가 최대 한 시간에 한 번 평가하며
**지금 정리 실행**으로 즉시 평가할 수 있습니다. 현재·기본 워크스페이스,
커밋하지 않은 파일, 푸시하지 않은 커밋과 실행 중인 작업은 보호합니다.
최근 정리에서 결과와 복원 동작을 확인합니다. Cmd/Ctrl+W로 탭을 닫아도
작업이나 워크스페이스를 보관하지 않습니다.

보관된 워크스페이스의 대화도 메시지 검색에서 찾을 수 있습니다. 보관된 결과는 읽기 전용으로 열리며, 복원하면 워크스페이스를 복원한 뒤 편집할 수 있습니다. 작업 일괄 보관은 보관된 워크스페이스를 건너뜁니다. 정리 기능은 미완료 턴, 실행 중인 하위 작업이나 활성 실행이 있으면 거부합니다.

**하위 에이전트가 남긴 워크트리**에는 Claude Code 하위 에이전트가
`<project>/.claude/worktrees/agent-<id>`에 남긴 워크트리가 나옵니다. 화면에는
"Claude Code 하위 에이전트가 남긴 워크트리입니다. 브랜치는 유지합니다."라고
표시됩니다. Stave 워크스페이스와 심볼릭 링크를 거쳐야 닿는 폴더는 표시하지
않습니다. 커밋하지 않았거나 추적하지 않는 변경 사항, 어느 브랜치에도 없는
커밋이 있는 분리된 HEAD, 잠긴 워크트리, 최근 30분 안의 변경, Stave 밖 활동이
켜져 있을 때 아직 끝나지 않은 하위 에이전트, 실패한 Git 검사 중 하나라도 있으면
제거할 수 없습니다. 항목을 선택하고 **워크트리 제거**를 누른 뒤 확인합니다.
Enter로는 확인되지 않습니다. Stave는 각 워크트리를 다시 확인한 뒤 강제하지 않고
제거하며 브랜치는 유지하고, 항목마다 결과를 보여 줍니다. 의존성, 빌드 결과물처럼
Git이 무시하는 파일은 함께 삭제됩니다. 자동 정리는 이 워크트리를 제거하지 않습니다.

**AI 사용량 > 프로젝트**는 선택한 기간의 토큰과 비용을 프로젝트와 워크스페이스별로
나눠 보여 줍니다. 앞선 같은 길이의 기간과 비교하고, 날짜별 막대를 프로젝트별로 쌓으며,
**정렬 기준**으로 토큰, 비용, 최근 활동 순으로 정렬합니다. 토큰은 모든 프로바이더를 세고,
비용은 보고한 프로바이더(Claude)만 표시하며 추정하지 않습니다. 같은 화면의
**워크스페이스 디스크 사용량**은 워크스페이스 폴더와 하위 에이전트가 남긴 워크트리를
하나씩, 폴더마다 최대 30초 동안 측정하고 5분마다 다시 읽으며 **다시 측정**으로 바로
측정합니다. 하위 에이전트 워크트리가 있는 프로젝트는 이름 아래에 개수를 표시합니다.
**공간 확보**는 정리 검사에서 막는 이유가 없는 워크스페이스와 하위 에이전트
워크트리(**하위 에이전트가 남김** 표시)를 큰 순서로 보여 줍니다. 직접 삭제하지 않으며
**정리에서 검토**는 이 워크스페이스 정리 창을 엽니다.


### 전체 에이전트 동시 실행 제한

설정 → 프로바이더의 **동시에 실행할 에이전트 턴 수 제한**은 기본으로 꺼져 있습니다.
켜면 1~16개 중 선택할 수 있습니다. 대기 중인 작업과 Fleet에는 앞서 대기하는 수가 표시됩니다.
직접 보낸 메시지는 자동 실행보다 먼저 시작하며, 같은 종류의 요청은 도착 순서를 따릅니다.
중지하면 대기열에서 빠집니다. 앱을 다시 시작하면 직접 보낸 메시지는 입력창 대기열에
**전송 대기 중 (복원됨)**으로 돌아오며, 보낼지 삭제할지 직접 정합니다. 자동 실행은 작업이 남아 있을 때만
다시 시작합니다. 다시 시작할 수 없거나 하루 넘게 기다린 요청은 알림과 함께 삭제됩니다.
하위 작업을 기다리는 부모는 자리를 비우고, 이어서 실행하기 전에 다시 자리를 얻습니다.
기존 기능별 제한도 그대로 적용됩니다.

## 도구를 찾고 읽지 않은 작업으로 돌아가기

명령 팔레트에서 모델 비교, Schedules, 워크스페이스 정리, Fleet View,
Agents, Performance, Resource Manager, 시크릿 요청을 짧은 설명과 함께
찾을 수 있습니다. Resource Manager는 개발자 모드를 켜지 않아도
설정 > 일반에서 열 수 있습니다.

턴 실행 중 보낸 메시지가 대기하면 실행 중 조종 기능을 켤 수 있는
한 줄 안내가 표시됩니다. 직접 켜기 전까지 기본값은 꺼짐입니다.
안내의 × 버튼으로 닫으면 다시 나타나지 않으며, 설정 > 일반 >
기능 팁에서 모든 안내를 끌 수 있습니다.

작업 탭, 사이드바 작업, Fleet 행의 점은 아직 보지 않은 완료·실패·주의
상태를 뜻합니다. 작업을 열어 읽거나 읽음으로 표시하세요. 나중에 다시
볼 작업은 읽지 않음으로 표시할 수 있습니다. Fleet에서는 선택 막대의
더 보기 메뉴로 선택한 여러 작업에 적용할 수 있습니다. 알림 개수도 같은
읽음 기록을 따릅니다. 읽음 처리는 요청 승인이나 결과 수락이 아닙니다. 작업과 출력은 최신 결과의 저장된 읽음 기록을 함께 사용하며,
재시작해도 유지됩니다.

작업 기록이나 사이드바에서 작업을 고정할 수 있습니다. 작업 기록은 고정한
작업을 먼저 보여 주고, 그 밖에는 최근 활동순입니다. 드래그하거나
Alt + ↑ / ↓로 옮긴 작업은 그 자리를 유지하고, 새 작업은 여전히 맨 위에
나타납니다. 순서 초기화를 누르면 최근 활동순으로 돌아갑니다. 사이드바는
실행 중이거나 응답을 기다리는 작업을 먼저 보여 주고, 워크스페이스마다
열린 작업을 최대 3개까지 표시하며 나머지는 "작업 N개 더 보기"로 접습니다.
작업 고정과 탭 고정은 별개입니다.

독립 리뷰가 막히면 Tars가 같은 리뷰 단계에 복구 지시를 전달하고 모델·권한·남은 예산을 유지합니다. 계정 사용량 한도로 멈춘 실행은 재개 시각을 저장하며, 초기화 시각을 모르면 5분마다 사용량을 확인해 여유가 확인됐을 때만 재개합니다. 직접 일시정지하거나 맡은 작업, 승인 요청과 일일 한도는 계속 사용자가 처리합니다.
